## 목적

`usb_cam_publisher` 가 발행하는 카메라 토픽을 구독해 YOLOv8 추론 결과(`ai_msgs/DetectionArray`)
만 발행한다. 카메라 장치를 열지 않고, 화면 표시도 하지 않는다(표시는 GUI 소관).

## 구조 관찰 — 2026-08-06 조치 결과

**① 설계 근거로 적힌 전제가 반증됐다 → 해소.** *"GPU 는 한 번에 한 프레임만 처리하므로
6대를 동시에 돌릴 수 없다"* 는 추정이 실측(배치 6 이 프레임당 CPU 18.83 → 5.68 ms,
처리량 48.95 → 90.03 fps)으로 뒤집혔다. 두 파일 docstring 을 **반증 사실과 근거 수치로
교체**했고, 그 위에 세워졌던 라운드로빈을 배치로 대체했다.

**② 수신 프레임의 약 83% 폐기 → 해소.** `_on_tick` 이 `_latest` 를 통째로 비워 한 배치로
넘긴다. 회귀 방어: `test_batching.py::test_tick_batches_every_pending_frame`
(돌연변이 확인 — `[:1]` 로 되돌리면 2건 실패).

**③ 카메라당 검출률이 나눗셈에 숨음 → 해소.** 파라미터가 `detect_hz`(카메라당)로 바뀌어
대수로 나누지 않는다. 구 `total_hz` 는 환산 + 경고로 받는다. 회귀 방어:
`test_legacy_total_hz_is_converted_and_warned`(돌연변이 확인 — 환산 제거 시 2건 실패).

**④ 순서를 정하는 상태가 둘 → 해소.** `_cursor` 와 `next_camera_index` 를 제거했다.
회귀 방어: `test_tick_never_starves_a_camera_that_keeps_arriving`.

**⑤ 타입 힌트가 실제와 다름 → 해소.** `_on_image(self, topic: str, msg)` 로 고치고
docstring 에 두 타입을 명시했다.

**⑥ `MS_PER_S` 옆의 리터럴 `1e6` → 해소.** `NS_PER_MS` 상수를 신설해 치환했다.

**신규 관찰 ⑦ — 배치 결과 개수 불일치 방어가 필요했다.** `zip` 은 짧은 쪽에서 조용히
끊기므로, 입력 장수와 결과 건수가 어긋나면 **다른 카메라의 검출을 남의 토픽에 발행**하게
된다. 개수 검증 후 불일치 시 이번 틱을 통째로 폐기한다(detector_node.py:245-249).
회귀 방어: `test_result_count_mismatch_publishes_nothing`(돌연변이 확인 — 가드 제거 시 1건 실패).

**남는 위험 ⑧ — 실기 종단 검증 미완.** 위 수치는 합성 프레임 벤치이며, 6대 카메라를 물린
실기 노드에서 `verify_live` 로 검출률·지연 분포를 아직 재지 않았다. ADR 의 Status 가
「벤치 실측 완료 / 실기 노드 구동 검증 미완」인 이유다.
