### 0-3. ⚠ 검증 도구가 보증하지 않는 것

`verify_doc_claims.py` 는 **인쇄된 숫자가 원자료에서 재계산되는지**와 **인용한 쪽에 그 문구가 실재하는지**만 본다.
2026-08-06 감사에서 **숫자를 그대로 둔 채 서술만 23곳 뒤집은 사본**(little-endian→big-endian, 「SDO 폴링」→「PDO 주기전송」,
「주변 확보 필수」→「불필요」, 폴트 이름 맞바꿈, 회전 부호 반전 등)이 **통과 174 · 불일치 0** 으로 그대로 통과했다.

⇒ **결론·해석·방향·안전 문구는 검사 대상이 아니다.** 도구 통과를 문서 신뢰의 근거로 인용하지 말 것.

### 0-4. ⚠ 계측 한계 — 캡처가 구조적으로 담지 못하는 것

주 캡처 도구가 `Tools/docking_field_kit/orin_homing_capture.py:179` 에서

```python
if bus != MOTOR_BUS or not dat:
    continue
```

로 **데이터 길이 0인 프레임을 전부 버린다.** 따라서:

| 대상 | DLC | 이 캡처에서 |
| --- | --- | --- |
| **SYNC** (`0x080`) | 0 | ❌ **계측 불가** — 버스에 있었어도 기록되지 않는다 |
| **Node Guarding RTR 요청** (`0x700+N`) | 0 | ❌ **계측 불가** |
| NMT (`0x000`) | 2 | ✓ 관측 대상 — 0건은 유의미 |
| EMCY (`0x081`~) | 8 | ✓ 관측 대상 — 0건은 유의미 |
| PDO 대역 | 1~8 | ✓ 관측 대상 — 0건은 유의미 |

타임스탬프도 버스 시각이 아니라 **호스트 USB 배치 처리 시각**이다(같은 파일 `:181` `t = time.time() - t0`).
프레임 간격의 약 49 %가 250 kbps 물리 하한(DLC 8 = 444 µs) 미만이고 다수 프레임이 동일 타임스탬프를 공유한다.
⇒ **µs 자리 정밀도를 주장할 수 없다**(§4-2).

**[설정]** 버스 비트레이트 **250 kbps** 는 같은 파일 `:61 CAN_KBPS = 250` 이 설정한 값이다.
253,510 프레임이 SDO 규격대로 디코드되고 정상 구간 실부하가 70.5 %(§4-2)로 100 % 를 넘지 않는 점은 이 설정과 정합한다.

- ⚠ **원인 미확정** — 드라이브 전원 / 버스 물리 단선 / 캡처 장비 수신 정지를 구별할 자료가 없다.

- ⚠ **파급**: §4-2 버스 부하와 §10-2 쓰기율의 「전 구간 평균」은 이 사장 구간을 포함한다. **국면별 값을 볼 것.**

## 3. NMT · 노드 보호

### 3-1. NMT 명령 [규격] `Handbook_V7.0` §6.3 **page 141** · [7.9] §6.3 **page 125**

프레임: `0x000` DLC 2 = `[명령어][슬레이브 Node-ID]` (ID 0 = 전체)

| Byte0 | 동작 | 비고 |
| --- | --- | --- |
| `0x01` | Start | 노드 활성화, PDO 유효 |
| `0x02` | Stop | 노드 비활성 |
| `0x80` | Pre-Operational 진입 | — |
| `0x81` | **Reset Node** | ⚠ **전 파라미터 초기화 · servo OFF · 알람 리셋. Modbus 로 설정한 PDO 파라미터 소실** |
| `0x82` | Reset Communication | — |

### 3-2. Heartbeat [규격] `Handbook_V7.0` §6.4.1 **page 142** · [7.9] **page 126**

`0x700+N` DLC 1 = 슬레이브 상태. 주기는 `0x1017`(ms), **0 이면 송신 중지**.
상태값: **0** Boot-Up · **4** Stopped · **5** Operational · **127** Pre-operational.

### 3-3. Node Guarding [규격] `Handbook_V7.0` §6.4.3 **page 142–144** · [7.9] **page 126**

- 마스터 요청: `0x700+N`, **remote frame(RTR)** — **page 143**.
- 슬레이브 응답: `0x700+N` + 상태 1 byte. **bit7 = 토글 비트**(응답마다 1/0 교대, 첫 요청에는 0) — **page 144**.
- **통신 두절 보호**: `0x100C` Guard Time(ms) × `0x100D` Life Time Factor 를 넘겨 요청이 오지 않으면
  드라이버가 **HALT 상태로 자동 정지**한다.
- 두 값 중 **하나라도 0 이면 이 보호는 동작하지 않는다.** 마스터가 요청을 보내지 않으면 슬레이브는 보호를 활성화하지 않는다.

> **⚠ 판본 간 서술 차이 — 두절 시 결과**
> - **V7.0 page 143**: 「the driver will enter the HALT state and halt automatically, **without powering off the motor**」
> - **[7.9] page 126**: 「…**驱动报警（通讯超时）**」 = **「통신 타임아웃」 알람**(폴트 코드 `0x8005`, §8).
>   **「모터 전원 유지」 문구는 삭제됐다.**
>
> ⇒ 최신판 기준 정확한 서술: **HALT 진입 + `0x603F = 0x8005` 알람.** 「모터 전원 유지」는 최신판이 보증하지 않는다.

> ### ⚠⚠ 안전 — 두절은 홀딩토크 상실로 이어질 수 있다
> 폴트 진입 시 드라이버는 **모터 운전을 자동 정지하고 enable 신호를 차단한다**
> ([규격] `Handbook_V7.0` §6.6.4 **page 153**).
> 조향축이 통전 해제되면 **홀딩토크를 잃는다.** 경사·외력이 있으면 차량이 움직일 수 있다.
> 같은 저장소의 캡처 도구도 같은 경고를 담고 있다 — `Tools/docking_field_kit/orin_homing_capture.py:41-42`.
> ⇒ **버스를 끊거나 마스터 폴링을 멈추는 실험은 평지·접지·주변 확보 상태에서만 할 것.**

### 4-1. 프레임 구조 [규격] `Handbook_V7.0` §6.7.1–6.7.2 **page 156** · [7.9] §6.7 **page 138**

```
byte0        byte1        byte2        byte3      byte4 … byte7
명령어    인덱스 하위   인덱스 상위   서브인덱스        데이터 (little-endian)
```

DLC 는 **항상 8**, **모든 요청에는 응답이 온다** — [규격] §6.2 **page 138**.

| 방향 | 명령어 | 의미 |
| --- | --- | --- |
| 요청 `0x600+N` | `0x2F` / `0x2B` / `0x27` / `0x23` | 쓰기 **1 / 2 / 3 / 4** byte |
| 요청 `0x600+N` | `0x40` | 읽기 요청 |
| 응답 `0x580+N` | `0x60` | 쓰기 성공 |
| 응답 `0x580+N` | `0x4F` / `0x4B` / `0x47` / `0x43` | 읽기 응답 **1 / 2 / 3 / 4** byte |
| 응답 `0x580+N` | `0x80` | **Abort** — `[80][index][sub][Error_Code 4B]` — [규격] §6.2 **page 139** |

> **구현 주의**: 읽기 응답의 명령어 바이트가 유효 데이터 길이를 알려준다.
> 크기를 무시하고 항상 4바이트를 해석하면 `0x4B`(2 byte) 응답의 상위 2바이트가 오염된다.
>
> ⚠ **문서 내부 불일치**: §6.2 의 abort 구조표(page 138–139)는 `Byte0/Byte1/Byte2/Bytes4~7` 로만 적어
> **Byte3(서브인덱스)이 빠져 있고 인덱스를 상·하위로 나누지 않는다.** §6.7(page 156)의 8바이트 레이아웃과 어긋난다.
> 본 문서는 **§6.7 형식을 따른다**(실측 프레임과 일치).

쓰기 `0x60A: 2B 40 60 00 06 00 00 00` → 응답 `0x58A: 60 40 60 00 …`

1. **이동량은 고정이 아니다.** 탐색 거리는 **개시 시점 위치에서 음의 리밋까지의 거리**로 정해진다.
   위 캡처는 개시→도달 **35.0 s**(실제 이동 29.1 + 3.6 ≈ 32.7 s, 사이 대기 2.3 s)였지만,
   **이미 원점에 있으면 아무것도 움직이지 않는다**(§9-4). 이 숫자를 상한으로 읽지 말 것.
2. **탐색과 복귀의 속도가 다르다.** 탐색은 `0x6099 = 2500`(250 r/min) 기준 느린 이동이고,
   복귀는 `0x6081 = 30000` 프로파일로 **137° 를 3.6 s** — 약 38 °/s 다. **위험 구간은 마지막 3.6 s** 다.
3. **복귀는 호밍이 아니다.** 호밍은 t=49.080 에 이미 끝났고, 복귀는 **마스터가 `0x607A` 를 재개해 일으킨 별도 이동**이다.
   마스터의 재지령이 없으면 축은 **원점(리밋)에 머문다.**
4. **호밍 중에는 Node Guarding 설정이 아직 기록되지 않았다**(§3-4) — 그 구간의 두절 보호 임계는 알 수 없다.
5. ⚠ **이식 규칙 — 동결 구간은 bit15 보다 늦게 풀린다.**

   | | node3 | node4 |
   | --- | --- | --- |
   | `0x6064` == 0 구간 | 17.930 – **49.178** | 17.931 – **49.178** |
   | `0x6041` bit15 == 0 구간 | 17.956 – **49.080** | 17.957 – **48.999** |

   동결이 **26 ms 먼저 시작하고 98~179 ms 늦게 끝난다.**
   ⇒ 「bit15 = 0 이면 읽지 말라」로 구현하면 **bit15 가 1 로 올라온 뒤의 0 을 실위치로 읽는다.**
   올바른 규칙: **「bit15 = 1 이 된 뒤 `0x6064` 가 0 이 아닌 값을 낼 때까지 기다린다.」**

> ### ⚠ 초판의 「스케일 교차 확인」은 스케일을 검증하지 않는다 — 인용 금지
> 초판은 「`0x6099=2500` → 4.762 °/s × 29.10 s = 138.6° vs 복귀 실측 137.45°, 0.8 % 이내」를
> **스케일 교차 확인**으로 제시했다. 그러나 `57,344 = 65,536 × 315/360` 이므로 **감속비 315 와 counts/° 가
> 양변에서 소거된다** — 315 를 다른 값으로 바꿔도 비는 1.0081 로 불변이다.
> 이 검산이 확인하는 것은 **「탐색 회전수 ≈ 복귀 회전수」** 라는 왕복 성질뿐이며, **스케일도 감속비도 검증하지 않는다.**
> 게다가 탐색 구간 내내 `0x6064` 는 0 으로 동결돼 **이동 자체가 관측되지 않았고**, 등속 가정(가감속 무시)에 의존한다.
> (실제 비는 138.57/137.45 = **0.815 %** 로 「이내」가 아니라 근소 초과다.)

### 9-4. ⚠ 같은 쓰기가 아무것도 움직이지 않는 경우가 있다 [실측]

### 11-1. 조향 — counts/° [설정] ⚠ **[실측] 이 아니다**

**1차 source** — EasyDRIVE 화면 캡처:

(삭제분은 실기 SDO abort 로도 확인된다 — §4-3).

**신설**: `0x6502 SupportedDriveModes` (RO, PDO 매핑 가능, 기본값 **`0x0000006F`**).
⚠ **두 판 매뉴얼 어디에도 기재돼 있지 않다**(EDS 에만 존재). 비트 배치는 CiA402 규격이 정하는데
**본 저장소에 규격서가 없어** 의미를 1차 source 로 확인하지 못했다. **`0x6F` 라는 값만 사실로 취급할 것.**

재현 — ⚠ **공통 섹션 내부 키까지** 비교해야 한다(섹션 이름 집합만 비교하면 위 18건을 놓친다):

```bash
python3 - <<'PY'
def parse(p):
    d, cur = {}, None
    for l in open(p, encoding='utf-8', errors='replace'):
        l = l.strip()
        if l.startswith('[') and l.endswith(']'): cur = l[1:-1].upper(); d[cur] = {}; continue
        if cur and '=' in l:
            k, v = l.split('=', 1); d[cur][k.strip().upper()] = v.strip()
    return d
o = parse("References/Tongyi-Motor-Controller/canopen/EDS_extracted/Servo_Driver_20200805.eds")
n = parse("References/Tongyi-Motor-Controller/canopen/EDS_extracted_20240423/Servo_Driver_20240423(3).eds")
for s in sorted(set(o) & set(n)):
    for k in sorted(set(o[s]) | set(n[s])):
        if o[s].get(k) != n[s].get(k): print(f"[{s}] {k}: {o[s].get(k)!r} → {n[s].get(k)!r}")
print("신설 섹션:", sorted(set(n) - set(o)))
print("삭제 섹션:", sorted(set(o) - set(n)))
```

## 13. 확정되지 않은 것

| 항목 | 상태 |
| --- | --- |
| **12.65 s 두절의 원인** | 슬레이브 측 사실은 확정(§2-3). 드라이브 전원 / 버스 물리 단선 / 캡처 장비 수신 정지를 구별할 자료 없음 |
| **두절 중 드라이브가 폴트를 냈는가** | 그 구간 `0x603F` 응답 0건. 마스터의 Fault Reset 105회는 정황이지 증거가 아님 |
| **두절 시 실제 거동**(HALT / 알람 / 홀딩토크) | 두 판본 서술이 다르고(§3-3) 실측 구간에서 드라이브가 응답하지 않았다. 유도 실험 필요 — **평지·접지·주변확보 필수** |
| **`0x3F` 가 실행인가 유지인가** | `0x000F` 전이가 없어 bit4 에지 동작을 구별할 수 없다(§6-4). 목표를 바꾸며 (a) 유지 (b) `0x000F`↔`0x003F` 토글 비교 필요 |
| **`0x60FB:04=1` 이 언제 무동작인가** | 「이미 원점」/「리밋 물림」/「거부」를 구별하지 못함(§9-4). 시작 위치 3조건 반복 필요 |
| **실제 감속비 315 여부** | 저장소 자료 전부가 57,344 를 곱해 지령한 것(§11-1). **기계적 각도계 독립 측정** 필요 |
| **폴트 국면 CAN 거동** | §8 폴트표 19행 중 실측 확인된 코드 **0건** |
| **PDO / EMCY / NMT 실사용** | 유의미한 0건(§2-2) — 다만 미캡처 국면(전원 사이클 등)이 남아 있다 |
| **SYNC** | ❌ **계측 불가**(§0-4) — 「0건」이라 말할 수 없다 |
| **Node Guarding RTR 요청** | ❌ **계측 불가** — 캡처 도구가 DLC 0 을 폐기(§0-4). 하드웨어는 RTR 을 다룰 수 있다(`Tools/panda_bench/reliability_24h.py:154`) |
| **`0x6502` 비트 의미** | CiA402 규격서 미보유 |
| **`0x6078` 전류 실측 대조** | 단위는 규격 확정, 정격 대비 검증 미실시 |
| **캡처 경로의 릴레이 개입 여부** | 캡처는 CAN2(모터측) 단일 버스. CAN0 동시 청취로 `0x607A` 일치 확인 필요 |
