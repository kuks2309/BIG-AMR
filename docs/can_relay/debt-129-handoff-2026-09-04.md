## 1. 이번 세션에 확정·완료된 것 (main 머지: 524c26d)

### 근본 원인 (실측 확정)
**릴레이(K1)가 engage 때 안 끊긴 진짜 이유 = `board/boards/black.h:143` 이 릴레이 구동핀 PC10 을
open-drain 으로 설정.** open-drain 은 HIGH 를 못 내는데, 이 자작 보드 릴레이는 **active-high**

→ PC10 이 R33(10K) 풀다운에 눌려 항상 LOW = 릴레이 영영 안 뜸. **하드웨어 결함 아님, 보드 정상.**

### 해결 (재호밍 100%→~13%, ~18/20 PASS)
- **`board/main.c` (git 미추적 — 코드는 `relay-pushpull-open-drain-fix-2026-09-04.md` 에 보존):**
  `SAFETY_SEER_GATE` case → `set_gpio_mode(GPIOC,10,MODE_OUTPUT); set_gpio_output_type(...,PUSH_PULL); set_gpio_output(...,true)` (릴레이 절체).
  `SAFETY_SILENT` case → 같은 push-pull 로 `false` (패스스루).
- **`board/safety/safety_seer_gate.h` (커밋 a33562e·903a9b3):**
  ① pos_act(0x6064) = Seer 명령목표(0x607A) 되돌림 → following error 0.
  ② freeze 시 목표=frozen pos 초기화.
  ③ 조향(node3·4) statusword(0x6041) = **상시 0x9450**(op-enabled+target-reached+homing-attained) — 2슬롯 토글의 0x0050(switch-on-disabled) 순간이 Seer 재init 유발했음.
  ④ (기존) node-guarding 토글 생성, cur/pos 2슬롯 replay.
- 실측: engage 중 모터 bus0 에서 0.5s 후 완전 격리, CAN 오류 40→2, 재호밍 100%(0/4)→~13%(누적 14/16·4/4).

## 2. ⚠ 다음 세션 필독 — 교란 요인 (2026-09-04 세션 67ed5a48 분석으로 다시 씀)

- **[해결 2026-09-04 17:16]** 하네스 방향 판정을 `black.h` 에서 제거하고 NC 로 고정한 펌웨어(DEV-8dcca835, md5 1f9fe50b…)를 4e002c 에 플래시했다. 부팅 harness=0 고정(리셋 2회 재현), 1사이클 clean intercept·재호밍 0. 아래는 그 전 상태의 기록이다.
- 하네스 방향 판정이 부팅마다 랜덤(1/2) 이었고, 17:16 이전 보드는 `car_harness_status=2`(FLIPPED)였다.
  FLIPPED 이면 `black_init()` 의 `can_flip_buses(0,2)` 가 논리 bus0↔bus2 를 바꾸고, `0xe8` 의
  `set_intercept_relay()` 가 릴레이핀 **PC10** 을 `!intercept` 로 구동해 `set_safety_mode` 의 push-pull 과
  정반대로 움직인다. NORMAL 이면 PC11(도면상 미연결)을 구동해 무해하다.
  → **E1 실측(15:26)으로 확인: FLIPPED 부팅에서 intercept 는 브리징 루프 폭주(node4 EMCY 0x8110 ≈1000 f/s)로 깨지고, SILENT 로 돌아가면 릴레이가 절체 상태로 남아 로봇이 Seer 와 분리된다**(main.c SILENT 분기의 `set_intercept_relay(false)` 가 PC10 HIGH). 14:09 부팅 이후 실제로 분리돼 있었다(52111 14:01:32 부터 활성). 복구: SILENT 에서 `0xe8=1`. 분석 문서 §6.
- 종전 서술 "0xe8 의 set_intercept_relay 가 릴레이 cut 에 필수(제거 시 0/8)" 는 **미검증**이다.
  근거였던 e8 실험은 set_intercept_relay 제거와 release cover 제거를 동시에 바꿨고, 플래시 재부팅으로
  방향이 바뀌었을 수 있다. e8 로그는 8사이클 전부 bus2 에 Seer 요청만 있고 모터 프레임 0 = FLIPPED 서명.
  상세: `docs/can_relay/debt-129-rehoming-cause-analysis-2026-09-04.md` §3.
- release cover: `0xe8=0` 직후 `set_safety_mode(0)` 이 바로 따라오므로 cover 창은 수 ms 뿐이다(300 ms 아님).
  SILENT 이후 판다는 응답도 흡수도 하지 않는다.

## 3. 잔여 ~13% — 원인과 현재 상태 (분석 문서 `debt-129-rehoming-cause-analysis-2026-09-04.md`)

- **[2026-09-04 17:30 실측]** 하네스 판정 NC 고정 펌웨어에서 **33/33 PASS(engage 4 s·6 s), engage 중 Seer 재init 쓰기 0건, EMCY 0**(분석 §8). 이어 100사이클 확인 런 100/100 PASS(누적 133/133) — **debt-129 해결 확정**(사용자 종결 기준 100회). 아래 원인 서술은 수정 전 관측이다.

- **재호밍 = Seer 의 조향 재init 시퀀스 `cw=0x86 → 0x6099=2500 → 0x60FB:04=1` 가 실모터에 도달할 때.**
  Seer 는 engage 중 이 시퀀스를 매 사이클 ~3.4 s 주기로 반복 발행(PASS 회차 포함, hs_ 실측 cw=0x86 2~11회/4 s)하고
  판다가 흡수한다. release 순간 진행 중이던 시퀀스가 새는 회차가 FAIL 이다(rel8 cyc5: node4 에 세 write 가 실리고 pos→0).
- **미확정 = Seer 가 engage 중 왜 재init 을 반복하는가.** 후보: 전이 글리치+재연결 타이머 / node4 EMCY 0x8110
  (FAIL 회차에만 56건) / 상시-0x9450 statusword. 확정 실험은 분석 문서 §4 (E1~E3).
- 수정 방향(승인 전): ① 방향 판정 무력화(교란 제거 선행) ② release 를 "재init write 미관측 300 ms" 조건부로
  ③ L1 트리거 확정 후 emulate 보정.
