## 1. USB 메시지 종류 (PC ↔ 판다)

| 방향 | MSG | 용도 | 페이로드(논리) |
| --- | --- | --- | --- |
| PC→판다 | `CAN_TX` | 원시 CAN 프레임을 지정 버스로 송신 | {bus, cob_id, ext, rtr, dlc, data[0..8]} |
| PC→판다 | `RELAY_CTRL` | 릴레이/주도권/E-STOP 전환 | {relay, auth, estop} (§3) |
| 판다→PC | `CAN_RX` | 버스에서 수신한 원시 프레임 | {bus, cob_id, ext, rtr, dlc, data[0..8], ts} |
| 판다→PC | `RELAY_STATE` | 현재 릴레이/게이트/헬스 | {relay, auth, berr, gated_cnt} (§3) |

- `CAN_TX`/`CAN_RX` = 판다 기존 `can_send`/`can_recv` **그대로 재사용**(bus 번호 포함). 신규 펌웨어 코드 0.
- 즉 신규 펌웨어 = `RELAY_CTRL` 처리 + intercept 전환 + 게이트 훅뿐.

## 2. CAN 프레임 필드 ↔ USB 필드 (래핑 — 값 변환 없음)

| CAN 요소 | USB 필드 | 비고 |
| --- | --- | --- |
| 11-bit ID (`0x600+N`, `0x580+N`, `0x700+N`) | `cob_id` (u16) | 값 그대로. 확장ID는 `ext`=1(본 버스는 미사용) |
| RTR(Remote Transmission Request) (guard 요청) | `rtr` (bit) | `0x700+N` guard RTR |
| DLC(Data Length Code) | `dlc` (u8) | expedited SDO 는 8 |
| data[0..7] | `data[8]` | **바이트 무변환** — 예: `23 FF 60 00 8D 09 00 00` |
| 버스 세그먼트 (Seer측/모터측) | `bus` (u8) | 판다 bus 번호(실측 매핑, §6) |

- **값 변환이 아예 없음** — PC 가 `0x60FF`(속도)·`0x607A`(위치) 프레임을 완성해 통째로 던지고, 펌웨어는 지정 bus 에 실을 뿐.

## 3. RELAY_CTRL / RELAY_STATE 명령표 (전환의 핵심)

| `relay` | 물리 릴레이 | CAN 경로 | 시나리오 |
| --- | --- | --- | --- |
| `PASSTHROUGH`(0) | OFF `set_intercept_relay(false)` | Seer ─직결─ 모터 (판다 우회) | **노드 이동**(Seer 구동) + fail-safe |
| `INTERCEPT`(1) | ON `set_intercept_relay(true)` | Seer ─[판다]─ 모터 (판다 삽입) | **도킹**(PC 구동) |

| `auth` | 게이트(intercept 중에만 유효) |
| --- | --- |
| `SEER`(0) | 투명 중계 — 양방향 원시 통과 (판다 삽입만, 간섭 없음) |
| `PC`(1) | **게이트 ON** — Seer 쓰기 차단 + 가짜 ack 합성(§4), 모터 명령은 PC `CAN_TX` |

| `estop` | 동작 |
| --- | --- |
| `1` | 즉시: PC 구동 정지(속도 0 프레임) + `auth` 자동반환 보류(Seer 즉시 재구동 방지) |

- **전환 순서(PC→도킹)**: `RELAY_CTRL{INTERCEPT, auth=PC}` → 이후 `CAN_TX` 로 enable·속도·위치 프레임 스트리밍.
- **반환(도킹→노드이동)**: 속도 0 `CAN_TX` → `RELAY_CTRL{auth=SEER}` → `RELAY_CTRL{PASSTHROUGH}`.
- `RELAY_STATE` 로 PC 는 릴레이/게이트 상태·`berr`(can0 error-passive)·차단 프레임 수를 폴링.

## 4. CAN 프레임 클래스별 흐름 (모드별) — 모터 독립·CANopen 일반 규칙

게이트는 **오브젝트 인덱스를 모름** — COB-ID 대역 + SDO 명령바이트만 본다(Tongyi 고유 아님).

| 프레임 클래스 | 판정 조건 | passthrough | intercept·auth=SEER | intercept·auth=PC |
| --- | --- | --- | --- | --- |
| Seer→모터 **쓰기** | `0x600~604` & data[0]∈{23,27,2B,2F} | (직결) | 통과 | **drop + 가짜 ack** `0x580+N:60 ..` → Seer |
| Seer→모터 **읽기** | `0x600~604` & data[0]=`40` | (직결) | 통과 | **통과**(Seer 폴링 유지 → 단절 미판정) |
| Seer→모터 **guard RTR** | `0x700+N` RTR | (직결) | 통과 | **통과** |
| 모터→Seer **응답** | `0x580+N` | (직결) | 통과 | 통과 |
| 모터→Seer **guard 응답** | `0x700+N` data | (직결) | 통과 | 통과 |
| **PC→모터 명령** | PC `CAN_TX`(속도·위치·controlword) | — | (미사용) | **모터 bus 로 송신** |
| PC 명령 에코 차단 | `0x600~604`·NMT 역방향 | — | — | 모터→Seer 방향 **비전달**(에코 은폐) |

| **bus↔bus 중계** | `bxcan.h:195-200` | `to_send` 에 `extended/addr/bus/dlc/data` 만 복사 → **중계 시 RTR 이 데이터 프레임으로 변질** |
| 구조체 | `can_definitions.h` `CANPacket_t` | `rtr` 필드 자체가 없음 (`reserved:1` 만 여유) |

**영향**: passthrough(물리 직결)에서는 무관하나, **intercept 중에는 Seer 의 guard RTR 이 모터에 정상 전달되지 않아**
guard timeout → 노드 폴트 위험. PC 가 대신 guard RTR 을 쏘는 것도 불가(동일 제약).

**해결(필수 패치)**: `CANPacket_t.reserved:1` → `rtr:1` 전용 + 4 지점 수정
1. `bxcan.h` TX: `TIR |= (rtr << 1)`
2. `bxcan.h` RX: `to_push.rtr = (RIR >> 1) & 0x1`
3. `bxcan.h` fwd: `to_send.rtr = to_push.rtr`
4. `python/__init__.py` `pack_can_buffer`/`unpack_can_buffer`: `header[0] bit0` 에 rtr 반영
   (와이어 포맷 무변경 — 예약 비트 사용이므로 프레임 크기·정렬 영향 없음)

## 9. ✓ 게이트 정착 지점 — `safety_fwd_hook` (RX 인터럽트 내)

- `typedef int (*fwd_hook)(int bus_num, CANPacket_t *to_fwd);` — `board/safety_declarations.h:92`
- `can_rx()` 인터럽트에서 호출, **반환값 = 전달할 bus 번호, `-1` = 드롭** (`bxcan.h:190`)
- 즉 §4 게이트를 **커스텀 `fwd_hook` 으로 구현**하면 μs 급으로 동작:
  - Seer 쓰기 차단 = `return -1`
  - 가짜 ack = 그 자리에서 `can_send()` 로 `0x580+N` 합성 프레임을 Seer 측 bus 로
  - 읽기·guard 통과 = `return <상대 bus>`
- 참고 구조: `board/safety/safety_defaults.h:70` `alloutput_fwd_hook` (이미 `passthrough` 파라미터 분기 예시 존재)

## 10. 남은 미확정 (⚠)

- `RELAY_CTRL` 전용 USB 제어전송(vendor request) 번호 신규 할당 (`board/usb_comms.h` 기존 번호와 충돌 회피).
- 도킹 중 PC→USB→CAN 경로 지터 실차 확인 (Seer 게이트는 온보드 `fwd_hook` 이라 calibrating 루프와 무관).
- 현 테스트 펌웨어는 `ALLOUTPUT=intercept 상시 강제` — 본 설계는 **PC 명령으로 passthrough↔intercept 동적 전환**
  이 필요하므로 해당 강제 해제 + `RELAY_CTRL` 연동으로 변경할 것.
