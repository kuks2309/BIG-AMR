# CAN relay 실구동 테스트 표준 프로세스 (2026-07-26 정립)

> 실로봇 구동/조향 테스트 시 **매번** 아래 순서를 지킨다. 오염된 상태(재호밍 트랜지언트·잔여 오류)에서 테스트하면 결과가 무의미하거나 위험하다. (근거: 2026-07-26 세션 — 플래시 직후 미회복 상태에서 구동해 52111/54301 오탐, freeze 검증 오염.)

## 절차 (순서 고정)

1. **호밍(Homing)** — 조향을 −리밋 데이텀(0x6098=1)까지 구동 후 Seer가 조향을 직진(Seer-frame 0°, 물리 직진 미확인)으로 복귀시킨다. 완료까지 대기. (홈과 0° 등치 금지 — 데이텀은 raw ~+137°, 직진 정착은 ~7.88M/7.86M(0°에서 +0.178°/+0.331°).)
2. **상태 확인(Status)** — 조향 실위치(0x6064) 리드백으로 **홈 도달 검증**(±허용오차 내). 미도달이면 진행 금지·원인규명.
3. **Seer 오류 확인·삭제** — `python3 seer_prep.py [ip]`:
   - API 1050으로 현 알람 확인 → API 4009(Clear All Errors)로 클리어 → 재확인.
   - **잔여 fatal/error 0 이어야 진행**(exit 0). 잔여 있으면 미회복 오류 = 진행 금지(원인 해결 먼저). *"미회복 오류는 클리어해도 재출현"(Seer best-practices §2.7).*
4. **클린 baseline 확인** — `seer_can_monitor.py [ip] 20` 로 **신규 CAN/모터 알람 0**(laser 계열은 무관) 확인.
5. **테스트 진행** — engage(take)→enable→구동/조향. 구동 중 monitor 병행.
6. **판정** — 구동 중 **신규** 52111/52106/52954/54301(+55602) = 0. bus2 에러 0. 지령대로 물리거동.
7. **종료** — home→release(passthrough)→q. Seer 직결 복귀(safety_mode=0) 확인.

## 도구
- `seer_prep.py` (오류 확인·클리어, exit 2=미회복) — scratchpad/kit.
- `seer_can_monitor.py [ip] [초]` (알람 실시간, exit 2=신규알람).
- 통합 드라이버(docking_drive 재사용 + 0x6064 리드백 + drivetest 후진→전진).

## 주의
- **플래시 후엔 판다 리부팅으로 Seer가 odo lost/재호밍(52106/54301)** — 반드시 4~5단계로 **완전 안정화 후** 테스트.
- Seer 오류의 laser 계열(Nanosick lidar)은 모터 무관 — CAN/모터 코드만 게이트.
- 운용 유의: 호밍 자체는 확정 동작(10/10, 35.0s, 2026-08-03). 조향이 ±90° 범위를 벗어나면 0x607A 위치지령이 무반응이 되는 것은 이해된 거동이며, 복구는 직결 CAN 원점 호밍(정상 동작)으로 한다.
