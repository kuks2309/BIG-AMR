## 2. ⚠ 상태워드를 CiA402 교과서로 읽으면 오판한다

정지 상태에서 4축이 다음을 보고한다 — 교과서대로면 **Switch on disabled**(비활성)다.

| 축 | 0x6041 | 교과서 해석 |
|---|---|---|
| N1·N2(구동) | `0x8050` | VoltEn, **SwOnDis**, bit15 |
| N3·N4(조향) | `0x1050` / `0x9450` | VoltEn, **SwOnDis**, SetptAck, (TgtReached) |

**그 해석은 틀렸다.** 마스터(Seer)가 조향을 100°+ 실제로 움직이던 캡처
`Log/homing_capture_220350.jsonl`(253,510 프레임)에서 **같은 값**이 나온다 —
N1·N2 `0x8050` ×420, N3·N4 `0x1050` ×1,527 / `0x9450` ×334.
즉 이 드라이브들은 **운전 중에도** 그 비트 조합을 보고한다.

덧붙여 그 캡처에서 마스터가 쓰는 controlword 는 `0x003F`(12,928회)·`0x0086`(216회) **둘뿐**이고
**NMT(COB-ID 0x000) 는 0건**이다. CiA402 enable 시퀀스(0x06→0x07→0x0F)는 마스터도 쓰지 않는다.
→ **「상태워드가 SwOnDis 라서 구동이 안 된다」는 판정을 하지 말 것.** 실제로 돌았다(아래).

**① 엔코더(0x606C 실속도)**

| 구간 | N1 평균 | N2 평균 | 지령 대비 최대 도달 |

정지 기준선 `ax = +0.2702 m/s²` 대비:

# ROS2 스택 실기 대조 (2026-08-04 15:17)

같은 시퀀스를 `can_relay` 드라이버 + ROS2 경로로 돌려 위 기준선과 대조했다.
원자료 `Log/field_2026-08-04/ros2_*.csv`.

## 1. 부호 규약 — `~/drive_mmps` 는 **raw 부호**다

`_on_drive_mmps` 는 `set_drive_mmps(mmps)` 를 `sign=1` 로 부른다 → raw = `mmps × 24.447`.
원본의 「전진 = raw 음수」(`JOG["전진"][1] = -1`)와 맞추려면 **`-50.0` 을 발행**해야 전진이다.
GUI 두 백엔드는 `app.py:565` 의 `be.drive(sign*mmps)` 에서 부호를 적용하므로 서로 일치한다.

## 2. IMU 대조 — 두 스택이 **같은 운동**을 만든다

같은 센서·같은 96 Hz 이므로 이것이 가장 공정한 비교다.

| 구간 | 원본 GUI | ROS2 스택 | 차이 |
|---|---|---|---|
| 전진 ax 평균 | +0.0477 | **+0.0478** | 0.0001 |
| 후진 ax 평균 | −0.0588 | **−0.0590** | 0.0002 |
| gz 평균 | ≈0.0003 | ≈0.0003 | — |

엔코더 실속도도 대칭이다(ROS2: 전진 −937/−896, 후진 +875/+883; 표본율이 달라 평균값 자체는
직접 비교하지 않는다 — 최대 도달은 −1311/+1301 로 원본 −1345/+1317 과 같은 대역).

정지 소요: ROS2 0.62 s / 0.81 s (원본 0.57 s / 0.65 s) — 같은 감속 프로파일이다.

> ⚠ 순변위는 원본 −144/+72 counts(원위치), ROS2 +36,222/+36,143 counts 로 갈렸다.
> **각 1회씩이라 스택 차이라고 말할 수 없다.** 정지 소요가 회차마다 0.54~0.81 s 로 흔들리는
> 것이 그대로 남은 거리 차이로 보이며, 판정하려면 반복 측정이 필요하다.

## 3. ⚠ 발견하고 고친 결함 — ros2 백엔드의 조그가 **스스로 꺼졌다**

드라이버에는 `cmd_timeout_s = 0.3` 워치독이 있다 — 「지령원이 죽으면 드라이브가 마지막 값을
물고 가지 못하게」 하는 **의도된 안전장치**다(`backend.py` 규칙 2). 그런데 `backend_ros2` 는
`drive()` 에서 **한 번만 발행**했다(타이머 0건). 결과:

```
지령 후 0.32s  실속도  -752   ← 출발
       0.53s          -1172  ← 최고
       0.75s           +133  ← 스스로 꺼짐
       0.97s              0
```
(`Log/field_2026-08-04/wd_singleshot.csv`)

`--backend direct` 는 유지되고 `--backend ros2` 만 꺼지므로 「UI 100% 동일」이 깨져 있었다.

**사용자 결정(2026-08-04)**: 「ros2 설계는 맞고 UI 에서 계속 명령을 내는 것이 맞다.」
→ 드라이버 워치독은 그대로 두고 `RelayClient` 가 20 Hz 로 재발행한다.

조치 후 실기 재확인 — `send_drive(-50.0)` **단발 호출**로 1.5 초 내내 유지된다:

```
1.30s -1143 → 1.62s -1317 → 1.94s -1221 → 2.42s -1215   (유지)
stop() @2.53s → 3.29s 에 0 도달 (0.76 s, 감속 프로파일과 일치)
```
(`Log/field_2026-08-04/ros2_hold_after_fix.csv`)

### 3-1. 재발행이 만든 두 부작용 — 둘 다 시험이 잡았다

1. **정지 무효화**. 재발행이 `~/stop` 직후 마지막 비영 지령을 다시 내보냈다.
   → `Ros2Backend.stop()` 이 **유지값을 먼저 0 으로 내린 뒤** 서비스를 부르도록 순서를 고정했다.
   회귀 `test_stop_wins_over_republish`.
2. **토픽 점유**. 처음에는 0 도 무기한 재발행해, 유휴 상태의 GUI 가 외부 지령을 즉시 덮어썼다
   (실측: 외부에서 넣은 50 이 드라이버에 **도달조차 못 했다**).
   → 비영이면 계속, 0 이면 `ZERO_HOLD_S=0.5 s` 동안만 반복하고 침묵한다.
   회귀 `test_zero_is_repeated_briefly_then_goes_quiet`.

조그 중 GUI 가 죽으면 재발행이 끊겨 워치독이 0.3 s 안에 0 으로 만든다 —
**「지령원이 죽으면 멈춘다」는 보호는 그대로 살아 있다.**
