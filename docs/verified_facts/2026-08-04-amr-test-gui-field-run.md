# ROS2 스택 실기 대조 (2026-08-04 15:17)

같은 시퀀스를 `can_relay` 드라이버 + ROS2 경로로 돌려 위 기준선과 대조했다.

## 1. 부호 규약 — `~/drive_mmps` 는 **raw 부호**다

GUI 두 백엔드는 `app.py:565` 의 `be.drive(sign*mmps)` 에서 부호를 적용하므로 서로 일치한다.

같은 센서·같은 96 Hz 이므로 이것이 가장 공정한 비교다.

정지 소요: ROS2 0.62 s / 0.81 s (원본 0.57 s / 0.65 s) — 같은 감속 프로파일이다.

## 3. ⚠ 발견하고 고친 결함 — ros2 백엔드의 조그가 **스스로 꺼졌다**

드라이버에는 `cmd_timeout_s = 0.3` 워치독이 있다 — 「지령원이 죽으면 드라이브가 마지막 값을

### 3-1. 재발행이 만든 두 부작용 — 둘 다 시험이 잡았다

   → `Ros2Backend.stop()` 이 **유지값을 먼저 0 으로 내린 뒤** 서비스를 부르도록 순서를 고정했다.

2. **토픽 점유**. 처음에는 0 도 무기한 재발행해, 유휴 상태의 GUI 가 외부 지령을 즉시 덮어썼다
   (실측: 외부에서 넣은 50 이 드라이버에 **도달조차 못 했다**).
   → 비영이면 계속, 0 이면 `ZERO_HOLD_S=0.5 s` 동안만 반복하고 침묵한다.
   회귀 `test_zero_is_repeated_briefly_then_goes_quiet`.

조그 중 GUI 가 죽으면 재발행이 끊겨 워치독이 0.3 s 안에 0 으로 만든다 —
**「지령원이 죽으면 멈춘다」는 보호는 그대로 살아 있다.**

## 1. ⚠ ROS2 는 **호밍 전 조향을 거부한다** — 원본은 거부하지 않는다

ROS2 첫 조향 시도는 바퀴가 **한 카운트도 움직이지 않았다.** 드라이버 로그:

```

             `~/home` 를 먼저 수행할 것(전원 사이클마다 필요)
```

`backend.py:213` `require_homed_for_steer` 게이트다(매뉴얼 §Home 35: 홈은 전원이 켜져 있는
동안만 유효 → 기동 후 호밍 전의 `0x6064` 는 어떤 각도인지 알 수 없다).
`homing_enabled: false` 와 겹쳐 **조향이 도달 불가 상태**였다.

  (드라이브의 `0x6041` bit15 에서 유도하지 않는다.)
- 이 검증을 위해 `config/machine/foil_a082.yaml` 의 `homing_enabled` 를 **true 로 바꿨다**
  (사용자 승인 2026-08-04). ROS2 조향을 쓰려면 켜져 있어야 한다.

## 2. 호밍 — 두 스택 모두 성공, 정착값 재현

| | 소요 | 완료 직후 N3 | N4 |
|---|---|---|---|
| ROS2 1회차 | 35.1 s | 7,882,022 (+0.178°) | 7,859,065 (+0.331°) |
| ROS2 2회차 | 35.1 s | 7,882,014 (+0.178°) | 7,859,058 (+0.331°) |
| 원본 | 31.5 s | **0** (무효) | **0** (무효) |

문서 기록값 7,882,021 / 7,859,065 를 **8 counts 이내로 재현**했다.
호밍은 조향 0° 가 아니라 +0.178° / +0.331° 에 정착한다는 것도 다시 확인됐다.

### ⚠ 원본은 완료 직후의 **무효 위치를 −137° 로 표시한다**

원본은 「호밍 완료 — 31초 소요」를 찍은 직후 `0x6064 = 0`, 각도 **−137.274° / −136.720°** 를
그대로 내놓았다. `0x6064`=0 은 `bit15`=0 구간의 무효값이다(`backend.py` 규칙 5).
ROS2 드라이버는 이 구간을 걸러내지만 **원본은 거르지 않아 운용자가 −137° 를 실측으로 본다.**
약 40 초 뒤 재판독하면 `bit15`=1 이고 위치도 정상이다(7,871,818 / 7,840,084).

> ⚠ 그 40 초 사이에 제어권을 반환했으므로 **Seer 가 0° 로 되돌린 것인지, 원본 호밍이 0° 로
> 복귀시킨 것인지 이 데이터로는 가릴 수 없다.** ROS2 는 제어권을 쥔 채 읽어 +0.178°/+0.331°
> 였다. 가리려면 제어권 유지 상태에서 연속 판독해야 한다 — 하지 않았다.

## 3. ~~조향 정밀도~~ — **철회한다 (2026-08-04)**

여기 있던 「조향 오차가 이동 거리에 비례한다(45°→0.25°, 90°→0.68°)」 표를 **철회한다.**

- **측정이 틀렸다.** 그 값들은 `_wait_settle(tol=1.0°)` 로 **1° 안에 들어오는 순간** 읽은 것이라
  아직 이동 중인 축을 잰 것이다. 위치가 실제로 멈출 때까지(3연속 200 counts 미만) 기다려
  다시 재니 5·10·20·45·90° **전 구간에서 오차가 0.000°**(최대 8 counts = 0.00014°)였다.
- **애초에 우리 소관이 아니다.** 위치 도달 정확도는 **검증된 상용 드라이브·모터**의 성질이다.
  이 저장소의 릴레이 소프트웨어가 하는 일은 제어권을 받아 지령을 중계하고 돌려주는 것뿐이므로,
  이 수치는 여기 있을 이유가 없었다. (사용자 지적: 「상용제어기에 우리는 제어권만 받아와서
  돌려주는데.. 이미 검증된 제어기와 모터를 사용하는데」)

같은 이유로 「원본 ↔ ROS2 순변위 차이」 재측정 계획도 폐기한다 — 두 스택이 같은 프레임을
보낸다는 것은 이미 바이트 대조(`test_master_frame_match`·`test_port_equivalence`)로 고정돼 있다.
