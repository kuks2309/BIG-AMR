## E-1. `0x6041` bit15 1→0 **시각** — 정밀도 하향 (결론 유지)

**잘못**: `t=17.9562`/`17.9567` 을 bit15 **전이 시각**으로 기술.

**정정**: 그 시각은 **bit15=0 으로 관측된 최초 시점**이다. 직전 `0x6041` 폴이 `t=5.1383`/`5.1387`
이고 그 사이 폴이 0건이므로 전이는 구간 **`(5.138, 17.956]`** 안에서만 확정된다.

**⚠ v1 과잉 정정**: v1 은 「트리거 31 ms 뒤 bit15 하강」이라는 **인과 서술이 성립하지 않는다**고 했으나
이는 과잉이다. 인과는 별도 증거로 앵커돼 있다:

- Handbook 인쇄쪽 151~152 — `Bit15: Home attend … when homing is actived, this bit will be reset`
  (bit15 리셋의 원인을 호밍 활성화로 규정)
- 캡처 전 구간 controlword **bit15(Reset Home) write 0건** → 캡처 내 유일한 호밍 활성화 명령은
  `0x60FB.4=1`(`t=17.9252/17.9257`) 하나뿐
- `0x6064` → 0 리셋이 **`(17.9232, 17.9302]` 7 ms 안에 갇혀** 그 write 를 감싼다

**결론**: 미확정인 것은 **bit15 전이 시각뿐**이며, 「트리거 → 호밍 개시」 인과는 `0x6064` 로 확정된다.
호밍 실행 시작점은 **`t≈17.93`** 로 유지.

### E-3c. `0x6000` 발췌 — **v1 발췌는 축자가 아니다**

v1 은 "원문과 완전 일치"라며 발췌를 실었으나 4건이 누락됐다. **축자 원문**(인쇄쪽 197 / PDF 199):

```
6000   ARRAY   Digtal_Input                UINT32   RO   YES
   0           Number of Input             UINT8    RO   YES
   1           Read Input 1h to 8h State   UINT8    RW   YES
   Parameter Description: ParameterBit0-Bit3 = DI0-DI3 input status, default value (0xBF);
   Bit0: Servo Enable State  Bit1: Positive Limit State  Bit2: Alarm State  Bit3: Negative Limit State
```

**누락이 사소하지 않은 이유**: 삭제된 `Parameter Description` 줄에 **기본값 `0xBF`** 와
**`Bit0-Bit3 = DI0-DI3` 대응**이 들어 있고, 이는 §4.6(인쇄쪽 116)의 *"the limit input (**DI4/DI2**)"*
와 **충돌**한다. 이 충돌은 미해결이다(→ debt-008). `protocol.py:45` 는 이미 `default 0xBF` 를
보존하고 있었으므로 **v1 정오표가 코드보다 정보량이 적었다.**

비트→의미 매핑 자체(`Bit0 Servo Enable / Bit1 Positive Limit / Bit2 Alarm / Bit3 Negative Limit`)는
원문과 일치한다 — 이 부분은 유효.
