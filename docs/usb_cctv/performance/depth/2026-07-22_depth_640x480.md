# Depth Camera FPS Benchmark — Orbbec Gemini E

- Date: 2026-07-22
- Host: tr-orin-22 (Jetson Orin, ROS2 Humble)
- Driver: OrbbecSDK_ROS2 (`orbbec_camera`, gemini_e.launch.py)
- Measurement: `ros2 topic hz /camera/depth/image_raw` (single camera)

## Setup

```bash
ros2 launch orbbec_camera gemini_e.launch.py \
  depth_width:=640 depth_height:=480 depth_fps:=30 \
  enable_depth:=true enable_color:=false
```

Driver confirmed stream: **depth 640x480 @ 30 fps, format Y11** (IR co-enabled
at 640x480@30 Y10 — IR must match depth per the driver).

## Result — depth-only, single camera

| resolution | format | requested fps | measured fps | interval min/max | std |
| --- | --- | ---: | ---: | --- | ---: |
| 640x480 | Y11 | 30 | **~29.3** (steady 29.0-29.98) | 0.028 s / 0.102 s | 0.0065 s |

- **640x480@30fps depth is achieved** (~29.3 fps effective). No need to step down.
- Very stable; occasional ~100 ms inter-frame hiccups (a few per ~400 frames).

## Datasheet cross-check

ORBBEC Gemini E Datasheet v1.1 (`References/orbbec/gemini_e/`) — depth supports
5/10/15/30 fps at 640x480 (Y11/Y12); 1024x768 depth is capped at 5/10 fps. The
measured 30 fps matches the spec ceiling for this resolution.

## Multi-camera & RGB+Depth results (measured 2026-07-22)

All cameras are currently on a **single USB 2.0 bus** (Bus 001); the host's
USB 3.0 bus (Bus 002) is empty. All numbers below are on that shared USB 2.0 bus.

| scenario | streams/cam | result |
| --- | --- | --- |
| 1 cam, depth only | depth | **~29.3 fps** (full rate) |
| 1 cam, depth + RGB (+IR) | depth+ir+color | depth **~13 fps**, color ~25 fps |
| 4 cam, depth + RGB (+IR) | depth+ir+color | **only 3/4 open**; cam2 `uvc_open` fails with LIBUSB_ERROR_BUSY (-6, bandwidth). Opened cams: depth ~12-20 fps, color ~26 fps (one color stream never published) |
| **4 cam, depth only** (no color/IR/PC) | depth | **all 4 open**, each **~14 fps** (aggregate ~56 fps) |

### Answers

- **4 cameras depth-only?** Yes — all 4 stream simultaneously, but at **~14 fps
  each**, not 30 (shared USB 2.0 bandwidth: depth Y11 640x480 ~18 MB/s/cam at 30
  fps; 4x exceeds the ~40 MB/s usable bus, so the rate self-limits to ~14).
- **4 cameras depth + RGB?** Does **not** fit — the 4th camera's color (UVC)
  interface fails to open (LIBUSB_ERROR_BUSY), and the 3 that open run depth
  degraded to ~12-20 fps.

### To get higher multi-camera depth rates

1. **Use the empty USB 3.0 bus** (Bus 002) — distribute cameras across both
   buses. This is the biggest win; USB 3.0 has ~10x the bandwidth. *(Untested —
   requires re-cabling to the USB 3.0 ports.)*
2. Lower depth resolution (e.g. 320x240) to cut per-camera bandwidth.
3. Accept ~14 fps for depth if RGB CCTV is the primary stream.
4. Disable IR (done here) and point cloud to minimize streams.
