## Context (배경)

`can_relay` ROS2 노드는 **제어 주도권**을 쥐는 계층이다. 이것이 멈추면 로봇이 지령을 받지
못한다. 사용자 요구는 두 가지였다 — **① 별도로 감시할 것 ② 멈추면 재가동할 것.**

### 역할 분리 (사용자 지시 2026-08-15 10:37)

| | 펌웨어 (`Tools/Can_Relay/`) | ROS2 노드 (`src/Comm/CAN/can_relay/`) |
| --- | --- | --- |
| 성격 | **항상 살아 있다** | 죽을 수 있다 |
| 소유 | 버스 중재·릴레이·fail-safe·호밍 시퀀서 | 지령·상태 발행·진단·서비스 |
| 노드 생존 판정 수단 | **심박(`0xf3`) 하나** | — |

본 ADR 의 대상은 **ROS2 노드**다. 펌웨어는 수정하지 않는다.

### 사전조사 — 노드가 죽는 형태는 3가지이고, 그중 하나는 사각지대다

| | 형태 | 심박 | 펌웨어가 아는가 | 결과 |
| --- | --- | --- | --- | --- |
| ① | 프로세스 소멸 (crash·OOM(Out Of Memory)·kill) | 끊김 | ✅ | 구동 0 → 릴레이 개방 |
| ② | 프로세스 생존, 백엔드 루프 정지 | 끊김(같은 스레드) | ✅ | 동일 |
| ③ | 프로세스·백엔드 정상, **ROS 계층만 정지** | **계속 나감** | ❌ | **좀비** |

③ 의 근거: 심박은 백엔드 스레드가 낸다(`backend.py:941`). ROS executor 가 정체하면
`/motor/low_cmd` 가 소비되지 않아 워치독이 **구동은 0** 으로 만들지만(`backend.py:952-959`),
조향 setpoint 는 계속 재송신되고(`backend.py:966-969`) `~/stop`·`estop` 은 도달하지 못하며
(콜백 미실행) 심박이 유지되므로 펌웨어도 개입하지 않는다. 프로세스가 살아 있어 systemd 도
재기동하지 않는다. ⇒ **제어권을 쥔 채 지령도 못 받고 아무도 못 뺏는 상태가 무기한 유지된다.**

### 조사가 확정한 것 (설계를 바꾼 사실 3건)

1. **노드 사망은 폭주가 아니다.** 심박 상실 1~2 s 뒤 펌웨어가 구동 노드에 `0x60FF=0` 을 3회
   쓰고(`safety_seer_gate.h:554-559`) 릴레이를 연다(`main.c:227-237`). 정지는 이미 보증된다.
2. **재호밍은 불필요하다.** `homed_effective()` 가 드라이브의 `0x6041` bit15 를 신선한 피드백
   조건으로 인정한다(`backend.py:260-282`). 전원이 유지되는 한 재기동 직후 조향이 열린다.
   ⇒ 복귀 비용이 35 s·100° 스윙이 아니라 서비스 콜 1회다.
3. **조향은 펌웨어 fail-safe 대상이 아니다.** `seer_stop_drives()` 의 순회 범위가 node1~2 로
   못박혀 있어 조향축은 건드리지 않는다. 릴레이 개방 후 조향의 운명은 Seer 의 `0x607A` 가
   정한다 — 캡처 6종(38만 프레임) 전수에서 Seer 는 「현 위치 유지」 패턴이나
   (`master_command_census.py`: `|목표−실측| ≤ 200 c` 가 5개 캡처 100 %, 1개 95.9 %),
   intercept 중 Seer 가 읽는 값은 **engage 시점 동결본**이다(`safety_seer_gate.h:88-93`,
   `:136-138`). 따라서 개방 직후 조향 거동은 **미확정**이며 본 ADR 은 그것을 가정하지 않는다.

### 현행 결정과의 충돌

`launch/can_relay.launch.py:44-46` 이 `on_exit=Shutdown()` 과 함께
*"respawn 하지 않는다 — 재기동은 제어권을 다시 잡는 행위이고 사람이 판단해야 한다"* 를
명시한다. 자동 재기동 요구와 정면으로 부딪힌다.

## Decision (결정)

### 1. 「재기동」과 「재engage」를 분리해 충돌을 해소한다

원 결정의 취지는 **버스를 다시 뺏는 행위**를 사람 판단에 두는 것이다. 프로세스 재기동
자체는 그 행위가 아니다 — `PandaLink` 는 `~/engage` 이전에 USB 를 열지도 않는다
(`driver_node.py:353-355`). 따라서:

- **프로세스 재기동은 자동**(systemd). 되살아난 노드는 **대기 상태**로만 뜬다.
- **제어권 획득은 별도 판단**이며, 그 판단을 감시 노드가 **기록에 근거해** 내린다.

### 2. 형태 ③을 ①로 환원한다 — ROS 생존을 심박 조건에 넣는다

새 안전 장치를 만들지 않고 **기존 장치를 확장**한다. `tx_fail_halt` 는 이미
「송신이 죽으면 심박을 끊어 펌웨어에 정지를 넘긴다」를 구현하고 있다(`backend.py:233-247`(`_hb_block_reason`)).
같은 경로에 조건 하나를 더한다:

- ROS 계층(진단 타이머)이 `mark_ros_alive()` 로 생존을 찍는다.
- `_loop` 은 그 표시가 `ros_alive_timeout_s`(기본 2.0 s)보다 낡으면 **심박을 끊는다.**

⇒ 세 형태 전부가 펌웨어 하나로 수렴한다. **감시 노드에 정지 책임을 주지 않는 것**이 이
구조의 핵심이다 — 감시 노드는 죽어도 되는 물건이어야 한다.

임계 2.0 s 의 근거: 진단 타이머가 1 Hz(`diag_hz`)이므로 2 주기 누락이 판정선이다. 펌웨어
임계(점화 off 기준 1~2 s)와 직렬로 붙어 최악 4 s 안에 정지가 성립한다.

### 3. 상태 기록은 `/run`(tmpfs) + `boot_id` — 전원 사이클을 넘기지 않는다

기록 위치를 디스크로 두면 안 된다. 조향 홈 설정은 **전원이 켜져 있는 동안만 유효**한데,
전원 사이클 뒤에 "이전엔 engaged 였다"는 기록으로 복귀하면 기준 없는 상태에서 제어권을
잡는다. tmpfs 는 재부팅 시 소멸하므로 그 사고를 구조적으로 막고, `boot_id` 를 함께 적어
tmpfs 가 남는 예외 상황도 교차 검증한다.

### 4. 무엇을 복원하고 무엇을 복원하지 않는가

| 항목 | 기록 | 복귀 시 | 근거 |
| --- | --- | --- | --- |
| `engaged` | ✅ | **복원** (`~/engage true`) | 「전 상태 그대로 복귀」의 본체 |
| 조향 목표 | ✅ | **복원 안 함 — 대조만** | 죽어 있는 동안 Seer 가 축을 움직였을 수 있다. 기록값을 밀어넣으면 실제와 다른 각으로 튄다 |
| 구동 속도 | ✅ | **항상 0 에서 시작** | 재기동이 곧 재출발이 되면 안 된다. 상위가 지령을 다시 준다 |
| E-stop 래치 | ✅ | **복원 불요 · engage 게이트로 사용** | `LATCHED_QOS`(TRANSIENT_LOCAL)라 재기동한 노드가 구독 즉시 현재값을 받는다(`driver_node.py:51-54`) |
| `homed` | ✅ | 복원 불요 | 드라이브 bit15 로 자동 복구(위 Context 2) |
| 재기동 횟수 | ✅ | 초과 시 **복귀 중단** | 반복 engage/release 는 죽은 채 있는 것보다 나쁘다 |

**부수 효과 (의도한 것)**: 조향 목표를 기록해 두면 복귀 직후 실측과 자동 대조되어,
Context 3 의 미확정 항목(「릴레이 개방 중 Seer 가 조향을 engage 시점 각으로 되돌리는가」)이
**실운용 로그로 답을 쌓는다.** 별도 시험 없이 판정 자료가 축적된다.

### 5. 판정 로직은 순수 함수로 분리한다

`decide(prev, obs, cfg)` 하나에 모든 판단을 모으고 ROS·파일 입출력을 배제한다.
`safety.py` 와 같은 규율이며, 하드웨어 없이 전 분기를 회귀로 고정하기 위한 것이다.

구현에서 **모듈까지 갈랐다** — 판정은 `can_relay/health.py`(순수), ROS 껍데기는
`can_relay/supervisor.py` 다. 한 파일로 두면 `conftest.py` 가 규정한 미소싱 회귀에서
`import rclpy` 가 수집을 막아 전 분기가 검증되지 않는다(초안에서 실제로 그렇게 깨졌다).

### 6. 감시 노드는 제어 경로 밖에 둔다

구독(`/diagnostics`)과 서비스 호출(`~/engage`)만 한다. CAN 에 쓰지 않고 판다를 열지 않는다.
`system_health` 에 넣지 않는 이유는 그 패키지의 **`rclpy` 무의존 불변식**
(`test/test_no_rclpy_import.py`)이며, ROS 구독은 그 패키지의 Phase 2 로 분리돼 있다.
대신 `system_health` 에는 `expected_processes` 에 `can_relay_node`·`relay_supervisor` 를 등록해
`process_restarted`(PID(Process Identifier) 변화 = 조용한 crash-loop)를 기록하게 한다.

### 7. 자동 재기동이 지우는 안전 래치를 감시자가 이어받는다

**본 ADR 이 도입하는 자동 재기동은 기존 안전 장치 하나의 전제를 깬다.**

`RelayBackend._home_failed`(상류 `54ceea4`)는 「우리가 건 호밍이 축을 움직여 놓고 끝을 못
봤으면 `0x6041` bit15 를 조향 근거로 쓰지 않는다」는 래치다. 실기 사고가 근거다 —
`ERR_GOZERO` 로 끝나면 축이 −리밋에 선 채 bit15 는 1 로 남고, 그 자리에서 0° 지령을 받으면
**≈136.7° 움직인다.**

그 래치는 **인스턴스 변수**다. 도입 시점에는 자동 재기동이 없어 그것으로 충분했으나,
본 ADR 이 재기동을 자동화하는 순간 다음 경로가 열린다:

| 단계 | 상태 |
| --- | --- |
| 호밍 실패 | 축 −리밋 · `_home_failed=True` · 조향 차단 ← 상류가 의도한 안전 상태 |
| 노드 사망 → systemd 재기동 | 새 프로세스는 `_home_failed=False` |
| `homed_effective()` | 드라이브 bit15=1 을 보고 **조향을 연다** |
| 감시자 자동 복귀 | 제어권까지 얹는다 → 0° 지령 시 **136.7° 스윙** |

⇒ **자동 재기동을 도입하는 쪽이 그 래치를 이어받는다.** 상류가 이미 `home_failed` 를
진단 KeyValue 로 내므로(`60cfbd6`), 감시자는 그것을 기록하고 **E-stop 과 같은 등급의 복귀
차단 사유**로 쓴다(`health.py` `decide()`). 자동 해제 경로는 두지 않는다 — 해제는 `~/home`
재수행뿐이며 그것은 100°+ 스윙을 동반하는 사람의 판단이다.

### 8. 진단에 `estop`·`homed_effective`·`hb_suppressed` 를 노출한다

감시 노드가 `/diagnostics` 하나만 보고 판정할 수 있어야 한다. 현재 `estop` 은 KeyValue 에
없고 message 문자열로만 드러나 파싱이 취약하다. `snapshot()` 은 이미 세 값을 모두 갖고
있으므로 KeyValue 3개를 추가한다(발행 주기·구조 변경 없음).

## Consequences (결과)

### 얻는 것

- 형태 ③(좀비)이 **정지로 수렴**한다. 지금은 무기한 유지된다.
- 프로세스 소멸이 자동 복구되고, crash-loop 이 기록에 남는다(지금은 아무도 모른다).
- 「전 상태 그대로 복귀」가 성립한다 — 재호밍 없이 서비스 콜 1회.
- 미확정 항목(Seer 의 조향 인수 거동)이 운용 로그로 스스로 답을 쌓는다.

### 치르는 비용 / 남는 위험

- **심박 억제 조건이 하나 늘어난다 = 로봇이 설 수 있는 경로가 하나 늘어난다.** 진단 타이머가
  2 s 멈추기만 해도 정지한다. 이것은 의도이지만, `diag_hz` 를 낮추면 오작동한다 —
  파라미터 결합이 생겼으므로 기동 시 검증하고 문서에 명시한다.
- **자동 재engage 는 Seer 에게서 버스를 다시 뺏는 행위다.** crash-loop 게이트가 유일한
  방어선이며, 그 임계값(3회/120 s)은 실측이 아니라 채택값이다.
- **감시 노드가 죽으면 복귀가 안 된다.** 정지 보증에는 영향이 없으나(제어 경로 밖) 복귀
  기능은 잃는다. systemd `Restart=always` 로 덮되, 재귀적 감시는 두지 않는다.
- **`home_failed` 차단은 「기록된 관측」에 의존한다.** 감시자가 진단을 한 번도 못 받은
  채 노드가 죽으면 기록이 없어 그 게이트가 서지 않는다(그때는 `prev.engaged` 도 없어
  복귀 자체를 안 하므로 결과적으로 안전하나, **의도한 경로가 아니라 부작용**이다).
- **Context 3 이 미확정인 채로 출하된다.** 릴레이 개방 시 조향 거동을 모른다. 본 설계는
  그것을 가정하지 않으므로 안전하지만, crash-loop 이 조향 스윙 반복이 될 가능성은
  `StartLimitBurst` 로만 막힌다. 잭업 `kill -9` 실측으로 해소할 것 — 별건.

### 후속

- 잭업 `kill -9` 실측 → Context 3 확정 → 필요 시 펌웨어 동결 스냅샷 주기 갱신 검토(별도 ADR)
- `system_health` Phase 3b(토픽 최신성)와 본 감시 노드의 역할 정리

## Rollback (되돌림 계획)

**가역이다.** 비가역 요소 0 — 펌웨어·영속 스키마·시스템 설정을 바꾸지 않는다.

1. **systemd**: `systemctl disable --now can-relay.service can-relay-supervisor.service` 후
   유닛 파일 삭제. 설치 스크립트가 명시 실행될 때만 설치되므로, 미설치 장비는 영향 0.
2. **감시 노드**: 실행하지 않으면 그만이다. 다른 노드가 import 하지 않으므로 파급 0.
   기록 파일 `/run/can_relay/state.json` 은 재부팅 시 소멸(tmpfs).
3. **심박 억제 조건**: `ros_alive_timeout_s = 0` 이면 판정이 꺼진다(기존 동작과 동일).
   파라미터 한 줄로 되돌아가며 재빌드 불요.
4. **진단 KeyValue 3개**: 소비자가 키 부재를 견디도록 되어 있어 추가/삭제 양방향 무해.
5. **코드 되돌림**: 해당 커밋 revert. `backend.py`·`driver_node.py` 변경은 기존 경로를
   수정하지 않고 조건·호출을 **추가**하는 형태라 revert 충돌 위험이 낮다.
