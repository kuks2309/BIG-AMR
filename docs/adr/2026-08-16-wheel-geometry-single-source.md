# ADR 2026-08-16 — 휠 기하를 config 단일 출처에서 읽는다 (2WS 오도메트리 경로)

## Status

Accepted (2026-08-16). 구현·검증 완료, 최종 verdict 는 외부 리뷰 몫(coding SOP §5 never-self-approve).

## Context

휠 오도메트리의 수식은 구조에 무관하다 — 바퀴 좌표 (xᵢ, yᵢ) 만 데이터로 들어가고,
정규방정식 행렬식은 `det = N·[N·Σ(xᵢ²+yᵢ²) − (Σxᵢ)² − (Σyᵢ)²]` 로 일반형이며 바퀴 2개일 때
`det = 2·d²`(d = 두 바퀴 간 거리)라 **두 바퀴가 한 점에 겹칠 때만** 특이하다.
즉 구조가 바뀌어도 바뀌어야 하는 것은 **숫자뿐**이다.

그런데 구현이 그렇게 되어 있지 않다. 저장소에 정본 파일
`trnav_2ws_core/config/robot_geometry_2ws.yaml` 이 있고 스스로 "정본(2 source 교차확인)" 이라
선언하는데, **그 파일을 로드하는 노드가 하나도 없다.** 소비자들은 값을 베껴 코드 기본값으로 박아
두고 주석에 "robot_geometry_2ws.yaml 실측값이 기본값" 이라고 적어 두었다. 그 결과:

| 위치 | 박혀 있는 기하 | 문제 |
| --- | --- | --- |
| `trnav_2ws_gazebo/scripts/wheel_odometry.py` | `w1_y = w2_y = −0.0014` | 정본은 `0.0` — 값이 갈린다 |
| `trnav_2ws_gazebo/scripts/wheel_cmd_bridge.py` | 같음 | 같음 |
| `translate_sim_odom` 코드 기본값 | `(±0.330, ±0.135)` **QD 대각값** | 2WS 기체와 무관한 값이 기본값이다 |
| `motor_control/config/tongyi_amr.yaml` | `module_y = −0.0014` | 정본과 갈린다 |

정본이 `−0.0014` 를 버리고 `0.0` 으로 확정한 이유도 그 파일에 적혀 있다 — 두 바퀴가 센터라인에
있는 inline 구조에서 y 잔차는 회전중심을 횡으로 밀어 제자리 스핀을 ±89.867° 로 만든다.

`translate_sim_odom` 의 코드 기본값이 QD 대각값인 것은 **잠재 위험**이다 — 파라미터 파일을 주지 않고
띄우면 2WS 플랜트가 QD 기하로 돌아 SIL(Software In the Loop) 이 실물과 다른 로봇을 검증하게 된다.
현재 이 노드를 띄우는 런치 19개는 **전부** `sim_params.yaml` 을 주므로 실사용 경로에서는 발동하지
않는다(2026-08-16 전수 확인). 즉 지금 당장의 오동작이 아니라, 런치를 하나 새로 쓸 때 열리는 문이다.

## Decision

1. **정본은 `trnav_2ws_core/config/robot_geometry_2ws.yaml` 하나다.** 새 파일을 만들지 않는다 —
   네 번째 사본을 만드는 것이 지금 문제의 원인이다. 이 파일은 이미 `/**:` 와일드카드라
   노드 이름과 무관하게 주입된다.
2. **코드에 기하 기본값을 두지 않는다.** 오도 노드는 기하 파라미터를 받지 못하면
   **기동을 실패시킨다.** 조용히 틀린 기하로 도는 것보다 뜨지 않는 편이 낫다.
   (기존 기본값은 "맞는 값처럼 보이지만 정본과 갈린" 상태였고, 그것이 이 ADR 의 원인이다.)
3. **런치가 정본을 주입한다.** `sim.launch.py`·`fleet.launch.py` 가 `robot_geometry_2ws.yaml` 을
   노드 파라미터로 얹는다. `translate_sim_odom` 을 띄우는 런치는 이미 전부 파라미터를 주므로
   런치 수정이 필요 없다.
4. **`tongyi_amr.yaml` 의 `module_y` 를 정본과 같은 `0.0` 으로 맞춘다.**
   ⚠ `module_x` 의 전·후 배정(node1 = Rear 가정)은 **미판정이므로 건드리지 않는다** — 이 ADR 은
   좌표값을 정본에 맞출 뿐 CAN 노드 매핑을 바꾸지 않는다.
5. **QD 스택은 손대지 않는다.** QD 는 LGIT 검증 후 재이식 예정이라 이 변경의 범위 밖이다.

## Consequences

- **이득**: 휠 구조가 바뀌면 YAML 한 곳만 고치면 된다. 값이 갈려 있던 세 곳이 하나로 수렴한다.
  QD 기하로 2WS 플랜트가 도는 경로가 사라진다.
- **비용**: 파라미터를 주지 않으면 노드가 뜨지 않는다 — 런치를 거치지 않고 `ros2 run` 으로 띄우던
  수동 절차는 파라미터 파일을 명시해야 한다. 이는 의도된 비용이다.
- **남는 위험**:
  - `translate_sim_odom/config/sim_params.yaml` 은 여전히 기하를 **자체 보유**하며 QD SIL 런치도
    같은 파일을 받는다(즉 QD SIL 이 2WS 기하로 돈다). 이 ADR 의 범위 밖이므로 부채로 등록한다.
  - `wheel_cmd_bridge.py` 도 같은 스키마의 거짓 기본값을 갖는다. 런치에서 정본을 함께 주입해
    실사용 경로는 정합되지만, 코드 기본값 제거는 오도 경로가 아니라 별도 건이다.

## Rollback

가역. `git revert` 로 되돌린다. 되돌리면 노드는 다시 코드 기본값으로 뜨고(정본과 갈린 값),
런치는 파라미터 주입 없이 동작하던 상태로 복귀한다. 영속 상태·스키마 변경 없음.
