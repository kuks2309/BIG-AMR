### 매뉴얼 근거 (1차 자료)

`References/Tongyi-Motor-Controller/manuals/IxLII-IxLs-IxH_Servo_Driver_Handbook_V7.0.txt:8948-8952`:

> **Home 35: The home point is the current position** — "When the parameter `SelfSofRst.uwRstMode`
> is set to 35, the driver **records the current motor position as the home position, sets the
> current angle to zero**, and reset the value of `SelfSofRst.uwRstMode` to 0. The secondary
> function can run multiple times, and **it is only effective when the motor is powered on**."

두 가지가 따라 나온다:

1. **method 35 는 각도를 0 으로 만든다** ⇒ 호밍 후 `0x6064 ≈ 0` 이 직진이다.
   따라서 **홈 상수가 코드에서 사라진다** — 남는 장비별 값은 "어느 절대 카운트로 가서 35 를
   걸 것인가"(`home_offset`) 하나뿐이다.
2. **전원 사이클마다 재호밍이 필요하다**("only effective when the motor is powered on").
   ⇒ 호밍 완료 전 조향 지령을 막는 게이트가 **필수**다(상류의 `home_comp` 와 같은 역할).

## Decision

**1. 조향 홈을 장비별 캘리브레이션 YAML 로 분리한다.**

새 파일 `src/Comm/CAN/can_relay/config/machine/<기체명>.yaml`. 스키마는 상류 이름을 계승하되
상류가 코드에 박아 둔 두 가지(조향 한계·호밍 방식)를 파라미터로 올린다.

**2. 호밍은 `homing_method` 파라미터로 고른다 — 방식이 장비마다 다르기 때문이다.**

| 값 | 절차 | 취소 | 전제 |
| --- | --- | --- | --- |
| `35` (기본) | can_relay 가 직접 지휘: 절대이동 → 도착확인 → `0x6098=35` | **전 구간 가능**(우리가 `0x607A` 를 쓰므로) | 절대 엔코더 재현성 |
| `firmware` | 판다 시퀀서 `0xea`/`0xeb`(method 1 리밋 + GOZERO) | `0xeb` 취소 프레임으로 가능 | 펌웨어 상수가 그 기체 값 |

`firmware` 경로는 2026-08-01 에 이미 구현·시험돼 있으므로 대안으로 존치한다(삭제하지 않는다).

> ❌ **정정 2026-08-03 15:40 — 위 표의 `firmware` 행 현재 상태** (method 35 기각 판정은 불변)
> - `firmware` 는 이제 **대안이 아니라 현행 경로**다(`homing_method: "firmware"`). 실측으로 **10/10 완주**,
>   회당 **35.0 s**(WAIT −리밋 탐색 31.7 s → RESTORE → GOZERO → DONE).
> - 「method 1 리밋」은 실기 `0x6098` 판독 **1**(Home 1)로 **확정**됐고, 리밋 스위치도 10회 모두
>   DI `0x01`→`0x09`(bit3 = −Limit) 전이로 **실재 확인**됐다.
> - 전제 열 「펌웨어 상수가 그 기체 값」은 **충족**된다 — 이 기체의 10회 정착 중앙값 7,882,021 / 7,859,065 가
>   상수 7882020 / 7859062 와 1~3 counts 일치. 단 그 상수는 **0° 가 아니라 「호밍 후 정착값」** 이며
>   조향 0° 대비 **+0.178° / +0.331°** 다 — 즉 **호밍은 조향을 0° 에 정확히 놓지 않는다**(설계 동작).
> 근거: `docs/homing/2026-08-03-can-relay-homing-assets.md` §0-1 · §0-2 · §0-3.
>
> ❌ **재정정 2026-08-03 17:00 (바로 위 블록 — method 35 기각 상태는 여기서도 불변)**
> - **「10/10 완주」는 유효.** 다만 2026-08-03 전체로는 **시도 13 / 성공 12 / 실패 1**(09:58 ERR_TIMEOUT
>   120.26 s)이므로 「12회 연속 성공」식 서술은 쓰지 말 것.
> - **회당 35.0 s → 평균 35.07 s · 중앙 35.05 s**(최소 34.99 · 최대 35.16, n=10).
>   **WAIT(−리밋 탐색) 체류는 31.7 s 가 아니라 31.30 s**(10회 평균, state4→state8;
>   31.7 은 RESTORE 진입 절대시각 t≈31.69).
> - **끝의 「(설계 동작)」은 과잉 확정** — 「**재현되는 정착 동작(상수 적정성은 별건, debt-016)**」으로 읽을 것.
>   「호밍은 조향을 0° 에 정확히 놓지 않는다」는 사실 서술 자체는 유효하다.
> 원자료: `Log/home_experiment_260803_153319_summary.json` ·
> `Log/home_experiment_260803_095815_summary.json` · `Log/homing_edge_260803_1{44602,52520}.json`.

**3. `target_pos` 계약을 바꾸지 않는다 — 절대 raw pulse 유지.**

2026-08-01 초안에서 "홈 기준 상대 pulse" 를 제안했으나 **철회한다.** 상류가 절대 raw 를 쓰고,
드라이버가 가공하지 않는다. 계약을 바꾸면 상류와 갈라지고 얻는 것이 없다.

**4. 미측정 전제를 코드가 검출하게 한다.**

D안의 전제 **"전원 재투입 후 절대 엔코더가 같은 값을 준다"** 는 아직 측정되지 않았다
(debt-007 상환계획 ②). 사용자가 그 상태로 진행을 선택했으므로, 전제가 틀릴 때 **조향이 엉뚱한
곳으로 가는 대신 멈추도록** 만든다:

- 호밍 시작 전 현재 `0x6064` 를 읽어 캘리브레이션의 `home_search_range` 밖이면 **거부**한다.
  엔코더가 재현되지 않으면 이 검사가 걸린다.
- 도착 판정은 상류와 같은 2조건(statusword bit10 + `|0x6064 − home_offset| < tol`).
- 호밍 완료(`homed`) 전에는 **모든 조향 지령을 거부**한다(매뉴얼상 전원 사이클마다 필요).

## Consequences

- (+) 장비 교체 시 **YAML 한 장**만 바꾸면 된다. 펌웨어 재빌드·재플래시가 불필요하다
  (`homing_method: 35` 인 한).
- (+) `safety.py` 의 `DEFAULT_STEER_HOME` 상수가 사라진다 — debt-016 이 상환된다.
- (+) 상류와 같은 구조·같은 파라미터 이름이라 대조·교체가 쉽다.
- (+) 상류가 코드에 박아 둔 조향 한계를 YAML 로 올려 상류보다 낫다.
- (−) **미측정 전제 위에 있다.** 절대 엔코더가 재현되지 않으면 `homing_method: 35` 는 못 쓴다.
  그때는 `firmware` 로 되돌린다(파라미터 한 줄).
- (−) 전원 사이클마다 재호밍이 필요하다(매뉴얼 명시). 기동 절차가 한 단계 늘어난다.
- (−) 캘리브레이션 값 자체는 여전히 사람이 측정해 넣어야 한다. 자동 산출이 아니다.

## Rollback

가역 변경이며 되돌림은 파라미터 한 줄 또는 파일 삭제로 끝난다:

```bash
# ① 호밍 방식만 되돌리기 (코드 변경 없음)
#    config/machine/<기체>.yaml 에서  homing_method: firmware
# ② 전면 되돌리기
git revert <이 ADR 의 구현 커밋>
rm -rf src/Comm/CAN/can_relay/config/machine
```

- 펌웨어를 쓰지 않는다(플래시 0건) → 판다 상태 변화 없음.
- 드라이브 파라미터를 영구 저장하지 않는다(`0x1010` Store 미사용). `0x6098=35` 는 매뉴얼상
  **전원 사이클에 휘발**되므로 되돌림에 물리 조작이 필요 없다.
- 상류 계약(`/motor/low_cmd` 의 `target_pos` 절대 raw)을 바꾸지 않으므로 상위 계층 무영향.

## 검증 게이트 (미통과)

1. **절대 엔코더 재현성 측정** — 잭업 상태에서 조향을 임의 자세에 두고 전원 재투입 후 `0x6064`
   재현 확인(debt-007 상환계획 ②). **이것이 통과해야 `homing_method: 35` 를 지면에서 쓸 수 있다.**
2. `home_offset` 실측 — 그 기체의 직진 자세에서 `0x6064` 를 읽어 YAML 에 기입.
3. 잭업에서 호밍 1회 완주 + `0x6098=35` 후 `0x6064 ≈ 0` 확인.
4. 기존 게이트(debt-017 구동축 브링업, debt-012 guard RTR)와 같은 시험에서 함께 확인.
