# ADR 2026-08-10 — `yaw_control` 에 조대(粗大) 헤딩 발산 탐지기 추가 (status −7)

- **Status**: Proposed — 2026-08-10 (**검증 전**. 최종 verdict 는 저자가 찍지 않는다 —
  `coding.md:88` never-self-approve)
- **Rollback**: 가역 — `git revert`. 영속 상태·스키마·펌웨어 변경 없음.
  `.action` 에 **주석 한 줄과 status 코드 하나**가 추가되나 기존 코드값 0/−1~−6 의 의미는 불변이라
  기존 호출자는 그대로 동작한다(새 코드를 모르는 호출자는 「알 수 없는 실패」로 취급).

## Context

2026-08-10 실기에서 `yaw_control` 이 **25° 틀어진 채 `status 0`(성공)** 을 반환했다.

```
조향 −14° · 2.0 m 주행    기구학 예측 회전 ≈ 20°
맵 측위(mcl2d)  +24.7°     ← 로봇은 실제로 그만큼 돌았다
IMU             +1.7°      ← 회전을 거의 못 읽었다 (ω ≈ 0.6 °/s, debt-054 구간)
결과            status 0 · 거리 2.001 m — 성공으로 보고
```

**시작 기준은 정상이었다.** `yaw_offset = start_yaw_map − start_yaw_imu`(`:184`)가 1회 계산되고,
역산하면 시작 시 보정 yaw +2.00° vs 맵 +2.094° 로 **0.09° 이내**였다.
문제는 그 뒤 IMU 가 회전을 놓쳤고, **아무도 그것을 알아채지 못했다**는 것이다.

`LocalizationMonitor` 는 pose **두절·점프**만 본다(`:305`). 헤딩 정합은 감시 대상이 아니다.

## Decision

### D1. 제어 소스는 **IMU 그대로 둔다** — 탐지기만 추가한다

현재 측위는 **heading 정밀도를 보정해 줄 만큼 정확하지 않다.** 미세 제어를 측위 heading 으로
닫으면 오히려 정밀도가 떨어진다. 「측위가 절대 기준을 1회 주고, 정밀한 IMU 가 추종한다」는
현 구조는 **의도된 선택이며 유지한다.**

```
잘못된 처방   측위 heading 으로 제어 루프를 닫는다        → 정밀도 하락
본 ADR        IMU 로 제어하되 측위와 크게 벌어지면 abort   → 25° 급 고장만 잡는다
```

### D2. 판정식과 임계

주행 루프에서 매 주기:

```
diverge = |normalizeAngleDeg(보정 yaw − 맵 yaw)|
diverge > heading_divergence_deg  가 heading_divergence_count cycle 연속  →  abort(−7)
```

**임계 5.0° · 연속 10 cycle**(50 Hz 기준 0.2 s)로 잡는다. 근거는 정상과 고장의 **100배 격차**다:

```
정상   시작 시 괴리 0.09°  ·  ω ≥ 2.8 °/s 에서 25° 회전에 0.25° (Tools/imu_rate_check 실측)
정지   맵 heading 잡음 ±0.05° (30 s)
고장   25°
```

그 사이 아무 값이나 오탐·미탐 없이 동작하므로 분포를 새로 측정하지 않는다.
연속 cycle 조건은 맵 측위의 순간 튐에 의한 오탐만 막는 용도다.

⚠ **이 탐지기는 정밀도에 관여하지 않는다.** 5° 는 제어 목표가 아니라 **고장 경계**다.

### D3. 전용 status 코드 **−7**

기존 코드(0/−1~−6)에 붙여 `−7 = heading_divergence` 를 신설한다. 기존 값의 의미는 바꾸지 않는다.
`-3`(타임아웃)이나 `-5`(loc_jump)에 얹지 않는 이유는 **원인이 다르고 대응도 다르기** 때문이다 —
측위는 멀쩡한데 **IMU 쪽이 어긋난** 상황이며, 재시도가 아니라 IMU 점검이 필요하다.

### D4. 파라미터는 yaml, 기본값은 켜짐

`heading_divergence_deg`(5.0) · `heading_divergence_count`(10) · `enable_heading_divergence_guard`(true).
끌 수 있게 두되 **기본은 켠다** — 조용한 실패보다 시끄러운 중단이 낫다.

## Consequences

**얻는 것** — 2026-08-10 급 고장이 **0.2 초 안에** 멈추고 전용 코드로 보고된다.
상위 로직이 `status 0` 을 신뢰해 잘못된 자세를 전제로 다음 동작을 하는 일이 없어진다.

**비용** — 주기마다 각도 뺄셈 1회(무시 가능). 맵 측위가 크게 흔들리는 환경에서는 오탐 가능
(연속 cycle 조건으로 완화하되 완전 배제는 아니다).

**⚠ 미해결로 남기는 것**
- `yaw_control_reverse` 에는 적용하지 않는다 — 그쪽은 **pose 토픽 자체가 죽어 있어**(`debt-050`)
  탐지기가 성립하지 않는다. 그 부채를 먼저 처리해야 한다.
- `turn`·`spin` 에도 같은 탐지기가 필요한지는 **별건**이다. 두 기동은 오늘까지 ω ≥ 2.8 °/s
  구간에서만 쓰였고 `debt-054` 위험 구간에 들어간 적이 없다.
- **IMU 가 왜 저속에서 못 읽는지(기전)는 여전히 미확정**이다(`debt-054`). 본 ADR 은 증상을
  조기에 드러낼 뿐 원인을 고치지 않는다.
