# ADR 2026-08-17 — 레거시 RobotPosEKF 이식: 휠 오도 + IMU 융합 노드 신설

## Status

Accepted (2026-08-17). 최종 verdict 는 외부 리뷰 몫(coding SOP §5 never-self-approve).

## Context

Seer 레거시의 측위 입력은 **휠 오도가 아니라 오도·IMU 융합본**이다. 원본 실측으로 확정했다
(배선 정본 `Tools/seer_re/docs/legacy_runtime_wiring.md` §A.1~A.27):

```
DSPChassis ─MotorInfos→ OdoCalculator ─Message_Odometer→ RobotPosEKF ─Message_Odometer→ MCLoc
DSPChassis ─IMU───────────────────────────────────────→ RobotPosEKF
```

`RobotPosEKF` 는 ROS `robot_pose_ekf` 이식본이며, 확정된 성질:

| 항목 | 값 |
| --- | --- |
| 상태 | 6-D (x, y, z, roll, pitch, yaw) |
| 예측 | `x⁺=x+v·cosθ` · `y⁺=y+v·sinθ` · `θ⁺=θ+ω` (z·roll·pitch 불변) |
| 야코비안 | `F=I`, `F(1,6)=−v·sinθ`, `F(2,6)=+v·cosθ` |
| 관측행렬 | `Hodom`(6×6): (1,1)(2,2)(6,6)=1 · `Himu`(3×6): (1,4)(2,5)(3,6)=1 |
| 시스템 잡음 | 대각 1e6 (σ=1000) |
| prior 공분산 | 대각 1e-6 (σ=0.001) |
| IMU 갱신 게이트 | 초기화 완료 **AND** `|ω_odom| > 1.0 deg/s` (하드코딩) |
| 첫 주기 | 센서별로 기준선만 세우고 융합하지 않음 |
| 내부 스케일 | 입력 x·y ÷100, 출력 ×100 (각도 무배율) |
| 구동 전제 | 오도·IMU 둘 다 수신해야 진행. **IMU 없으면 무발행** |

**우리 스택에는 이 층이 없다.** `mcl2d` 는 `/odom` 을 그대로 받고, 그 `/odom` 은 런치에 따라
`icp_odometry`(레이저) 또는 `motor_control`(휠)이다. IMU 드라이버(`iahrs_driver`)는 있으나
어디에도 융합되지 않는다. 레거시가 yaw 를 자이로로 잡던 층이 통째로 빠져 있다.

## Decision

**레거시와 같은 위치에 융합 노드를 신설한다.** 기존 노드를 고치지 않고 파이프에 한 칸을 끼운다.

```
휠 오도 (nav_msgs/Odometry) ─┐
                              ├→ odom_imu_ekf → 융합 오도 (nav_msgs/Odometry) → mcl2d
IMU (sensor_msgs/Imu) ───────┘
```

1. **코어는 ROS-무의존** (`odom_imu_ekf/ekf.hpp|cpp`) — 시계·미들웨어 없이 시험한다.
   `mcl2d_core` 와 같은 방침이다.
2. **원본 수치를 그대로 옮긴다** — 상태 차원, 예측식, 야코비안, `Hodom`/`Himu`,
   시스템 잡음 1e6, prior 1e-6, IMU 게이트 1.0 deg/s, 첫 주기 기준선 규칙.
3. **내부 ÷100/×100 스케일도 그대로 옮긴다.** 대칭이라 인터페이스에서는 보이지 않지만,
   **잡음 상수가 그 스케일 공간에서 정의돼 있으므로** 스케일만 빼면 실효 프로세스 잡음이
   100배 어긋난다. 상수와 스케일은 한 벌이다.
4. **관측 잡음만 의도적으로 이탈한다.** 원본은 `odom_covariance_`·`imu_covariance_` 를
   크기만 잡고 값을 넣지 않아 **초기화되지 않은 힙 메모리**가 매 주기 측정모델로 복사된다
   (§A.13·A.14·A.23). 이것은 재현 대상이 아니다 — **파라미터로 노출된 상수**를 쓰고,
   기본값은 원본 생성자가 측정모델에 넘긴 지역 행렬 값(오도 6×6 대각 1.0, IMU 3×3 대각 1.0)으로 둔다.
5. **IMU 필수 전제도 그대로 옮긴다** — 오도와 IMU 를 둘 다 받기 전에는 발행하지 않는다.
   IMU 수신 플래그는 원본과 같이 **한 번 서면 내려가지 않는 래치**다.
6. **미소비 요소는 이식하지 않는다** — `UseIMU`·`StartSkidDetection`(원본에서 읽는 곳 없음),
   `VelocityEstimatorIMU`(출력 소비 없음), rf2o 레이저 오도(배포 비활성), VO·GPS(멤버째 삭제).
7. **속도 필드 처리도 원본과 같게** — 융합은 자세만 바꾸고, `twist`·`child_frame_id` 등은
   수신 오도 메시지를 그대로 복사해 내보낸다(원본 `run()` 의 `CopyFrom` → `getFilterOdometer` 순서).

## Consequences

- **이득**: yaw 가 조향각 유도값과 자이로로 함께 잡힌다 — 레거시가 드리프트를 다루던 **0층**이 생긴다.
  `mcl2d` 는 손대지 않는다(입력 토픽만 바꿔 물리면 된다).
- **비용**: 노드 하나 추가. **IMU 가 없으면 융합 오도가 안 나온다** — 레거시와 같은 성질이지만
  우리 런치에서는 새로운 실패 모드다. 진단으로 드러내야 한다.
- **의도적 이탈 2건**(위 4·6)은 문서에 명시하고, 「원본과 100% 동일」이라고 주장하지 않는다.
  관측 잡음이 다르므로 **비트 일치 대조는 성립하지 않는다** — 검증은 수치 특성 시험으로 한다.
- **남는 위험**: 이 노드를 넣어도 `motor_control` 휠 오도의 조향 부호 2건(`debt-004`·`debt-007`)이
  미판정이라, 휠 오도를 소스로 쓰면 yaw 부호가 뒤집힐 수 있다. **그 실측이 선결**이다.
  IMU 융합은 그 오차를 줄이지만 부호 반전을 고쳐 주지는 않는다.

## Rollback

가역. 노드를 런치에서 빼고 `mcl2d` 입력을 원래 토픽으로 되돌리면 끝난다.
영속 상태·스키마 변경 없음.
