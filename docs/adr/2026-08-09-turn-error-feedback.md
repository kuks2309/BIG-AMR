# ADR 2026-08-09 — `turn` 계열에 오차 피드백 도입 (coarse 사다리꼴 → fine PD)

- **Status**: Proposed — 2026-08-09 (사용자 지시로 착수. **검증 전**이며 최종 verdict 는
  저자가 찍지 않는다 — `coding.md:88` never-self-approve)
- **지시**: 「turn 은 오차 피드백을 넣어야지. 시작은 사다리꼴 프로파일로 하고
  종료는 당연히 pd 제어를 해야지요」 (사용자, 2026-08-09)
- **Rollback**: 가역 — `git revert`. 영속 상태·스키마·펌웨어 변경 없음. 액션 인터페이스
  (`.action` 필드)도 불변이므로 상위 호출자 수정 불요. 파라미터 yaml 은 같은 커밋에 포함되며
  되돌리면 함께 돌아간다.

## Context

`turn`·`turn_reverse` 에는 **오차 피드백이 없다.**

```cpp
auto prof_out = profile.getSpeed(accumulated_angle);   // turn_action_server.cpp:204
double omega_dps = prof_out.speed;                     // ← 지령 생성 끝. 오차항 없음.
```

각속도 지령은 **누적각의 함수(사다리꼴 표 조회)** 일 뿐이고, 「목표 대비 얼마나 벗어났나」를
되먹이는 항이 어디에도 없다. IMU 는 지령 생성에 관여하지 않고 오직 `accumulated_angle`
(진행량)에만 들어간다. 닫혀 있는 것은 **「언제 멈출까」 하나뿐**이다.

그 `accumulated_angle` 은 **IMU 델타 누적**이며 **0 클램프**를 갖는다
(`:259-260 · 314-315 · 387-388`). 음의 델타가 누적을 0 아래로 끌면 잘라 버리므로 그 음수는
영구히 사라지고, 편향이 **한 방향으로만** 쌓일 수 있다. Phase 3.5 미세보정도 **같은 누적기**를
보므로 누적기 자신의 편향은 **원리적으로** 못 잡는다.

2026-08-09 실기 n = 6 (전수는 `docs/issues_and_fixes/issues_and_fixes.md` 2026-08-09):

```
과회전량 = |실측| − |지령|
10° 다리(n=4)  +0.38 · −0.19 · +0.01 · −0.35     |오차| ≤ 0.38°
90° 다리(n=2)  +0.53 · +0.66                      |오차| ≤ 0.66°
자기보고 vs 맵 절대 측위: 양쪽 다리 모두 자기보고가 작다(0.3~0.5°)
```

## Decision

**`spin` 이 이미 쓰는 하이브리드 구조를 `turn` 계열에 이식한다** — Stage 1 사다리꼴(coarse) →
남은 오차 ≤ `pid_band` → Stage 2 PD(fine). `spin` 의 이 구조는 실차 HIL 로 확정돼 있다
(2026-06-02, ±10~±180.1° 전 각도 |오차| ≤ 0.42°).

### D1. 각도 계상을 **절대 목표 yaw** 로 교체 — 델타 누적 폐기

```
start_yaw       Phase 0(차체 정지) 직후 N 샘플 원형 이동평균 atan2(Σsin, Σcos)
target_imu_yaw  start_yaw + sign · target_abs
e(cur)          normalizeAngle(target_imu_yaw − cur) [deg]   ← 부호 있는 전역 잔여 회전
progress        target_abs − |e|                              ← 사다리꼴 입력
```

`accumulated_angle` · `imu_deadband` · **0 클램프 3곳**이 전부 사라진다. 델타를 더하지 않으므로
드리프트·편향이 **원천 소거**된다. 이것이 `debt-048` 의 상환이며, `turn` 소스 주석 `:253-256` 이
이미 권고하고 「별건(구조 변경)」으로 미뤄 둔 바로 그 변경이다.

⚠ `start_yaw` 를 1회 샘플로 잡으면 그 순간의 IMU 잡음이 **기준 전체를 오프셋**한다.
`spin` 이 원형 이동평균을 쓰는 이유가 이것이므로 그대로 가져온다. `atan2` 원형평균이어야
±180° 부근에서 오평균(179°, −179° → 0°)이 나지 않는다.

### D2. Stage 1 (coarse) = 사다리꼴 유지, 인덱스만 교체

프로파일 자체는 그대로 두고 입력만 `accumulated_angle` → `progress` 로 바꾼다.
종료 조건: `|e| ≤ pid_band_deg` **또는** `profile DONE`.

### D3. Stage 2 (fine) = **PD** — `ki` 는 신설하지 않는다

```
ω_cmd = kp · e + kd · ė          (ė = (e − e_prev)/dt = −실측 yaw rate)
|ω_cmd| ≤ ω_max = max_linear_speed / turn_radius     하한 floor 없음
```

**`ki` 는 파라미터로도 만들지 않는다**(구현 중 상향 결정) — 사용자 상시 지시
(2026-08-09: 「ki 는 진동을 만들 수 있으므로 하지말고」). 당초 「`ki_turn: 0.0` 으로 두되 고정」을
계획했으나, **항상 0 이어야 하는 게인은 손잡이가 아니라 함정**이라 아예 신설하지 않았다 —
2026-08-09 `spin_params.yaml` 죽은 파라미터 제거와 같은 판단이다. 따라서 순수 **PD** 다.
`spin_params.yaml` 도 `ki_spin: 0.0` 이다. 적분항이 없으므로 **정상오차는 남을 수 있다**;
그 잔차를 규격으로 다루는 것이 `spin` 과 같은 방침이다.

하한 floor 를 fine 에 걸지 않는 이유도 `spin` 과 같다 — 목표 근처에서 `≥ min_speed` 를 강제하면
한계진동이 된다.

**정착 게이트**(`spin` 과 동일): `|e| ≤ fine_threshold` **AND** `|ė| ≤ settle_rate` 가
`settle_count` cycle 연속이면 조기 종료. `|e|` 만 보고 끝내면 **아직 돌고 있는데 도달로 판정**해
액션이 값을 읽은 뒤 차체가 더 움직인다 — 2026-08-09 `spin` 에서 실측한 바로 그 함정
(자기보고 0.22° vs 2초 뒤 실측 0.43°).

fine 타임아웃은 파라미터가 아니라 기동 규모에 비례해 계산한다: `max(2.0, 3.0 · target_abs / ω_max)`.

### D4. 원호(ICR) 보존 — fine 구간에도 조향을 움직이지 않는다

지령 변환을 **한 식으로 통일**한다:

```
vx = sign · ω_cmd · R          ωz = ω_cmd          (turn_reverse 는 vx 만 부호 반전)
```

`sign` 은 기동 전체에서 **불변**(ICR 이 어느 쪽인지)이고, PD 가 초과를 보정하려고 `ω_cmd` 의
부호를 뒤집으면 `vx` 도 함께 뒤집혀 **같은 조향각 그대로 원호를 되짚는다**. `v/ω = R` 이
보존되므로 IK 가 내는 조향각이 변하지 않는다 — 조향은 Phase 0 이후 Phase 4 까지 정지 상태다.

이 식은 기존 두 경로를 **모두 재현**한다(검산):

```
주 루프    ω_cmd = sign·|ω_prof|  →  vx = sign·sign·|ω|·R = |ω|·R        ✔ 현행과 동일
현 미세보정 ω_cmd = travel_dir·sign·|ω| →  vx = travel_dir·|ω|·R          ✔ 현행과 동일
```

⚠ 조향각을 fine 에서 다시 세우는 것은 **금지**다 — 종전에 `computeSpin` 으로 ±90° 스핀 자세로
갈아탔다가 조향이 173° 움직여 `can_relay` 클램프 상한을 밀어올린 전례가 있다
(`turn_action_server.cpp:326-330` 주석).

### D5. `turn` 과 `turn_reverse` 에 **동시 적용**

`vx` 부호만 다르고 나머지는 같다. ADR `2026-08-09-turn-reverse.md` 가 이 중복 비용을 명시적으로
수용했으므로 여기서 구조를 바꾸지 않고 **양쪽을 함께 고친다**.

### D6. 파라미터 — 죽은 손잡이는 남기지 않는다

```
신설  pid_band_deg · kp_turn · kd_turn · settle_rate_dps · settle_count · start_yaw_avg_samples
삭제  fine_correction_speed_dps · fine_correction_timeout_sec · settling_delay_ms
      imu_deadband_deg            ← 델타 누적이 없어져 쓸 곳이 없다
유지  fine_correction_threshold_deg (정착 게이트 tol 로 재사용) · min_speed_dps(coarse 전용)
```

**삭제한 이름은 주석으로 남기지 않는다.** 설명만 달아 두면 `ros2 param set` 이 성공을 반환하면서
거동은 안 바뀌는 함정이 된다 — 2026-08-09 `spin_params.yaml` 에서 실측하고 사용자 지시로
손잡이 자체를 없앤 사례와 같다(「엉터리 주석으로 인한 피해」).

## 초기 게인 — 인계 연속성 기준

`spin` 의 게인(`kp 1.7 · kd 0.1 · pid_band 30°`)을 **그대로 쓰지 않는다.** `spin` 은 제자리
회전이라 병진 관성이 없고, `turn` 은 `v = ω·R` 로 **차체가 진행**하므로 플랜트가 다르다.

인계 지점에서 지령이 튀지 않도록 `kp · pid_band ≈ ω_max` 가 되게 잡는다:

```
R = 1.0 m · max_linear_speed 0.05 m/s  ⇒  ω_max = 2.86 dps
pid_band_deg 5.0 ,  kp_turn 0.6        ⇒  kp·band = 3.0 dps ≈ ω_max      (연속)
kd_turn 0.1 (spin 과 동일 출발점) — ki 항 없음(순수 PD)
```

⚠ **이 값들은 미검증 출발점이다.** SIL 로 조정하고, 실기 재측정 전까지 규격을 주장하지 않는다.

## Consequences

**얻는 것** — 오차 피드백이 생겨 프로파일·플랜트 오차를 종료 전에 되먹여 줄인다.
델타 누적기가 사라져 `debt-048` 이 닫히고, 자기보고와 절대 측위의 괴리도 같은 원인이라면 함께 준다.

**비용** — `turn` 계열 두 파일을 동시에 고쳐야 하고, 게인이 **재튜닝 대상**이다.
적분항이 없으므로 정상오차가 남을 수 있으나, SIL 상 이 구간의 잔여는 허용오차 설정이 지배한다(아래 검증 결과).

**⚠ 미해결로 남기는 것**
- **`turn` 계열 허용 규격은 여전히 미정**이다. 본 변경 후 재측정하고 나서 정한다 —
  지금 정하면 편향을 규격으로 승인하는 셈이 된다.
- **cross-track(경로) 피드백은 여전히 없다.** 본 ADR 은 **헤딩만** 닫는다. 반경 오차는
  개루프로 남으며, 2026-08-09 실측 반경 추정 0.998~1.017 m 가 그 상태의 자료다.
- 자기보고와 절대 측위의 괴리(0.3~0.5°)가 **정말 누적기 탓인지는 미확정**(n = 2 의 방향 일치).
  본 변경으로 사라지지 않으면 원인이 다른 데 있다는 뜻이므로 **재측정이 그 자체로 판별시험**이다.

## 검증 결과 — 1·2 수행 (2026-08-09)

**1 빌드** — `colcon build --packages-select trnav_2ws_action_server` 통과(4 min 4 s).
stderr 는 `mpc_reverse` 의 기존 printf 포맷 경고로 본 변경과 무관.

**2 SIL** — 동특성 켠 상태(`drive_accel/decel 0.0833 · steer_rate 57.1`), `imu_yaw_noise 0.0`.

```
액션            목표    액션보고    IMU 지상진값   실제오차   측정오차(보고−진값)   소요
turn            10°     9.737°      9.738°        −0.262°    −0.001°              9.65 s
turn            90°    89.737°     89.738°        −0.262°    −0.001°             38.18 s
turn_reverse    10°     9.737°      9.738°        −0.262°    −0.001°              9.65 s
turn_reverse    90°    89.734°     89.736°        −0.264°    −0.001°             38.15 s
```

- **측정오차가 −0.001° 로 사라졌다.** 실기에서 관측한 「자기보고가 절대 측위보다 작다」(0.3~0.5°)의
  SIL 대응 증상이 없어졌다 — 자기보고와 지상진값이 이제 **같은 절대 기준**에서 나오기 때문이다.
- **오차가 각도에 무관해졌다** — 10° 와 90° 가 같은 −0.262°. 종전 실기에서는 90°(0.53~0.66°)가
  10°(0.01~0.38°)보다 컸다. 오차가 기동 규모에 비례하지 않는 것이 종단 제어의 서명이다.
- **전진·후진이 소수점까지 일치**한다(−0.262 / −0.264) — 거울 대칭이 유지된다.

**잔여 −0.26° 의 정체 = 허용오차 그 자체** (추가 실험으로 분리):

```
fine_correction_threshold_deg 0.3  →  실제오차 −0.264°   소요 38.15 s
fine_correction_threshold_deg 0.05 →  실제오차 −0.041°   소요 41.38 s   (오차 6배↓, 시간 8%↑)
```

PD 는 여유가 있고, 잔여는 **「이 정도면 도달로 친다」는 설정값**이 정한다. `ki = 0` 이라
정상오차가 남는다는 당초 서술은 **이 구간에서는 지배적이지 않다**.

⚠ 다만 **SIL 은 IMU 잡음 0** 이다. 실기에서 0.05° 임계는 정착 게이트를 만족 못 해 타임아웃을
태울 수 있다. **소스 기본값은 0.3 으로 유지**하고, 조이는 판단은 실기 재측정 후로 미룬다.

**3 회귀 · 4 실기 — 미수행.** `turn_angle_accounting_check.py` 는 델타 누적 계상을 검사하는
도구인데 그 계상이 사라졌으므로 **검사기 자체를 갱신해야** 한다(현 상태로는 무의미).
실기는 사용자 승인·공간 확보 후.

⚠ 최종 verdict 는 저자가 찍지 않는다(`coding.md:88`).
