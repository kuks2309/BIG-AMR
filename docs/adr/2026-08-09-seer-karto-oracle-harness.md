# ADR 2026-08-09 — 원본 `libSlaMapping.so` 를 오라클로 직접 구동해 이식본과 대조한다

- Status: **Accepted (완료 — M1~M4 전부 실행, 대조 결과 반영)**.
  실측: 스캔 채택 213/213 일치 · 점군 81,948 완전 일치 · 포즈 위치차 max 0.026 m / mean 0.0084 m ·
  방위차 max 0.0073 rad / mean 0.0019 rad. **대조가 정적 분석이 못 잡은 이식본 결함 4건을 잡아냈다.**
- Date: 2026-08-09
- 관련: `docs/code_review/seer-slam-mapping/2026-08-08.md` (역어셈블 대조 §2차),
  debt-053(실 로그 재생 회귀) · debt-057(RSSI 관통 배선 격차) · debt-059(`vID` 미해독)

## Context

`src/Navigation/slam_karto_core` 는 Seer 지도생성(`libSlaMapping.so`)을 Open Karto + g2o 채용으로
이식한 것이다. 2026-08-08 역어셈블 대조로 파라미터·솔버 구성까지 맞췄으나, **가장 중요한 명제 하나가
검증되지 않은 채 남아 있다 — "우리 구현이 원본과 같은 지도를 만드는가".**

지금까지의 검증은 전부 **합성 궤적**이다. 그 한계가 실측으로 드러났다:

- 돌연변이 검사에서 4건이 **합성 데이터로 도달 불가**로 판정됐다. 대표적으로
  `LoopMatchMinimumResponseCoarse` 를 Seer 값 0.35 에서 상류 0.8 로 되돌려도 **솔버 계측이 완전 동일**했다 —
  합성 스캔은 벽까지 정확히 레이캐스트한 값이라 상관 응답이 사실상 1.0 이라 게이트가 걸리지 않는다.
- 즉 **★ Seer 튜닝 파라미터의 실제 효과가 회귀로 고정돼 있지 않다**(debt-053).

원본 실 로그는 회수돼 있다(`References/seer/slam_mapping/rawmaps/*.rawmap` 26개, md5 로 원본과 동일 확인).
그러나 **입력→출력 짝이 없다** — 26개 rawmap 은 전부 짧은 국소 주행(최장 153초·최대 6.6×10.2 m)인데
회수한 `.smap` 15개는 33×22 m ~ 10만 점의 설비 전체 지도다. 어느 rawmap 도 어느 smap 의 입력이 아니다.
따라서 "원본 산출물과 대조"라는 경로는 이 자산으로 닫혀 있다.

남은 길은 **원본 코드를 직접 돌려 산출물을 만들어 내는 것**이다. 실현성을 실측했다:

| 관문 | 결과 | 근거 |
| --- | --- | --- |
| 이 PC 에서 실행 | **불가** | 이 PC `aarch64`, `.so` `x86-64` |
| qemu-user 우회 | **비권장** | 설치는 가능하나(`qemu-user-static 1:6.2`), 목적이 비트 대조인데 에뮬레이터 부동소수가 하드웨어와 미세하게 다를 수 있어 대조 자체가 오염된다 |
| amap-server 에서 실행 | **가능** | `uname -m` → `x86_64` |
| rbk 프레임워크 필요 여부 | **불필요** | `dlopen(RTLD_NOW\|RTLD_LOCAL)` 성공, `karto::Mapper` 생성자 호출 후 vptr 확인 |
| 심볼 접근 | **가능** | `karto::` 심볼 **545개가 `.dynsym`** 에 공개(전체 symtab 547) → `dlsym` 직접 호출 |
| 라이브러리 | **전부 있음** | DT_NEEDED 63건 중 벤더 57건이 하드의 `3rdlib`(770)·`lib`(32) 에, 나머지 6건은 OS 제공 |
| ABI | **호환** | 원본 GCC 7.5 / amap-server GCC 11.4 — 둘 다 `__cxx11` new ABI |
| 클래스 레이아웃 | **확보** | `debug_info` 생존. `Mapper` 440 B · `LocalizedRangeScan` 1088 B · `LaserRangeFinder` 160 B · `Dataset` 88 B |

## Decision

**원본 `.so` 를 amap-server 에서 `dlopen`+`dlsym` 으로 직접 구동하는 오라클 하니스를 만들고,
같은 실 로그를 우리 이식본에도 먹여 출력을 대조한다.**

1. **플러그인 프레임워크는 재현하지 않는다.** `plugin_connect`→`Host::add`→`Provider::create` 경로를
   따라가지 않고 `karto::` 심볼을 직접 부른다. 실증된 경로이며, rbk 서비스 의존을 피할 수 있다.
2. **객체는 불투명 버퍼로 다룬다.** DWARF 가 준 크기로 할당하고 원본 생성자를 `dlsym` 해 호출한다.
   상류 open_karto 헤더로 `new` 하지 않는다 — Seer 가 멤버를 추가해 `sizeof` 가 다르다.
3. **백엔드도 원본 것을 쓴다.** `G2OSolver` 가 같은 `.so` 안에 있으므로 `Mapper::SetScanSolver` 로 연결한다.
4. **출력 규격을 양쪽이 공유한다.** 스캔별 `{added, unique_id, odom, corrected}` JSONL + 점군 별도 파일 +
   `points_sha256`. 부동소수는 `%.17g` 무손실 — 반올림하면 대조가 무의미해진다.
5. **양쪽이 적용 파라미터 전량을 함께 남긴다**(`oracle_params.json` / `ours_params.json`).
   출력이 다를 때 **설정 차이인지 알고리즘 차이인지**를 먼저 가리기 위해서다.
6. **기준 입력을 고정한다** — `robokit_2023-08-10_05-41-41.rawmap`(빔 521개 균일 단일 스윕,
   스캔 213개, 실이동 7.6 m). 1041빔 파일은 앞 521빔만 균일하고 뒤 520빔은 비균일이라 1차 대상에서 제외한다.
7. **관문마다 되읽어 검증하며 올라간다** (M1 객체 생성 → M2 스캔 1개 `Process` → M3 전량 재생 → M4 대조).
   타입 재구성이 틀리면 크래시가 아니라 **조용히 잘못된 값**이 나오므로, 넣은 값을 되읽어 확인한 것만 진행 근거로 삼는다.

## Consequences

- (+) **"원본과 같은 지도를 만드는가"에 답할 수 있는 유일한 경로**가 열린다. 성공하면
  debt-053·052·054 가 한 번에 닫힌다.
- (+) 지금까지의 정적 분석(`[존재]`)을 **실행 관측(`[동작]`)** 으로 올릴 수 있다. M2 만 달성해도 그렇다.
- (+) 향후 파라미터·알고리즘 변경마다 **원본 대비 회귀**를 돌릴 수 있다 — 합성 시험이 못 잡는 것을 잡는다.
- (−) **오라클이 amap-server 에 묶인다.** 이 PC 에서는 못 돌리므로 CI 후보가 아니고, 그 장비가 없으면 재현 불가다.
  → 완화: 오라클 **출력물**(JSONL)을 저장소에 보관하면 이 PC 에서 대조는 가능하다. 오라클 재생성만 원격이 필요하다.
- (−) 하니스가 원본 헤더 없이 타입을 다루므로 **오류가 조용히 잘못된 값으로 나타날 수 있다.**
  → 완화: Decision 7의 관문별 되읽기 검증. 검증 못 한 단계는 "미검증"으로 남기고 진행 근거로 쓰지 않는다.
- (−) 원본 `Compute()` 는 매 루프클로저마다 CWD 에 `before/after_optimization.g2o` 를 **무조건 덤프**한다
  (`0xeba78`·`0xebc39`, 조건분기 0건). 오라클 실행 시 디스크가 찬다 → 작업 디렉터리를 `/tmp/oracle/` 로 두고 정리한다.
- (−) 라이선스: 원본 `.so` 는 Seer 독점물이다. **분석·상호운용 목적의 사내 사용에 한정**하며,
  바이너리도 그 산출물도 저장소에 커밋하지 않는다(`References/` 는 `.gitignore:12` 로 미추적).

## 결과 (2026-08-09 추가)

26개 rawmap 전량의 오라클 출력을 생성했고, 기준 파일로 대조를 완료했다.

**대조가 잡아낸 이식본 결함 4건** — 전부 반영:
`SetCorrectedPose(odom − mPose0)` 누락(위치차 mean 2.65 → 0.108 m) ·
per-beam 각도 미사용(위치차 max 1.83 → 0.026 m, 동봉 Karto 패치로 해소) ·
거리 정규화가 무반사를 유효 히트로 둔갑(점군 101,074 → 81,948) · `min_range` 0.05 → 0.001.

**부수 성과**: 이 대조가 2차 역어셈블에서 내린 판정 하나(`per-beam 각도 미사용`)를 반증했다 —
상류 원문을 보고 Seer 개조본을 판정한 오류였다. **정적 분석만으로는 상류와 포크를 계속 혼동하게 되는데,
오라클은 그것을 데이터로 가른다.** 이것이 이 하니스의 가장 큰 값어치다.

**한계 그대로**: 오라클은 `Mapper` 계층까지다. `KartoSLAM::SaveMap`/`OccupancyGrid` 는 구동하지 않았으므로
"원본이 실제로 저장한 `.smap` 과 같은가"는 여전히 **미검증**이다(debt-052).

## Rollback

**N/A (가역).** 하니스는 원격 `/tmp/oracle/` 와 저장소의 독립 도구 디렉터리에만 존재하며,
`slam_karto_core`·`slam_karto_ros2` 의 동작에 관여하지 않는다. 폐기 시 해당 디렉터리와
`References/seer/slam_mapping/{oracle,ours}/` 산출물을 지우면 원상복구된다.
원본 하드는 **읽기 전용**으로만 접근하므로 되돌릴 변경 자체가 없다(작업물은 전부 `/tmp`).

## Dependencies

- **신규 외부 패키지 없음.** 하니스는 `libdl` + 표준 C++ 만 쓴다. 원본 `.so` 와 그 의존 라이브러리는
  분석 대상 자산이며 배포물에 포함하지 않는다.
- 환경: amap-server(x86_64, GCC 11.4), 원본 하드 마운트 `/media/amap/6ab6980d-…`(읽기 전용).
