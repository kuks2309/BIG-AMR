# 2026-08-03 15:40 (KST) — 팬아웃 기준선을 원자료로 검증하지 않고 14명에게 배포

## 무엇을 했는가

호밍 10회 연속 실측(10/10 성공)을 마친 뒤, 「확정 사실」 기준선을 만들어 **에이전트 14명에게
배포해 42개 문서를 일괄 정정**시켰다. 1차 측정은 원자료로 확인했으나, 거기서 **파생한 집계**는
재계산하지 않고 기억과 추론으로 썼다. 그중 셋이 틀렸다.

| 배포한 기준선 | 실제 (원자료 재계산) | 파급 |
|---|---|---|
| 「09:58 이후 **13회 연속 성공**」 | **12회** — 15:33 실행의 `baseline` 은 호밍이 아니라 **레지스터 스냅샷**(`orin_home_experiment.py:390`)인데 성공 1회로 셌다 | **70곳** |
| 「`0x6064`=0 은 **1회 관측·재현 안 됨**」 | **재현된다** — `0x6041` bit15=1 인 채로 0 이 나온 캡처 **6개** | 6곳 + debt-036 **우선순위 하향의 근거** |
| 「**물리 직진 앵커 부재** — 非-Seer 계측 필요」 | **거짓.** 앵커는 실재한다 — Seer 1005/1040 은 EasyDRIVE `steerOffset` 으로 **교정된** 조향각이고 사용자가 바퀴 직진 상태에서 Seer 0° 를 **육안 확인**했다 | **27개 파일** |

부수 사고 2건도 같은 세션에서 냈다:
- §15·§16 에 「호밍 실패 원인 **확정**」을 쓴 뒤 §17 로 뒤집었다(대조군 없이 2변수 동시 변경).
- 일괄 정정 스크립트가 `claude-mistake/*.md` **6개의 YAML frontmatter 앞**에 블록을 삽입해
  frontmatter 를 무효화했다. 자체 검사로 발견해 복구했다.

## 무엇이 잘못이었나

- `docs/claude_guideline/mistake/mistake.md` §카테고리 정의 **`verify-skip`** —
  「검증 없이 완료·성공 선언. 빌드·테스트·**관찰 가능 지표** 확인 누락」.
  원자료가 `Log/` 에 있는데 **세지 않고 서술**했다.
- `docs/claude_guideline/reverse_engineering/principle.md` §6 —
  「`[동작]` 주장은 배포자산 대조 전 "확정" 금지」. §15·§16 이 이를 어겼다.
- `docs/claude_guideline/coding/coding.md` §5(검증, never-self-approve) —
  기준선을 자기 검토만으로 14명에게 배포했다.
- **앵커 건은 범위 초과 일반화**다. 「(a) 역산식이 항등식이라 육안 확인이 **counts 값 결정**에
  기여하지 않는다」는 참인데, 거기서 「(b) **물리 직진이 미확인**이다」로 넘어갔다 — **(b) 는 거짓이다.**
  (a) 와 (b) 는 다른 질문이고, (b) 는 이미 사용자 육안 확인으로 성립해 있었다.

  가설로 대신하고 있었다는 지적. 실제로 그 10회가 문제를 종결시켰다.

## 원인 분석

규칙은 설치·주입돼 있었고 알고 있었다. 강제력 쪽에 구멍이 있었다.

1. **팬아웃이 오류를 증폭한다는 특성을 계산에 넣지 않았다.** 혼자 쓰면 틀린 문장이 1곳이지만,
   14명에게 기준선으로 주면 **42개 문서에 사실로 박힌다.** 배포 전 검증 강도는 파급 규모에
   비례해야 하는데, 1인 작업과 같은 강도로 검증했다.
2. **「확정」 라벨이 검증 강도를 구분하지 않는다.** 원자료로 센 「10/10」과 기억으로 쓴
   「13회 연속」이 같은 표에 같은 굵기로 들어갔다. 읽는 쪽(에이전트)은 구분할 수단이 없었다.
3. **부정 판정의 범위를 좁게 유지하지 못했다.** 「A 는 B 의 근거가 못 된다」를 「B 는 미확인이다」로
   확대했다. `2026-07-28-012`(「검증했는데 **대상**이 틀린 것」)의 변형 — 이번엔 **무효화의 대상**이 틀렸다.
4. 적대적 검증을 붙이자 즉시 잡혔다. 그러나 그 라운드는 **사용자가 「오류가 있으면 절대 안됨」이라
   말한 뒤에야** 돌았다 — `2026-07-29-003` 이 이미 지적한 「반대심문의 기동 조건이 사용자 지시」의 재발.

## 재발 방지

**강제 메커니즘 신설: `Tools/docking_field_kit/verify_homing_claims.py`**

`Log/` 원자료를 재계산해 **문서의 수치와 대조**하고, 어긋나면 `exit 1` 한다. 사람이 세지 않는다.

| 재계산 항목 | 이번에 잡았을 오류 |
|---|---|
| 회차 집계 — `transitions`(summary)·`fsm_trace`(edge) 양쪽 키 인식, `baseline` 제외 | 「13회」 |
| 최장 연속 성공 | 「13회」 |
| 소요 평균·중앙·범위 / WAIT(state 4) **체류**(절대시각과 분리) | 「35.0 s」·「WAIT 31.7 s」 |
| 정착값 중앙·**모/표본 σ 병기** | 「σ≈3」 기준 미표기 |
| `0x6064`=0 을 **직전 `0x6041` bit15 로 층화** | 「1회 관측」이 **거짓**임, 그리고 **호밍 중(정상)과 bit15=1(비정상)의 혼동** |

`--docs` 는 저장소 전 `*.md` 를 훑어 ① 과대주장(`N회 연속 성공` > 실제) ② 「1회 관측」 잔존
③ **「물리 직진 앵커 부재」 오주장**을 잡는다. 원문 보존 관례를 알아 **인접 정정이 있으면 통과**시킨다.

**적용 규칙: 팬아웃 정정 캠페인의 기준선은 이 도구의 출력으로 만든다.** 기억으로 쓰지 않는다.
