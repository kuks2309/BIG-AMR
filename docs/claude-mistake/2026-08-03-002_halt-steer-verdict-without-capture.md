# 2026-08-03 22:44 (KST) — 실측 캡처를 안 보고 「우리가 만든 우회 기법」이라 판정했다

## 무엇을 했는가

사용자가 「`halt_steer` 는 어디서 만든 명령인지?」라고 물었다. 나는 세 가지를 조사했다:

1. `docs/` 전수 grep → `halt_steer` 언급이 **오늘 내가 쓴 3개 문서뿐**임을 확인
2. `git ls-files src/Comm/CAN/can_relay` → **0건**(미추적)이라 도입 이력 추적 불가임을 확인
3. 벤더 매뉴얼(`IxLII-IxLs-IxH_Servo_Driver_Handbook_V7.0.txt`) 대조 → PP 모드 「이동 중 목표
   변경 가능」(:9049-9050)과 controlword **Bit4/Bit5/Bit8**(:7480-7484) 확인

그리고 `docs/debt/registry.md` 에 **debt-041** 을 등록하며 이렇게 적었다 —
「이름은 `halt_steer` 인데 벤더가 정의한 Halt(bit8)를 쓰지 않는다 — **「목표를 현재 위치로 즉시
적용」이라는 우회 기법**이고, 그 선택의 근거가 **어디에도 기록돼 있지 않다**」.
사용자에게도 「기법의 근거는 절반은 있고 절반은 없다」고 보고했다.

## 무엇이 잘못이었나

**저장소에 있는 실측 캡처를 한 번도 열지 않았다.** `Log/homing_capture_220350.jsonl` 은 실제
마스터(Seer)가 180 초간 낸 **253,510 프레임**이고, 이 저장소에서 「인코더 28종이 실측 캡처와
바이트 동일」(2026-07-29 리뷰) 같은 판정의 근거로 **이미 상시 쓰이던 자산**이다.

사용자가 「can log 에 이 명령이 있는지?」라고 물어서야 열어 봤고, 결과는 내 판정과 반대였다:

| 관측 | 값 |
| --- | --- |
| 마스터의 `0x607A` + `0x6040=0x3F` 송신 | **12,928 회** |
| 그중 「목표 ≈ 그 시점 실측」(\|Δ\| ≤ 200 c) | **12,396 회 (95.9 %)** |
| 마스터의 Halt(bit8) 송신 | **0 회** |

즉 `halt_steer` 가 쓰는 객체·컨트롤워드 조합은 **마스터가 상시 쓰는 바로 그것**이고,
「Halt 를 안 쓴다」는 것도 **마스터와 동일한 선택**이다. 「우회 기법」이라는 서술은 틀렸다.

⚠ 다만 **한 부분은 여전히 미검증이며, 그건 정정이 아니라 유지된다** — 같은 캡처에서
**「이동 중 목표 변경」은 0 건**이다(목표가 현재에서 1000 c 이상 떨어진 송신 4종 모두 직전
0.5 s 위치 변동 0 c = 정지 상태). 따라서 「움직이는 축을 이 방법으로 세운다」는 `halt_steer`
docstring 의 주장은 **캡처로 뒷받침되지 않는다.** 내 잘못은 「근거 없음」이 아니라
**「근거의 범위를 캡처를 안 보고 정했다」**는 것이다.

## 사용자 지적

> 「debt 인지 mistake인지 정확하게 구분이 안되는데. **can log에 이 명령이 있는지?**」

한 문장으로 판정의 근거 부족을 짚었다. 앞선 지적도 같은 성격이었다 —
「**오늘 오후에 확정한 실험 값도 참조할 것 제발**」(22:33). 두 번 다 **저장소에 이미 있는
원자료를 안 봤다**는 같은 지적이었고, 두 번째에서야 캡처를 열었다.

## 원인 분석

`context-missing` — 조사 범위를 **문서와 매뉴얼**로 한정했다.

「이 명령의 근거가 있는가」라는 질문에 대해 나는 근거의 후보를 ① 저장소 문서 ② 벤더 매뉴얼
두 곳으로 전제했고, ③ **실측 캡처**를 후보에 넣지 않았다. 이 저장소에서 캡처는 보조 자료가
아니라 **1차 판정 자산**인데도 그랬다.

더 나쁜 것은 **부정형 단정을 먼저 문서에 박았다**는 점이다. grep 결과(문서에 없음)는 사실이었지만,
그것을 「근거가 어디에도 기록돼 있지 않다」로 확대했다. `docs/` 에 없다는 것과 근거가 없다는 것은
다른 명제인데 후자로 적었다 — `docs/claude-mistake/INDEX.md` §메타 패턴의
「**부정 판정의 범위를 넘겨 일반화**」(2026-08-03-001)와 같은 형태다. 하루 사이 같은 형태를 반복했다.

또한 registry 는 **다른 세션이 그대로 인용하는 자산**이다. 팬아웃 위험(2026-08-03-001)을 하루 전에
겪고도 검증 강도를 올리지 않고 등록했다.

## 재발 방지

**「마스터가 실제로 쓰는 명령인가」를 기억이 아니라 원자료로 답하는 도구를 만들었다** —
`Tools/docking_field_kit/master_command_census.py`(읽기 전용, 장치 미접속).
캡처를 받아 ① 마스터가 쓰기를 보내는 객체 ② controlword 값 분포와 **Halt(bit8) 사용 여부**
③ `0x607A` 가 그 시점 실측과 같은 비율(= 「현 위치 유지」 패턴) ④ **이동 중 목표 변경 건수**를 낸다.
출력 말미에 판정 사용법을 함께 찍어, ④가 0 이면 「이동 중 정지」 주장을 **하지 않도록** 안내한다.

```
$ python3 Tools/docking_field_kit/master_command_census.py Log/homing_capture_220350.jsonl --nodes 3 4
  → Halt(bit8) 포함 송신 **0회**
  |목표 − 실측| ≤ 200c : **12,396 / 12,928회** (95.9 %)
  → **이동 중 목표 변경 0건**
```

함께 한 것:

- **debt-041 전면 정정** — 「우회 기법·근거 없음」을 철회하고, 실측으로 뒷받침되는 부분과
  여전히 미검증인 부분(이동 중 정지 거동)을 분리해 다시 적었다.
- **메모리에 값으로 상주** — `biguamr-steer-hold-command.md`. 「조사하라」는 지시가 아니라
  **조사 결과**(마스터가 쓰는 조합·Halt 0회·이동 중 변경 0건)를 박았다.
  2026-07-31-004 의 교훈(「주입만으로는 막히지 않는다 → 결과를 값으로 상주시킨다」)을 따른 것이다.

**적용 범위 주의**: 이 도구는 「마스터가 그 명령을 쓰는가」에만 답한다. 「그 명령이 안전한가」·
「이동 중에도 성립하는가」는 답하지 않는다 — 그건 실기 측정 몫이며 debt-041 상환계획 ③ 이 소유한다.
