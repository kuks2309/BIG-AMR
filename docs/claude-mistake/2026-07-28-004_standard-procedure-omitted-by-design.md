# 2026-07-27 23:00 (KST) — 표준 동작을 근거 없이 생략한 설계 3연속

## 무엇을 했는가

판다 펌웨어에 조향 호밍 시퀀서를 설계하면서 세 번 연속으로 업계 표준 동작을 뺀 설계를 먼저 제시했다.

1. **리밋 백오프 생략** — 호밍 완료(`0x6041` bit15 0→1) 후 축을 리밋 스위치에 얹은 채 `DONE` 을
   내는 시퀀서를 만들고, 주석에 "안전상 이동하지 않는다" 고 정당화했다.
2. **조향 0° 복귀 생략** — 호밍을 "원점 도달" 로 정의하고 종료했다.
3. **E-STOP 축소 제안** — GUI 의 E-STOP 버튼을 `즉시 정지 (소프트)` 로 개명하고 대형 적색 스타일을
   낮추자고 제안했다.

## 무엇이 잘못이었나

- ①·②는 참조 구현이 눈앞에 있었는데 적용하지 않았다. 같은 세션에서 이미 읽은
  `github.com/kuks2309/TR_Nav_ros2_ws` `can_open.hpp` 는 리밋 도달 후 `home_offset` 으로 이동해
  거기서 끝낸다(`home_count_` 1→2→3). Seer 실측(`Log/homing_capture_220350.jsonl` t=49.14)도
  `0x607A = 7,882,020 / 7,859,062` 로 조향 0° 복귀를 수행한다.
- ①의 실해: 리밋에 얹힌 축은 그 방향 지령이 막힌다. Handbook 인쇄쪽 122 가 Home 36/37 에 대해서만
  "In this moment, the limit is in a disabled state" 라는 단서를 단 것의 대우 — 평시에는 리밋이 유효하다.
- ③은 산업용 AMR(Autonomous Mobile Robot) 조작 화면에서 가장 중요한 제어를 약화시키는 제안이었다.

## 사용자 지적

- ① "통상적으로 리미트 스위치가 홈을 거치면 인지하고 살짝 뒤로가서 꺼지게 해야지"
- ② "일반적으로 호밍이라고 하면 홈 위치에서 다시 0도 기준점으로 돌아온은 것을 이야기 합니다"
- ③ "E-STOP 는 산업용 amr에서 필수인데 상식을 제발 제발 제발"
- 종합: "왜 상식을 자꾸 무시하고 마음데로 코딩하려고 하는지 이해가 안됨"

## 원인 분석

`wrong-assumption` — **"안전"을 근거로 표준에서 이탈하는 것이 보수적 선택이라고 가정**했다.
실제로는 반대다. 표준 시퀀스는 그 자체가 검증된 안전 절차이고, 일부만 떼어내면 검증되지 않은
새 상태(리밋에 얹힌 축, 기준점 없는 정지)를 만든다.

순서가 뒤집혀 있었다. 참조 구현과 실측 캡처를 **이미 읽은 뒤에도** 그것을 기준선으로 삼지 않고
내 판단을 먼저 세운 다음 사후에 정당화했다. ③은 참조조차 없이 일반 관행을 축소 제안했다.

## 재발 방지

- 지식 보강: 호밍의 정의(원점은 경유지, 종착지는 조향 0°)를 메모리
  `biguamr-steer-homing-architecture` 에 명문화하고, 펌웨어 상태기계가 `GOZERO` 도달 확인 없이는
  `DONE` 을 내지 못하도록 구현했다(실패 시 `ERR_GOZERO`).
- **미충족(open 사유)**: "참조 구현·표준이 존재하면 그것을 기준선으로 먼저 채택하고, 이탈 시에만
  근거를 제시한다" 는 일반 규칙은 어느 자산에도 기록되지 않았다. ③처럼 참조가 없는 영역은
  여전히 무방비다.
