# 2026-08-08 14:54 (KST) — 「두 경로 다 실패」로 소프트웨어를 배제하고 하드웨어 고장을 선언했다. 두 경로는 같은 백엔드였다

## 무엇을 했는가

전륜 구동축(`node1 walk_front`)이 지령을 받고도 돌지 않는 증상을 진단하면서, 두 갈래로 시험했다.

```
ROS2 체인   /motor/low_cmd            → 실패
「GUI 직결」 ~/steer_axis_deg·~/drive_mmps → 실패
조향각 0°·45°·70°                      → 전부 실패
```

여기서 **「경로 문제도 아니고 각도 문제도 아니다 ⇒ 소프트웨어 원인 배제」** 로 결론짓고,
`issues_and_fixes.md` 에 **「미해결 — 소프트웨어 원인 배제됨, 물리 점검 필요」**,
**「지령이 들어가는데 회전하지 않고 전류가 흐르는 것은 구속(stall) 의 전형」**,
**「손상 위험이 있어 구동 시험을 중단했다」** 로 기록하고 커밋했다(`b1ff211`).
사용자에게는 **「전륜 구동륜을 손으로 돌려 봐 주세요」** 라고 물리 점검을 요청했다.

60분 뒤, 원인은 **순수 소프트웨어**였다 — can_relay 가 제어권 획득 시 구동축 브링업
(`0x6040=0x86` · `0x60FF=0` · `0x100C`/`0x100D` · `0x6060=3` PV)을 보내지 않는 것이었고,
그 시퀀스를 보내자 두 축이 0.5 mm 이내로 복귀했다(`a7420a6`).

## 무엇이 잘못이었나

**「두 경로」가 서로 다른 경로가 아니었다.**

```
/motor/low_cmd        → driver_node → RelayBackend.set_motor_cmds
~/steer_axis_deg      → driver_node → RelayBackend.set_steer_axis_deg
~/drive_mmps          → driver_node → RelayBackend.set_drive_mmps
                                      ^^^^^^^^^^^^ 같은 인스턴스
```

둘은 **같은 `RelayBackend` 인스턴스의 진입점 2개**다. 따라서 이 시험이 배제한 것은
**상류 경로 의존성뿐**이고, 두 진입점이 **공유하는 구간**(기동 시퀀스·브링업)은 배제되지
않는다. **실제 원인이 정확히 거기 있었다.**

즉 근거는 「한 백엔드의 진입점 2개」만 덮는데 결론은 「소프트웨어 전체」를 덮었다.
그 위에 「구속(stall)」이라는 물리적 단정과 「손상 위험」이라는 조치 권고까지 얹었다.

부차 오류: 나중에 UI 직결 백엔드(`DirectBackend`)로 시험해 실패한 것을 「두 경로 모두」의
근거로 삼았는데, 그것도 **브링업을 안 보내는 것이 원인**이라 같은 결함의 두 표현일 뿐
독립 증거가 아니었다.

## 왜 그랬는가

「GUI 직결 경로」라는 **내가 붙인 이름을 사실로 취급**했다. `~/steer_axis_deg`·`~/drive_mmps`
는 can_relay **ROS 노드의 토픽**이지 UI 의 별도 경로가 아니다. 이름만 보고 아키텍처를
확인하지 않았다 — `driver_node.py` 에서 두 토픽이 어디로 가는지 **한 번도 읽지 않았다.**

그리고 배제 추론의 방향이 편했다. 소프트웨어를 배제하면 내가 더 할 일이 없어지고,
공을 사용자에게 넘길 수 있었다.

## 무엇이 대가였는가

- 사용자에게 **불필요한 물리 점검**(바퀴를 손으로 돌려보기, 배선·커플링 확인)을 요구했다
- 「손상 위험」을 근거로 구동 시험을 **스스로 중단**해 진단을 60분 지연시켰다
- 잘못된 인과가 **커밋으로 저장소에 들어갔고**, 다음 커밋이 그것을 반증했는데도
  기록은 정정되지 않은 채 남았다 — 그 상태로 인수인계됐다면 다음 사람이 하드웨어를 뜯는다
- 사용자가 「seer로 움직여 볼께」로 직접 반증할 때까지 내 힘으로 못 뒤집었다

## 재발 방지 — 자산에 반영한 것

1. **`RUNBOOK-steer-check.md` §0 함정표**에 「드라이브가 이상을 보고하지 않는다」를 넣고,
   자기보고(`error_code 0`·`motor_enabled true`)를 믿지 말고 **엔코더 이동량으로 판정**하라고 못박았다.
2. **`issues_and_fixes.md` 해당 entry** 에 취소선 + ❌ 철회 표기로 원문을 남기고
   「같은 `RelayBackend` 인스턴스를 탄다 ⇒ 상류 경로 의존성만 배제된다」를 명시했다.
3. **`backend.py:_write_bringup` docstring** 에 「`DirectBackend` 는 미수정 — PC 경로 전부
   고쳤다로 읽지 말 것」을 박았다.
4. **debt-045/046/047** 로 잔여(UI 백엔드 미수정 · node2 기전 미규명 · 회귀 0건)를 등록했다.

## 규칙으로 남길 것

**「A 경로도 실패, B 경로도 실패 ⇒ 상류 배제」를 쓰기 전에 A 와 B 가 어디서 합류하는지
코드로 확인한다.** 합류 지점 하류는 그 시험이 배제하지 못한다. 확인 없이 쓰면
배제의 범위를 넘긴 일반화이며, 이 저장소에서 **네 번째 재발**이다
(2026-08-03-002 · 2026-08-05-001 · 2026-08-06-002 와 같은 형태).
