# 프로세스 상태 미확인 + 도구 출력 의미 오독 — 오염된 수치를 두 번 보고

## 무슨 일이 있었나

CCTV 뷰어 렌더율 30 Hz vs 10 Hz 를 비교 측정하면서 **오염된 조건의 수치를 두 번 보고**했고,
별도로 `ps` 의 `%CPU` 를 순간값으로 오독했다.

1. **뷰어 중복 구동** — `TaskStop` 으로 백그라운드 작업을 종료했으나 그것은 **셸만 죽이고 ROS
   노드는 고아로 남긴다.** 종료 후 `ps` 로 실제 프로세스 수를 확인하지 않아, 53분째 살아 있던
   뷰어와 새 뷰어가 **동시에 2개** 도는 상태에서 측정했다. 그 값(`16.7~21.5 fps`,
   `10 Hz 76.2% CPU / 6.1~6.6 fps`)을 사용자에게 보고했다.
2. **`kill -9` 로 파이프라인 붕괴** — 고아 뷰어를 강제 종료하자 Fast DDS 공유메모리가 정리되지
   않고 `/dev/shm` 에 236개 누적, **카메라가 29.7 → 0.79~1.40 FPS 로 붕괴**했다. 전 프로세스
   정상 종료 후 재기동으로 회복.
3. **`ps` `%CPU` 오독** — 유휴 탐지기가 `ps` 에서 102% 로 보여 "놀고 있는데 코어를 먹는다" 고
   읽을 뻔했다. `ps` 의 `%CPU` 는 **프로세스 생애 평균**이고 순간값은 `top` 2회차의 **4.7%** 였다.
   보고 직전에 스스로 잡아 정정했다.

## 왜 일어났나

**주장의 대상과 검증의 대상이 달랐다.**
- (1)(2)는 "종료 명령을 보냈다" 를 "종료됐다" 로 받아들였다 — 명령의 반환이 아니라 **프로세스
  목록**을 봤어야 했다.
- (3)은 도구가 내는 숫자의 **정의를 확인하지 않고** 의미를 부여했다.

이는 이미 등재된 계열의 재발이다:
- `2026-07-28-001`(자기 도구 출력 무검증 — 증분/누적 필드 혼동)
- `2026-07-28-008`(이미 종료된 GUI 를 「점유 중」으로 stale 보고)

## 영향

- 잘못된 수치 2회 보고 → 사용자가 그 값으로 판단할 뻔했다. 재측정으로 폐기·정정.
- 카메라 파이프라인이 실제로 붕괴했다(약 10분). 다른 작업 중이었다면 그 시험도 깨졌다.
- ADR 에 오염 수치가 기록됐고, 후속 감사에서 걸러냈다.

## 재발 방지

1. **ROS 노드는 SIGINT 로 종료한다.** `kill -9` 는 DDS 공유메모리를 남겨 살아 있는 발행자까지
   막는다.
2. **종료 후 반드시 `ps` 로 실제 프로세스 수를 확인한다.** `TaskStop`·`pkill` 의 반환값은
   종료 증거가 아니다.
3. **측정 전 프로세스 수를 세고 보고에 함께 적는다.** "viewer=1 detector=1 camera=6 확인" 이
   수치와 같은 줄에 있어야 재현 조건이 성립한다.
4. **`ps %CPU` 는 생애 평균이다.** 순간 CPU 는 `top -b -n2` 2회차 또는 `pidstat` 구간 평균을
   쓰고, **측정 종류를 수치 옆에 병기**한다.
