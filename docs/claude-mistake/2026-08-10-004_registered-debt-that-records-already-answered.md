# 기록에 이미 있는 것을 「미확인 부채」로 등록했다 — 같은 날 세 번째

## 무슨 일이 있었나

`/robot_pose` 를 누가 채우는지 모르겠다며 `debt-068` 을 **미확인**으로 등록하고,
「전체 스택 기동 후 `ros2 topic info -v` 로 발행자 확정」을 상환 계획으로 적었다.
사용자 지적: **「068 기록 안보지? 실제 실험기록」**

`docs/issues_and_fixes/issues_and_fixes.md` 에 **2026-08-06 자(나흘 전)** 기록이 있었다:

```
yaw_control          yaw_control_pose_topic:         "/robot_pose"                 발행자 1 (정상)
yaw_control_reverse  yaw_control_reverse_pose_topic: "/rtabmap/localization_pose"  발행자 0
```

같은 문서가 이미 다음도 적어 두었다:

- `LocalizationMonitor` 는 TF 가 아니라 `/robot_pose` 토픽 캐시를 읽는다(오류 문구가 거짓)
- 실차 발행자로 지목된 `trnav_pose_publisher` 는 **이 저장소에 없다**
- 그래서 「실차 경로는 정상」은 **확인 불가**다 — 초판 주장을 스스로 철회한 자기 정정까지 포함

즉 내가 오늘 「발견」해서 부채로 등록한 내용은 **나흘 전에 이미 측정·기록·자기정정까지
끝나 있었다.** 나는 그것을 다시 유도하느라 시간을 쓰고, 결론을 「미확인」으로 낮춰 적었다.

## 왜 나쁜가

부채 등록은 **모르는 것**을 적는 자리다. 이미 답이 있는 것을 미확인으로 올리면

- 다음 사람이 같은 조사를 또 하고,
- 실기 시간을 이미 아는 것을 재확인하는 데 쓰고,
- 기록의 신뢰도가 떨어진다 — 「부채 목록에 있으니 모르는 것이겠지」가 깨진다.

## 근본 원인

**같은 날 세 번째다.**

1. `csm` 오판 — 「grep 0건」이라 적었으나 `import` 행을 보지 않는 조회였다(실제로는 사용 중)
2. `2026-08-10-003` — 설계 의도가 docstring 에 있는데 안 읽고 단정했다가 「반전」으로 포장
3. 본 건 — 실측 기록이 있는데 안 찾고 미확인으로 등록

공통 형태는 하나다: **코드/기록을 조회하는 대신 내 머릿속 모델로 판정하고, 그것을
결론으로 적는다.** `2026-08-05-001` 의 메타 패턴 그대로다.

특히 이번엔 조회 비용이 거의 0 이었다. `grep -n "robot_pose" docs/issues_and_fixes/…`
한 줄이면 나왔고, 실제로 사용자 지적 후 그 한 줄로 찾았다.

## 재발 방지 (자산 반영)

1. **부채를 「미확인」으로 등록하기 전에 `docs/issues_and_fixes/issues_and_fixes.md` 와
   `docs/code_review/` 를 대상 키워드로 grep 한다.** 이 저장소는 실측을 그 두 곳에 쌓는다.
   등록 항목에 **「조회한 기록과 조회어」를 함께 적어**, 안 찾아본 것과 찾아봤는데 없는 것을
   구분한다.
2. `debt-068` 을 기록 기반으로 **정정**했다 — 미확인 범위를 「발행자가 누구냐」(이미 답
   있음)에서 「실차 정본 발행자를 어떻게 세울 것이냐」(진짜 미결·설계 결정)로 좁혔다.
3. 그 조사에서 실제로 새로 확정된 것(`translate_*`·`mpc*` 의 죽은 키, 후진 2종의 리다이렉트
   수단 부재)은 부채가 아니라 **수정**으로 처리했다(`d8f14f1`).

## 부수 사고 — 커밋 메시지가 하지 않은 일을 주장했다

본 기록을 쓰던 명령이 staging 훅에 막혀 **통째로 실행되지 않았는데**(heredoc 이 앞
`git add` 와 같은 명령에 있었다), 재시도한 커밋 `d8f14f1` 의 메시지에는 「debt-068 정정」이
그대로 남아 나갔다. 실제 diff 는 코드 6파일뿐이었다.

교훈: **커밋 직전에 `git show --stat` 로 메시지와 diff 가 일치하는지 본다.** 특히 앞
명령이 오류로 끝났을 때는 반드시 확인한다.
