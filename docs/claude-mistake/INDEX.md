## 메타 패턴

- **정정 작업 자체가 오염된다 (2026-07-28-006)** — 오류를 고치려고 만든 정오표 v1 이 **정확한
  Handbook 인용을 「오진」으로 규정**했다. 원인은 2차 자료(검증 에이전트 산문)를 1차 자료처럼
  사용한 것 — `external_reference/handling.md` §3 이 금지하는 형태다. 사용자가 "10명이 재검토"·
  "적대적 검증을 해야 합니다" 를 지시하지 않았으면 잘못된 정오표가 정본으로 남아 **정확한 인용을
  되돌리는 데** 쓰였을 것이다. **교훈: 정정문에는 원본보다 높은 수준의 원문 대조를 요구한다.**
- **표준을 「안전」을 이유로 이탈 (2026-07-28-004)** — 리밋 백오프·조향 0° 복귀·E-STOP 을 각각
  "안전상" 이라며 뺐다. 셋 다 사용자가 바로잡았고 셋 다 업계 표준이었다. 참조 구현(TR_Nav)과
  실측 캡처를 **이미 읽은 뒤에도** 기준선으로 삼지 않고 내 판단을 먼저 세웠다.
  **표준 시퀀스는 그 자체가 검증된 안전 절차이고, 일부만 떼면 검증 안 된 새 상태를 만든다.**
- **`verify-skip` 의 시간 축 변형 (2026-07-28-008)** — 기존 3건은 "검증 전 확정" 이었으나 본 건은
  "**검증했으나 시효 지난 값을 확정**" 이다. 시변 상태(프로세스·장치 점유)를 1회 판독으로 고정했고
  그 사이 실기 관측 기회를 놓쳤다.
- **부정형 단정이 또 재발 (2026-07-28-005)** — 아래 2026-07-27-003 항목이 SessionStart 훅으로
  **주입되어 눈앞에 있었는데도** "우리가 못 막습니다" 를 인용 없이 단정했다. 실제로는 차단 기계
  (`seer_gate_fwd_hook` 의 Seer write drop)가 이미 존재했고 약 20줄로 해결됐다.
  **주입만으로는 막히지 않는다 — 강제 검사가 필요하다는 증거.**
- **자기 도구 출력 무검증 (2026-07-28-001)** — 같은 세션에서 만든 로그 생산자·소비자의 필드 의미
  (증분 vs 누적)를 대조하지 않아 "정지 구간 4~8건" 을 확정 보고했으나 실제는 0건. 같은 로그에 독립
  교차검증 지표(뷰어 자체 WARN 0건)가 이미 있었다. **로그 파생 수치는 독립 지표와 대조 후 보고**가
  결론. closed — 필드 개명(`frames_delta`)·0 판정 교체·회귀 테스트로 코드에 고정.
- **`verify-skip` 3연속 (2026-07-26-001 → 2026-07-27-001 → 2026-07-27-002)** — 모두 "검증·대조
  전에 확정형으로 보고" 가 뿌리다. 심각도가 소프트 오보고(emulate 정지값) → 문서 추측(freeze 객체)
  → **실장비 물리 손상**(node4 137° 갇힘) 순으로 상승했다. 세 건 다 규칙은 설치·인지돼 있었고
  advisory 였다는 점이 공통 — 강제 메커니즘 부재가 원인.
- **부정형 단정도 같은 뿌리 (2026-07-27-003)** — type 은 `mistake`/`wrong-assumption` 이지만
  실패 형태는 위와 같다: 자유도를 소진하지 않고 "두 실측은 모순" 이라는 구조적 결론을 확정형으로
  서술했다. **"된다" 만 조심하고 "안 된다·불가능하다" 에는 같은 기준을 적용하지 않은 것**이 핵심 공백.
