# 2026-07-29 07:55 (KST) — 지적받은 실수를 산문 반성으로 종결하고 entry 를 남기지 않음

## 무엇을 했는가

사용자가 "45도 크랩인데 전방 조향만 움직임 **기능확인 안하고 추측에 의한 리펙토링 함**",
"매번 지시마다 실수임" 이라고 지적했다. 나는 조사·수정·검증·커밋을 수행하고, 최종 보고에
**"## 짚어야 할 것"** 절을 붙여 이렇게 썼다:

> "지적하신 대로 저는 **프레임 보존만 검증하고 기능은 확인하지 않은 채** 리팩터를 마쳤다고
> 보고했습니다. 호밍(정의 미확인)과 크랩(동작 미확인) 두 번 같은 실패였습니다."

**그리고 거기서 끝냈다.** `docs/claude-mistake/` 에 entry 를 만들지 않았다.

## 무엇이 잘못이었나

- `CLAUDE.md` §mistake 등록 — "Claude 의 실수·규칙 위반이 발생하거나 **사용자가 지적하면**
  (정정·재발 포함) **응답 전 의무 선행 점검** … `docs/claude-mistake/YYYY-MM-DD-NNN.md` 에
  entry 기록(frontmatter 5 필드 + 고정 5 절) → 재발 방지를 자산에 반영(`reflected_assets` 1+)
  까지 수행한다. **기록 없는 '다음부터 잘하기' 종결 금지.**"
- `docs/claude_guideline/mistake/mistake.md` §사용 규칙 — "사용자가 직접 지적한 실패는
  **그 즉시** `docs/claude-mistake/` 에 기록한다."
- 같은 파일 §Closure 규칙 — "**단순 기록만으로는 학습이 닫히지 않음**" 의 앞 단계인 기록
  자체를 건너뛰었다.

내가 쓴 산문은 규칙이 금지한 형태(**기록 없는 반성**)의 정확한 표본이다. 같은 세션에서
`2026-07-29-001` 을 작성하며 이 절차를 이미 한 번 밟았으므로 "몰랐다" 가 성립하지 않는다.

## 사용자 지적

> "짚어야 할 것은 반성하고 mistake에 기록도 안하는 실수와 지시를 어겻음"

## 원인 분석

규칙은 설치돼 있고, SessionStart 훅이 mistake INDEX 를 주입하며, 같은 세션에서 직접
entry 를 쓴 직후였다. 가시성·지식 공백이 아니다. 실패 지점은 **트리거 판정**이었다:

1. **"이미 고쳤으니 사건이 아니다"로 오분류했다.** 지적 → 조사 → 수정 → 검증 → 커밋까지
   마쳤으므로 사안이 종결됐다고 보고, 남은 것은 보고용 요약이라고 판단했다. 규칙의 트리거는
   "미해결 여부" 가 아니라 **"사용자가 지적했는가"** 인데 그 조건을 확인하지 않았다.
2. **산문 반성이 기록의 대체물처럼 느껴졌다.** 보고서 안에 자기비판 절을 쓰면 심리적으로
   정산이 끝난다. 그러나 그 텍스트는 **대화가 끝나면 사라지고** 다음 세션의 INDEX 주입에
   잡히지 않는다 — 즉 재발 방지 기능이 0 이다. 정공법(entry+자산 반영)을 가벼운 대체물로
   우회한 것이라 `tech-debt-shortcut` 으로 분류한다.
   (⚠ enum 에 "SOP 미이행" 범주가 없어 가장 가까운 것을 골랐다. 임의 추가는 금지이므로
   `mistake.md` §카테고리 정의 개정이 필요하면 번들 SSOT 에서 해야 한다.)
3. 커밋 메시지에 경위를 길게 적은 것이 **기록을 남겼다는 착각**을 강화했다. 커밋 메시지는
   `docs/claude-mistake/` 가 아니고 INDEX·`entry-lint.sh` 어느 쪽에도 걸리지 않는다.

## 재발 방지

- **누락분 작성** — `2026-07-29-002` 를 뒤늦게 작성했다(본 entry 의 `reflected_assets`).
- **트리거 판정을 산출물로 고정** — 사용자 메시지가 정정·지적·불만을 담으면, 응답의 첫
  도구 호출은 **id 충돌 조회**(`ls docs/claude-mistake/`)여야 한다. "이미 고쳤는지" 는
  트리거 판정에 들어가지 않는다.
- **보고서에 자기비판 절을 쓰지 않는다.** 실수를 언급해야 하면 entry 를 먼저 만들고
  보고서에는 **그 링크만** 건다. 링크할 파일이 없다는 사실이 곧 미기록의 신호가 된다.

> ⚠ **아직 closure 아님.** 위 세 항목은 전부 내 자기보고에 의존하며, 이 저장소에는
> "지적 발생 → entry 존재" 를 재도출하는 기계 검사가 없다(`entry-lint.sh` 는 **있는** entry 의
> 형식만 본다 — **없는** entry 는 검출하지 못한다). `rule-violation` 은 강제 메커니즘 없이는
> 닫히지 않으므로 `open` 으로 둔다.
>
