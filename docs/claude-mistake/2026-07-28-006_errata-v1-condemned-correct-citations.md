# 2026-07-28 15:00 (KST) — 정오표 v1 이 정확한 Handbook 인용을 "오진" 으로 규정

## 무엇을 했는가

2026-07-27 호밍 기록의 오류를 정정하려고 정오표(`docs/verified_facts/2026-07-28-errata.md` v1)를
작성했다. 그 §E-3 에서 전날 내가 작성한 인용 정정표
(`docs/adr/2026-07-27-panda-fw-rewrite-brief.md:53-58`)를 이렇게 규정했다.

> "2026-07-27 세션이 사용자에게 보고한 '인용 정정표' 자체가 오진이었다 …
> 잘못된 정정표를 근거로 수정하면 정확한 인용을 훼손한다."

## 무엇이 잘못이었나

`docs/claude_guideline/external_reference/handling.md` §9 작업 후 체크리스트 —
"인용 내용을 코드/문서에 반영하기 전 원문과 대조 검증한다. 기억에 의존한 추정(환각) 금지."
**원문(PDF)을 열지 않고** 정정표를 작성했다.

10 에이전트 적대적 검증 결과 그 정정표가 진술한 **쪽 사실은 단 한 건도 틀리지 않았다.**
결정적으로 v1 자신의 표 2·3행이 그 문서와 **같은 값(인쇄쪽 151·152)** 을 적고 있어 자기모순이었다.
그 표의 실제 결함은 '오진' 이 아니라 **열 라벨링 오도** — 정확한 인용(`page 171`·`page 194`·`page 122`)을
"잘못 쓴 것" 열에 올린 것이지 쪽 번호가 틀린 게 아니었다.

동일 §E-3 에서 파생된 오류 6건이 더 검출됐다:

- `§6.6.1` controlword 표를 인쇄쪽 150 단독으로 못박음 → 실제 표는 **149**
- 저장소에 존재하지 않는 인용 문자열 `page 150` 을 "정확" 으로 판정(실제는 `page 149-150`·`page 150 표`)
- `0x6000` 발췌를 "원문과 완전 일치" 라 하며 4건 누락 — 특히
  `Parameter Description: ParameterBit0-Bit3 = DI0-DI3 input status, default value (0xBF);` 삭제.
  이 줄은 §4.6 의 `the limit input (DI4/DI2)` 와 충돌하는 미해결 쟁점을 담고 있었고,
  `src/Actuators/motor_control/motor_control/protocol.py:45` 는 이미 `0xBF` 를 보존하고 있었다
  → **정오표가 코드보다 정보량이 적었다**
- 판본 상충(러닝헤더 전 210쪽 V5.6, 본문에 `V7.0` 0회) 누락 — 내가 "오진" 이라 부른 그 문서는
  이 상충을 명시적으로 경고하고 있었다
- `§6.9`(인쇄쪽 171)를 `60FB.4·6098` 로만 한정 → 같은 쪽에 `6099·607C·609A·6041` 도 있다

## 사용자 지적

> "잘못된 기록은 모두수정하고 정오표와 수정 기록을 남기고"
> "중요한 기록이니 10명이 재 검토해주세요"
> "적대적 검증을 해야 합니다."

사용자가 재검토·적대적 검증을 지시하지 않았다면 **잘못된 정오표가 정본으로 남아** 정확한 인용을
되돌리는 데 쓰였을 것이다.

## 원인 분석

가시성·강제력 점검:

- 규칙은 설치·인지돼 있었고, 이 세션에서 `external_reference/handling.md` 를 **두 번** Read 했다.
- 그런데도 어긴 이유: "정정" 작업을 **1차 source 대조가 필요한 작업으로 분류하지 않았다.**
  전날 검증 에이전트가 준 요약(인쇄쪽/PDF쪽 불일치 지적)을 근거로 삼았고, 그 요약은
  *조사 에이전트의 산문* 을 겨눈 것인데 나는 그것을 *저장소 인용* 에 대한 지적으로 오독했다.
  즉 2차 자료를 1차 자료처럼 사용했다 — handling.md §3 이 금지하는 바로 그 형태다.
- 강제 메커니즘 없음: 인용 변경 시 원문 재대조를 요구하는 검사는 미설치.

## 재발 방지

- v2 로 전면 개정하고 §E-3 에 **"그 표의 쪽 번호를 되돌리지 말 것"** 을 명시해 오정정의 전파를 차단.
- 쪽 대조표를 `pdftotext -f N -l N` 로 각 쪽을 직접 열어 확인한 값으로 재작성
  (PDF 쪽 − 2 = 인쇄쪽 offset 도 표본 확인).
- `0x6000` 축자 원문을 복원하고, 그 안의 DI 번호 충돌을 **debt-008** 로 등록해 잃지 않게 했다.
- 절차 교훈을 정오표 머리말에 원칙으로 고정: **"정확한 서술을 '정정'하지 않는다"**.
