# 2026-07-27 23:03 (KST) — 이미 종료된 GUI 를 "점유 중" 이라고 보고

## 무엇을 했는가

실기 호밍 캡처를 준비하면서 판다 USB 점유 프로세스를 확인해 `amr_test_gui`(PID 351049)가
쥐고 있다고 보고했다. 사용자가 호밍을 진행하는 동안에도 같은 판단을 유지하며
"지금 캡처를 못 붙입니다 — GUI 가 판다를 쥐고 있어서" 라고 답했다.

## 무엇이 잘못이었나

보고 시점에 GUI 는 **이미 종료돼 있었다.** 최초 확인은 사실이었으나 그 뒤 상태가 바뀌었고,
나는 **재확인 없이 과거 판독을 현재 사실처럼 서술**했다.

그 결과 사용자가 호밍을 실행하는 동안 캡처를 붙이지 못해 **1회 관측 기회를 놓쳤다.**

## 사용자 지적

> "뭔소리야 gui 종료되엇는데"
> "캡처 못 했으면 다시 할꼐"

## 원인 분석

가시성·강제력 점검:

- 규칙 자체는 명시돼 있다 — 루트 `CLAUDE.md` reverse_engineering §6 은 `[존재]`(과거 판독)와
  `[동작]`(현재 상태) 라벨 분리를 요구한다. 프로세스 점유는 전형적인 시변(time-varying) 상태인데
  1회 판독을 무기한 유효한 사실로 취급했다.
- 이 실패는 `verify-skip` 계열의 **시간 축 변형**이다. 기존 3건(2026-07-26-001,
  2026-07-27-001·-002)은 "검증 전 확정" 이었고, 본 건은 "**검증했으나 시효가 지난 값을 확정**" 이다.
  같은 뿌리이되 재확인 시점이 빠졌다.
- 강제 메커니즘 없음. 시변 상태(프로세스·장치 점유·연결)를 근거로 판단할 때 재판독을 요구하는
  검사는 미설치.

## 재발 방지

강제 메커니즘 보강이 필요하나 **이번 세션에서 추가하지 못했다** — open.

필요한 것: 시변 상태(PID·USB 점유·네트워크 연결·브랜치 HEAD)를 근거로 결론을 서술하기 직전
재판독을 강제하는 절차. 최소한 "판독 시각을 함께 적는다" 는 관례라도 자산에 기록해야 한다.
