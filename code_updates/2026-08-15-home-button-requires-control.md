> 수정 이력의 기록처. 주석은 현재 코드의 사실만 담고 이력은 여기와 커밋 메시지가 담는다
> (`docs/claude_guideline/coding/conventions.md` §4).
> 약어: GUI(Graphical User Interface) · API(Application Programming Interface) ·
> SDO(Service Data Object)

- 사용자 지시: 2026-08-15 "제어권 획득하기 전에 호밍 button 을 활성화 하면 안됨"
- 대상: `can_relay/ui/app.py` · `can_relay/driver_node.py`

## 왜

제어권 없이 호밍을 누르면 이렇게 나왔다.

```
13:43:50  호밍 실패 — 백엔드가 기동돼 있지 않다
```

드라이버 내부 사정(`_running=False`)을 그대로 뱉은 것이고, 운용자가 할 일은 **제어권 획득**이다.
같은 GUI 의 조그는 「조그 불가 — 제어권을 먼저 획득하세요」라고 정확히 말하는데 호밍만 달랐다.

**대체 경로가 없다는 점이 조그와 다르다.** 조그는 제어권이 없으면 Seer 개루프 운동(2010)으로
우회하지만, 호밍은 우회할 상대가 없다 — Seer 로봇 제어 API(19205)의 전 명령이
`2000 정지 · 2001 자이로 캘리브레이션 · 2002 재측위 · 2003 측위확인 · 2010 개루프 운동 ·
2022/2023 스캔 · 2024/2025 지도` 뿐이고 조향 호밍이 없다
(`References/Seer-Driver/robokit_tcp_api.md`, 공개 SDK + 동봉 PDF v1.2.1 기준).
조향 호밍은 CANopen SDO `0x60FB:04` 로 드라이브 내부 루틴을 부르는 것이라 로봇 레벨 API 층에
대응물이 아예 없다.

## 고친 것

**① 버튼을 못 누르게 하고 이유를 보여 준다** (`app.py::_sync_home_button`)

| 상태 | 버튼 | 툴팁 |
| --- | --- | --- |
| 제어권 없음 | 비활성 | 「제어권을 먼저 획득하세요 — 호밍은 릴레이로 버스를 쥐고 있어야 하고 Seer 쪽 대체 경로가 없습니다」 |
| 호밍 중 | 비활성 | 「호밍 진행 중」 |
| 제어권 있음 | 활성 | (없음) |

100 ms 주기 갱신(`_refresh`)이 돌린다. 이벤트에만 걸면 **제어권 상실**을 놓친다.
capability 로 이미 막힌 백엔드는 건드리지 않는다 — 그 사유 툴팁을 덮으면 안 된다.

**버튼이 제어권을 대신 잡아 주지는 않는다.** 획득은 Seer 를 밀어내는 동작이라 운용자가
그 버튼을 눌러 명시적으로 해야 한다. 서비스(`~/home`)의 계약도 그대로 뒀다 — 서비스가
스스로 제어권을 잡으면 그것을 부르는 누구든 자기도 모르게 Seer 를 밀어내게 된다.

**② 상태 소유자를 하나로** — 종전에는 호밍 완료 분기(`_on_op_done`)가 버튼을 직접 켜서,
도중에 제어권을 놓으면 켜지면 안 될 버튼이 켜졌다. 이제 `_sync_home_button` 하나가 쥔다.

**③ 클릭 경로에도 확인을 남긴다** — 버튼이 비활성이라 정상 경로로는 오지 않지만, 오면
「호밍 불가 — 제어권을 먼저 획득하세요」로 막는다. 백엔드 내부 사정이 운용자에게 나가지 않는다.

**④ 조향 잠금을 상태줄에 드러낸다** (`driver_node.py::_on_diag_timer`)

실기에서 호밍이 실패해 조향이 잠겼는데 상태줄은 계속 「정상」이었다(13:53 이후). 화면만 보면
아무 문제가 없고, 조향을 걸어야 비로소 거부 로그가 뜬다. `home_failed` 를 판정에 넣고
진단 KeyValue 로도 노출한다.

```
조향 잠금 — 직전 호밍 미완료. `~/home` 재수행 필요        (WARN)
```

「호밍 진행 중」보다 **뒤**에 둔다 — 호밍 중에는 그쪽 문구가 맞다.
