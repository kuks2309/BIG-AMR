## 결론 먼저

1. **영상 `angle` 은 자세 측정이 아니라 `offset` 의 원근 파생량이다** — 실측으로 확정.
2. `angle` 을 쓰는 항을 전부 끈 **순수 crab** 제어로 1 m 주행, **XTE 20.1 cm → 3.4 cm**.
3. 정규화 `offset` 의 미터 척도를 실측했다 — **기준행 지면 반폭 0.53 m**(2회 독립 실측이
   4.6 % 안에서 일치). `XTE(m) = offset × 0.534`.

## 1. 영상 angle 은 원근이다 (SIL 가정의 반증)

SIL 가상 센서는 **지면** 값을 냈다(`offset`=지면 횡거리/반폭, `angle`=지면 접선각).
실제 `line_seg_node` 는 **영상** 값을 낸다(`centerline.py:106-112`) — 기준행 픽셀 오프셋과
영상에서의 수직 기준 기울기다.

지면 위 직선은 진행축과 나란하면 영상에서 **소실점(화면 중앙)으로 수렴**한다. 그래서 옆으로
벌어진 나란한 라인도 `angle ≠ 0` 으로 읽힌다. 정지 상태 실측이 이를 뒷받침했다:

| 항목 | 값 |
| --- | --- |
| offset | −0.364 |
| angle | **+0.550 rad = +31.5°** |
| 기준행 픽셀 오프셋 | 0.364 × 688 = 250 px |
| `tan(31.5°)` 로 역산한 소실점 거리 | 250/0.613 = 408 px |
| 기준행 y(=0.8×829) 663 − 408 | **y ≈ 255** — 사진에서 바닥이 배경과 만나는 높이 |

**자세 오차 0° 인데 angle 이 31.5° 로 읽힌다.** 결정적 증거는 주행 중 두 값의 비율이다:

| | 시작 | 종료 | 잔존비 |
| --- | --- | --- | --- |
| offset | −0.3675 | −0.0621 | **0.169** |
| angle | +32.3° | +5.8° | **0.180** |

`angle` 에 독립적인 자세 정보가 있었다면 두 비율이 이렇게 맞을 수 없다. `angle` 은 `offset` 의
선형 함수다.

⇒ SIL 로 정한 기하 게인(`kp_angle = L/2d`, `k_curve_heading = L/d`, `curve_bias_gain = d/2hw`)은
**이 카메라에 그대로 쓸 수 없다.** 그대로 두고 달렸다면 `delta_heading` 이 −37.8° 로 차체를
라인 **반대쪽**으로 돌렸을 것이다(주행 전 계산으로 발견해 차단했다).

## 2. 주행 설정 — angle 을 쓰는 항 차단

| 파라미터 | SIL 값 | 실기 값 | 이유 |
| --- | --- | --- | --- |
| `line_follow_kp_angle` | 0.6 | **0** | 공통분의 기울기 항 제거 |
| `line_follow_k_curve_heading` | 1.2 | **0** | 차이분 제거 → 차체가 돌지 않는다 |
| `line_follow_curve_bias_gain` | 0.8333 | **0** | SIL 기하 전용 보상 |
| `line_follow_kp_offset` | 1.2 | 1.2 | 유지 — 공통분 = 순수 crab |
| `steer_timeout_sec` | 5.0 | **15.0** | Phase 0 가 −90°→0° 로 90° 를 움직인다 |

남는 제어는 `delta_cte = −kp_offset·offset` 하나뿐이다. SIL 의 `hold_straight` 와 같은 형태.

### 3-1. 1 m (최대 0.2 m/s · 전진)

| 항목 | 값 |
| --- | --- |
| offset | −0.3675 → **−0.0621** (\|offset\| 83 % 감소) |
| 지령속도 적분 | 1.011 m · 경과 7.0 s |
| 측위 실측 | 전진 **+0.888 m** · 횡(좌+) **+0.167 m** |

**yaw 가 0.19° 밖에 안 변했다** — 차이분 0 으로 둔 대로 차체를 돌리지 않고 crab 만으로 붙었다.

### 3-2. 2 m (최대 0.2 m/s · 전진) — 사용자가 로봇을 옆으로 더 벌려 놓고 재시험

| 항목 | 값 |
| --- | --- |
| offset | −0.4338 → **+0.0014** (\|offset\| 최소 0.0002) |
| **XTE** | **23.2 cm → 0.07 cm** |

| 지령속도 적분 | 2.016 m · 경과 12.5 s |

`angle` 이 `offset` 과 함께 0 으로 떨어진 것이 원근 가설의 두 번째 확인이다.

⚠ `phase` 이력에 **2(LOST_COAST)** 가 스쳤다. 서버 로그에 소실 경고가 없으므로 `detected=false`
가 한두 프레임 지나간 수준이고 coast 0.5 s 안에 복귀했다. 광택 바닥 반사로 인한 간헐 미검출로
보이며 **속도를 올리면 문제가 될 수 있는 항목**이다.

## 4. offset 의 미터 척도 실측 (이번 시험의 핵심 소득)

차체 회전이 없으므로 주시점의 횡변위 = 로봇의 횡변위다(1차 0.19°, 2차 0.36°). 따라서
`hw = Δ횡거리 / Δoffset` 이고, **두 주행이 독립적으로 같은 값을 낸다**:

| 주행 | Δ횡거리 (m) | Δoffset | **hw (m)** |
| --- | --- | --- | --- |
| 1 m | 0.167 | 0.3054 | **0.547** |
| 2 m | 0.227 | 0.4352 | **0.522** |
| | | 평균 | **0.534** (편차 4.6 %) |

기준행(화면 높이 80 %)에서 화면 반폭이 덮는 지면 폭이 **약 0.53 m** 다. 이제 XTE 를 미터로 읽는다:

```
XTE(m) = offset × 0.534
```

| 주행 | 시작 | 종료 |
| --- | --- | --- |
| 1 m | 20.1 cm | 3.4 cm |
| 2 m | **23.2 cm** | **0.07 cm** |

### 모형 교차 검증

crab 각 = `kp_offset·offset` = `1.2/0.547 = 2.19 rad` per m of XTE → 감쇠 길이상수 `1/2.19 = 0.457 m`.
경로장 `hypot(0.888, 0.167) = 0.904 m` 에 대해

- 예측 잔존비 `exp(−0.904/0.457)` = **0.138**
- 실측 잔존비 `0.0621/0.3675` = **0.169**

초기 포화(시작 offset 0.3675 가 포화 임계 `0.436/1.2 = 0.363` 을 막 넘었다)를 감안하면 일치한다.
**척도·게인·수렴이 하나의 모형으로 설명된다.**

## 5. 절차상 확인된 것

- `can_relay` **engage 직후 조향 판독은 즉시 유효하지 않다.** engage 3 s 후 `/wheel_motor_state`
  가 −106.8° 를 보고했으나 Seer 는 −90° 였다. 이후 안정화되자 두 판독이 0.33° 안에서 일치했다.
  ⇒ **engage 후 판독이 안정될 때까지 확인하고 나서 지령한다**(5회 연속 동일 확인).
- 조향 0° 복귀는 goal 을 내고 Phase 0 완료 시점에 취소하는 방법으로 **구동 없이** 수행했다
  (지령속도 적분 0.000 m).

## 6. 구성상 미해결 — 도메인 분리

`can_relay` 는 systemd 로 **도메인 125**, 측위·rviz 는 **도메인 0** 이다. 지령 경로에 손수 만든
도메인 브릿지를 끼우는 위험을 피해, 이번에는 인식·모션을 전부 125 로 모으고 측위를 제어에서
뺐다(`enable_localization_watchdog:=false`, `max_distance=0`). 거리는 액션 피드백의 지령 속도
적분으로 재고, 측위는 도메인 0 의 별도 기록기가 분석용으로만 남겼다.

⇒ **통합은 별건이다.** 이 상태로는 `max_distance` 종료 조건과 측위 워치독을 실기에서 쓸 수 없다.

## 7. 곁가지 결함

`usb_cam_cctv.launch.py:57-68` 이 `config_file` 인자를 **선언만 하고 쓰지 않는다** — 항상 기본
로스터를 읽어, 카메라 한 대만 띄우려 해도 6대가 전부 뜬다. 이번엔 대역 경합으로 일부가
`failed to open device` 로 떨어졌다. 별건 수정 대상.

## 남은 것

- **곡선은 아직 못 한다.** `angle` 을 지면 값으로 바꾸는 IPM(호모그래피)이 필요하고, 그러려면
  카메라 외부 파라미터(장착 높이·피치)를 재야 한다. 그 전에는 `kp_angle`·`k_curve_heading` 을
  실기에서 켜면 안 된다.
- `curve_bias_gain` 도 같은 이유로 0 으로 둔다 — 0.8333 은 SIL 기하 전용이다.
- 도메인 통합(§6), 카메라 런치 인자 결함(§7).

## 8. 라인 선택을 ROI 판정으로 교체 (사용자 지시)

후진 시험에서 검출이 **화면 반대편의 다른 붉은 라인**으로 옮겨가 발산 가드가 걸렸다.
로봇은 0.478 m 밖에 안 갔는데 `offset` 이 0.134 → 0.834 로 뛰었고, 그 변화량을 거리로
환산하면 1 m 이상이라 물리적으로 성립하지 않았다 — 로봇이 아니라 **검출 대상이 점프**한 것이다.

### 원인 둘

1. `line_seg_node._infer_best_mask` 가 **신뢰도 최고 인스턴스 하나만** 썼다
   (`confs.argmax()`). 신뢰도는 「어느 라인을 따라가야 하는가」와 무관하다.
   실측: conf 0.692 인 화면 끝 선을 골라 conf 0.653 인 진짜 라인을 버렸다.
2. `fit_centerline` 이 전경 **전체**에 직선 하나를 맞춘 뒤 기준행에서 평가한다 —
   **기준행에 라인 픽셀이 없어도 외삽**한다.

### 고친 방식 — 「피팅된 직선이 ROI 를 지나는가」

사용자 지시: 「ROI 에 있는 라인 선택해야지」 · 「직선이 ROI 에 있느냐 없느냐로 판단해야 함」.

- `_infer_instances` — 인스턴스를 **전부** 후보로 돌려준다(신뢰도로 버리지 않는다).
- `select_line_in_roi` (신규) — 인스턴스마다 직선을 뽑고, 그 **직선이 기준행 ROI 를 지나는지**로
  후보를 거른 뒤 `prefer_x` 에 가장 가까운 것을 고른다.
- `prefer_x` = **직전 프레임의 기준행 위치**. 오차가 커도 따라가던 라인을 유지하고,
  `MISS_FRAMES_TO_RESET`(20 프레임 ≈ 1 초) 이상 끊기면 버리고 화면 중앙 기준으로 새로 찾는다.
- 픽셀이 아니라 직선으로 판정하므로 **기준행에서 테이프가 끊겨도 검출이 이어진다** — 이 지점이
  중요하다. 픽셀 판정으로 만들었더니 라인이 기준행에서 끊긴 프레임이 미검출이 되어
  `−9`(라인 소실)로 주행이 끊겼다.
- 파라미터 `roi_half_width_ratio`(화면 반폭 대비, 기본 0.9). 좁히면 반대편 라인을 확실히
  배제하지만 큰 오차에서 진짜 라인까지 버린다 — 0.6 으로 뒀다가 offset 0.70 인 실제 상황에서
  미검출이 나 0.9 로 넓혔다.

### 검증

단위시험 **23건 통과**(기존 13 + ROI 씨앗추적 5 + 직선-ROI 판정 5).
실기에서 저장한 프레임 4종으로 전후 대조:

| 프레임 | 상황 | 기존 | 신규 |
| --- | --- | --- | --- |
| 발산 시점 | 라인 2개 | 기준행 x=**1177**(오선택) | **613** ✓ |
| 소실 시점 | 기준행에서 테이프 끊김 | 미검출 | **728** ✓ |
| 정상 후방 | 라인 1개 | 920 | 920 ✓ |
| 정상 전방 | 라인 1개 | 362 | 362 ✓ |

`line_lost_coast_sec` 은 0.5 s → **1.5 s**(사용자 지시: 「바로 끊으면 안되고 … 1초 정도는 유지」).
0.5 s·감속 0.15 m/s² 면 유예 중 이동이 7 cm 뿐이라 짧은 끊김도 못 넘긴다.

## 10. 미해결로 남기는 것

- **조향 판독 환산 계수** — 같은 자세를 Seer 는 −90.0°, 우리 `/wheel_motor_state` 는
  **−106.78°** 로 읽는다(10 초 안정, 재현됨). 0° 에서는 양쪽이 0.33° 안에서 일치하므로
  오프셋이 아니라 **계수(약 1.19배) 차이**로 보인다. 어느 쪽이 물리적 참인지 미확정.
  전진·후진 모두 폐루프가 흡수해 주행에는 지장이 없었으나 **열린 항목**이다.
- 도메인 분리(§6), 카메라 런치 `config_file` 인자 결함(§7), 곡선용 IPM.
