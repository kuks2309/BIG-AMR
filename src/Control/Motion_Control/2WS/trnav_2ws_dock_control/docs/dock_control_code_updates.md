## 2026-08-14 — `returnHomeAbort` 에 marker 결손 유예 (정본 1프레임 규칙 이탈)

**계기**: 실기에서 복귀가 두 번 연속 `marker stale·lost` 로 죽었다(0.5 s·2.8 s).

**측정**: 같은 스택·정지 상태 30 s 에서 `has_lateral` 결손 **5.1%**(22/433), 8구간, 연속
최대 **7프레임 = 0.49 s**. 세 축(`has_lateral`·`has_range`·`has_yaw`)이 **동시에** 빠진다.
⚠ 같은 측정을 도킹 위치(d=0.550)에서 했을 때는 **0%** 였다 — 자세 의존 가능성.

**판단**: 관측이 **안 오는** 경우는 `obs_max_age_s` 0.5 s 까지 견디면서, 관측이 「아무것도
못 봤다」고 **말해 주면** 즉시 죽는 것은 정보량이 같은 두 경우를 다르게 다루는 것이다.
정본이 1프레임 규칙을 쓴 것은 맞지만 정본은 그 규칙으로 100회를 성공했으므로 **정본의
관측이 지금보다 안정적이었다**고 보는 편이 자연스럽다.

**조치**: `HomeAbort` 에 `MARKER_WAIT` 추가, `HomeAbortInput` 에 `marker_lost_elapsed_s`·
`marker_grace_s` 추가. 유예 안이면 대기(호출자가 **steer-hold 정지**), 넘으면 `STALE`.
판정 순서는 «관측낡음 → marker → 라이다 → FOV → timeout» — marker 결손 중에는 나머지를
보지 않는다(눈이 감긴 동안의 값이다).

**검증**: 단위시험 PASS + **red 3종 검출**(유예 소멸 / 경계 부등호 / 순서 뒤집기).
골든 재생성 — `returnHomeAbort` 480→864행(시그니처 변경), **그 외 1,129 데이터행은 동일**.
전체 1,805건 0 불일치.

⚠ **유예는 증상 완화다.** 결손 5.1% 자체의 원인(자세 의존? 조명? 마커 가림?)은 미해결이며,
그래서 노드가 결손 횟수·누적 시간을 로그와 완료 문자열에 남기도록 함께 넣었다.

## 2026-08-13 — 과조향 바이어스 `geomEntryDeltaBiased`

**지시**: *"기하학적 계산보다 3도 정도 더 돌아가게 해서 빠르게 진입하면 어떨까?"*

### 왜 더 도는가

두 근거가 같은 방향을 가리킨다.

- **실측 폐합률이 이론의 91%** 다(포화 구간 적합 −0.4246 대 이론 −0.4663). 순수 기하각은
  계통적으로 덜 돈다 — δ 13° 지령이 실효 11.87° 로 작동해 약 1.2° 부족하다.
- **비대칭**: 덜 돌면 경유점에 오차를 남긴 채 도착해 도크 가까이서 고쳐야 하고, 더 돌면
  0 에 일찍 닿아 멀리서 피드백으로 넘어간다.

### 조치

`geomEntryDeltaBiased(cte_x, e_d, δmax, bias)` — 오차 방향으로만 키우고 상한에서 클램프.
얹는 양은 **`min(bias, |δ*|)`** 라 오차가 작으면 바이어스도 함께 작아진다(오차가 거의 없는데
고정량을 더하면 «이유 없이 3° 틀기» 가 된다).

⚠ 과조향은 그대로 두면 반대편으로 넘어간다 — **조기 전환(`entry_exit_px`)이 짝** 이며
그 장치 없이 이 함수만 쓰면 안 된다. 헤더 주석에 못박았다.

### 검증

단위시험 [6] 신설 — 방향 유지 · 크기 `min(bias,|δ*|)` · 2배 상한 · 클램프 · 0 보존.
red 2종(부호 무시 / 비례 제한 제거) 모두 FAIL 확인 후 green.

실기: `진입각 고정 δ=-21.09° (과조향 +3.0° 포함)` 로그 확인 · 3축 수렴.

### 부수 — 정량 효과

같은 출발(`cte_x0 −0.162 m`)에서 δ 18.4° → 21.4° 로 올리면 수평 0 도달 거리가 1.048 → 1.122 m
로 **7.4 cm 당겨진다**. 다만 접근 성분 `cos δ` 가 줄어 목표까지 총 시간은 **0.7 s 늘어난다** —
이득은 속도가 아니라 «정렬을 일찍 끝낸다» 이다.

## 2026-08-13 — 기하 진입 + 관측 게이트: 수평 수렴을 이득에서 기하로

**지시**: *"게인 튜닝"* → *"과학적으로 수학적으로"* → *"crab 각도는 삼각함수에 의해서 정해짐 맞지"*
→ *"2단계로 해야 할 것 같습니다. 1단계는 기하 진입 2단계는 피드백 주행"* → *"조향 한계치 밖이면
translate 사용"*.

### 무엇이 문제였나

순수 crab 은 `d(cte_x)/dD = tan δ` 라 수평 폐합이 **접근 거리**에만 묶인다. 정본 수평 법칙은

관측 게이트는 별개 문제였다. 3축 AND 라 heading 이득이 0 인 순수 crab 에서도 자세축을 요구했고,

## 2026-08-13 — `phase4Steer` 신설: 조향 합성 부호를 접근측에 대칭으로

**지시**: *"1번부터 부탁드립니다. 단위 검증부터"* (수평축 부호 정정).

### 무엇이 문제였나

정본 `:1844` 는 `steer = as·π/2 − δ` 다. 정본 기체는 **좌측 접근(as=+1)** 뿐이라 이 식과
`as·(π/2 − δ)` 가 같은 값을 낸다 — 차이는 **우측 접근에서만** 드러난다.

우측(as=−1)에서 전자를 쓰면 크랩 기준각은 뒤집히는데 δ 항은 안 뒤집혀, δ 가 오차를 **키우는**
방향으로 붙는다. 실기에서 `err_px −110.8` → 조향 −115°(후진 성분) → `err_px` 가 −273 까지
벌어지고 마커가 시야를 벗어났다.

### 조치

코어에 `phase4Steer(as, δ, δ_max)` 신설 — `as·(π/2 − δ)` 에 정본과 같은 `±(π/2 + δ_max)` 클램프.
**골든 대상 함수는 건드리지 않았다**(합성부는 골든 케이스가 아니며 `composePhase4Wheels` 는
`steer` 를 입력으로 받는다). 회귀 확인: 골든 **872건 0 불일치**.

### 단위 검증 (`test/unit/phase4_steer_check.cpp`)

| # | 검사 | 결과 |
|---|---|---|
| 1 | 좌측 접근 = 정본 식과 완전 일치 | 21점 |
| 2 | 우측 접근 = 좌측의 부호 반전 | 21점 |
| 3 | **오차 감소 방향** — 본 기체 실측 규칙(+x 전진 → err_px 증가) | 20점 |
| 4 | 실기 조건 재현 `err_px −110.8` → **−65°** (종전 −115°) | ✓ |
| 5 | 클램프 ±115° | ✓ |

⚠ 시험 [3]은 **본 기체(우측 카메라) 조건에만** 적용한다. 처음에는 양쪽에 적용해 20건이
실패했는데, 그것은 코드가 아니라 **시험이 틀린 것**이었다 — 좌측 기체는 카메라가 거울상이라
그 규칙도 뒤집힌다. 좌측의 정당성은 [1]·[2]가 담보한다.

⚠ 실기 재검증은 **미실시**. 무구동 계산으로는 `err_px −68.85 → −65°` 가 나온다.

## 2026-08-12 — SIL 에 IMU 하드캡 결선 + `Plant` 위치 초기화 사고

### 무엇을

|---|---|

### ⚠ 사고 — `Plant` 위치 초기화가 값을 밀었다

`heading_rad` 를 `arm` **앞에** 끼웠는데 케이스 표가 위치 초기화
(`{0.030, 1.20, 94.0, 0.33, 607.7}`)라 뒤 값이 통째로 밀렸다 —
**`arm` 에 `fx` 607.7 이 들어가** 팔 길이가 1,841배가 되면서 `w_rad = (vf−vr)/(2·arm) ≈ 0`,
즉 **회전이 사라졌다.** 자세 시나리오 2건이 「yaw 미수렴」으로 깨진 원인이 이것이다.

증상이 「가드를 넣었더니 자세 제어가 죽었다」로 보여 가드를 의심했으나, **가드를 빼도 동일**해
초기화로 좁혀졌다 — 의심 대상을 실행으로 배제한 것이 진단을 살렸다.

조치: 필드를 **구조체 맨 뒤로** 옮기고, 케이스 표 8곳을 **지정자 초기화**
(`{.mx = …, .my = …, .yaw_deg = …}`)로 바꿔 순서 의존을 제거했다.
구조체 주석에 「새 멤버는 반드시 맨 뒤에」와 사고 내용을 남겼다.

## 2026-08-12 — IMU 가드 3종 골든 등록 (1,008 → 1,060건)
