## 1. 목적

Seer(SRC) 컨트롤러와의 Robokit TCP/IP API 통신을 단일 지점으로 모은다. 이전에는 16B 헤더가
`seer_read_lidar_install.py:24` 와 `seer_lidar_tf_node.py:27` 에 각각 재구현돼 있었고, 두 구현 모두
seq 고정·응답 seq 미대조·요청 간격 무제한이었다.

⚠ **하네스 자체의 함정 2가지 — 둘 다 실제로 밟았다.**
1. `__pycache__` 오염 — `.pyc` 유효성이 (mtime 초, 파일크기)로 판정되므로 같은 초에 같은 크기로 쓴
   변조는 **직전 항목의 바이트코드가 재사용된다.** 초판이 그 오염으로 27/27 을 잘못 보고했다.
   `python -B` + `PYTHONDONTWRITEBYTECODE` + `__pycache__` 삭제로 닫았다.
2. **무력한 돌연변이** — `frozenset(…) or frozenset({…})` 로 쓰면 파생 집합이 비었을 때 falsy 라
   `or` 가 원본으로 되돌아가 **변조가 아무 일도 하지 않는다.** P2 가 그래서 미검출로 나왔다.
   블록을 통째로 치환하도록 고쳤다. 「미검출」이 나오면 **시험을 의심하기 전에 돌연변이를 의심한다.**

## 3. 전역변수표

가변 전역 **0개**. 모듈 수준 이름은 전부 상수(포트·편호·헤더 포맷)이며 런타임에 바뀌지 않는다.
연결 상태(`_sock`, `_seq`, `_last_request_at`)는 `SeerTransport` 인스턴스 안에만 있다.

| 이름 | 위치 | 가변 | 누가 바꾸나 |
|---|---|---|---|
| `API_PORT_*`, `MAX_CONNECTION_PARAM`, `OBSERVED_MAX_CONNECTIONS`, `CONNECTION_LIMIT_RET_CODE`, `GUARDED_PORTS`, `MIN_REQUEST_INTERVAL_S`, `RESPONSE_TYPE_OFFSET` | `ports.py:15-70` | 불변 | 아무도(소스 수정만) |
| `HEAD_FMT`, `HEAD_LEN`, `SYNC`, `VERSION`, `RSV` | `transport.py:27-31` | 불변 | 아무도 |
| `API_*`(편호) | `api.py:21-41` | 불변 | 아무도 |

⚠ `OBSERVED_MAX_CONNECTIONS` 는 **코드에서는 불변이지만 로봇에서는 가변**이다(런타임 파라미터,
`minValue` 1 ~ `maxValue` 20). 상수를 진실로 쓰지 말고 판정이 필요하면
`SeerApi.get_max_connections()` 로 로봇에 묻는다.
