## 1. 목적

Seer(SRC) 컨트롤러가 보유한 2D LiDAR **장착 pose(`install_info`: x/y/yaw)** 를 우리 TF 트리로
가져온다. 값의 **정본은 Seer 설정**이고 저장소는 사본을 들고 있다 — 재장착·재캘리브 시에만
재조회해 갱신한다(사용자 지시: 요청 시에만 변경).

세 파일의 역할이 다르다 — 혼동 주의:

| 파일 | 언제 쓰나 | Seer 접속 |
|---|---|---|
| `seer_read_lidar_install.py` | **사람이 값을 확인/갱신할 때** 1회 실행 → 붙여넣을 텍스트 출력 | 실시간 |
| `seer_lidar_tf_launch.py` | **평시 운용** — 코드에 박힌 스냅샷으로 static TF 발행 | 없음(오프라인) |
| `seer_lidar_tf/…/seer_lidar_tf_node.py` | Seer 를 **직접 읽어** TF 발행하거나 merger YAML 로 기록 | 실시간 |

## 4. 전역변수표

가변 전역 **0개**. 아래는 전부 기동 시 1회 확정되고 이후 바뀌지 않는다.

| 이름 | 위치 | 가변 | 누가 바꾸나 |
|---|---|---|---|
| `SEER` | `seer_read_lidar_install.py:24` | 기동 시 확정 | `argv[1]`, 없으면 기본 IP |
| `PARENT` | `seer_lidar_tf_launch.py:15` | 불변 | 소스 수정만 |
| **`LIDARS`** | `seer_lidar_tf_launch.py:18-22` | 불변 | **Seer 재조회 후 사람이 갱신** — 정본은 Seer 설정이지 이 배열이 아니다 |

**인스턴스 상태**(`SeerLidarTf`, 전역 아님 — 노드 1개 안에만 있다)

| 이름 | 위치 | 누가 바꾸나 |
|---|---|---|
| `done` | `:52` | `._write_once` — `main` 이 spin 여부 판정에 읽는다 |
| `_client` | `:56` | `.__init__` 생성, `main` 의 `finally` 가 close |
| `_broadcaster`/`_published`/`_timer` | `:66,67,69` | publish 모드에서만 존재 — **write 모드에는 없다**(`__init__` 이 조기 반환) |

⚠ `_broadcaster`·`_timer` 가 **모드에 따라 존재하지 않는다.** write 모드에서 `_tick` 을 부르면
`AttributeError` 다. 현재는 호출 경로가 없어 문제되지 않으나, 두 모드를 한 클래스가 겸하는 구조가
그 위험을 안고 있다.

## 5. 의존성

- `seer_lidar_tf_node.py` → `rclpy`, `tf2_ros`, `geometry_msgs`, **`seer_tcp_ip`**(exec_depend).
  Seer TCP 프로토콜을 여기서 재구현하지 않는다(ADR `docs/adr/2026-08-07-seer-api-tcp-hal.md`).
- `seer_read_lidar_install.py` → **`seer_tcp_ip` 만**(ROS 무관). 미소싱 환경은 경로 fallback.
- `seer_lidar_tf_launch.py` → `launch`, `launch_ros`, `tf2_ros`. **Seer 접속 없음.**
- 네트워크: Seer 는 무선 전용(`wlan0`) — `docs/network/seer_network_access.md`.

## 6. 값의 정본 관계

```
Seer 컨트롤러 설정  ──(정본)
   │
   ├─ seer_read_lidar_install.py ─→ 사람이 확인 → seer_lidar_tf_launch.py 의 LIDARS (사본, 수동 갱신)
   ├─ seer_lidar_tf_node.py [publish] ─→ static TF (실시간, 사본 없음)
   └─ seer_lidar_tf_node.py [write]   ─→ dual_laser_merger calibration_result.yaml (사본, 자동 생성)
```

⚠ **사본이 3벌**이다(launch 상수 · merger YAML · 런타임 TF). 재캘리브 시 어느 것을 갱신했는지
분명히 하지 않으면 서로 어긋난다. 관련 실측 기록: 후방 라이다가 Seer 설정과 하드코딩 사이에서
22 mm 어긋난 사례(메모리 `biguamr-seer-lidar-mounts`).
