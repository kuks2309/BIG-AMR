## 목적

바닥 라인(테이프·도색)을 YOLOv8-seg 로 분할하고 중심선을 피팅해 **횡오차·기울기**를
`/line/error`(`ai_msgs/LineError`)로 발행한다. 주행 제어는 하지 않는다 — 제어 계층은 별건.

## 핵심 제약 — 카메라를 직접 열지 않는다 (카메라 HAL 준수)

`usb_cam_publisher` 6개 노드가 `/dev/video*` 를 점유한다. 본 노드는 **토픽 구독만** 하며,
카메라 이름·토픽은 로스터 SSOT `config/camera/camera_common.yaml` 에서 유도한다.
전송은 `compressed`(MJPEG 패스스루)이므로 **디코드는 본 노드 안에서** `cv2.imdecode` 로 한다.
(`dataset_collector`·`yolo_detector` 와 동일 규약. ADR §D1)

## 데이터 흐름

```
usb_cam_publisher(cam_f | cam_r)
  → /<cam>/image_raw/compressed (CompressedImage, SensorDataQoS)
     → line_seg_node
        ├ cv2.imdecode → (선택) flip_180
        ├ YOLOv8-seg 추론 → 최고 conf 마스크
        ├ fit_centerline → line_error(offset, angle)
        ├ → /line/error        (ai_msgs/LineError, 미검출도 발행)
        └ → /line/debug_image  (구독자 있을 때만)
```

`direction` 파라미터(`forward`|`reverse`)가 `cam_f`|`cam_r` 중 어느 쪽을 구독할지 고른다.

## 부호 규약

- `offset` + = 라인이 **진행방향 기준 오른쪽**. 후방 카메라는 광축이 `-x_robot` 이라
  영상 오른쪽 = 로봇 왼쪽 = 후진 시 진행방향 오른쪽 → **좌우 반전 보정 불요**
  (기하 추론, ADR §D4 — **`[미검증]`, 실기 확인 전 주행 금지**)
- `angle` + = 라인 위쪽이 오른쪽으로 기움. 수직 = 0

## QoS

발행자(`usb_cam_publisher`)가 `SensorDataQoS`(BEST_EFFORT/VOLATILE)이므로 구독도 동일하게
맞춘다. `RELIABLE` 로 구독하면 호환되지 않아 메시지가 0 이 된다(ros2-coding.md §1).
`/line/error` 는 제어 계층이 놓치면 안 되므로 RELIABLE depth 10 으로 발행한다.
