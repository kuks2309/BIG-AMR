# RUNBOOK — 조향·구동 점검 (이관용)

> 목적: **인수자가 이 문서만으로** 조향·구동이 정상인지 판정하고, 이상하면 어디가 원인인지
> 가릴 수 있게 한다. 2026-08-08 세션에서 하루를 태운 두 결함과 네 번의 오진이 근거다.
>
> 대상 기체: Foil_A082 · `can_relay` + `amr_motor_cmd_translator` + 2WS 모션 체인

---

## 0. 먼저 알아야 할 것 — 오진을 부르는 함정 5개

이 다섯 개를 모르면 **멀쩡한 하드웨어를 뜯게 된다.** 전부 2026-08-08 실기에서 겪었다.

| # | 함정 | 증상 | 대응 |
| --- | --- | --- | --- |
| 1 | **passthrough 중 `/motor/low_state` 는 캐시가 언다** | 제어권 반환 후 엔코더가 50 Hz 로 계속 발행되는데 **값이 안 변한다**. 「로봇이 안 움직였다」로 오독하기 쉽다 | 제어권 없는 구간의 엔코더 대조는 **무효**. 반환 직전·재획득 직후 값으로만 대조 |
| 2 | **PC 권한 중 Seer 판독도 언다** | can_relay 가 intercept 하는 동안 Seer API 1100/1101 이 engage 시점 스냅샷을 준다. 조향을 10°·20° 움직여도 Seer encoder 가 **1 count 도 안 변한다** | Seer 를 계측기로 쓰려면 **제어권을 반환**할 것. 그래도 우리가 움직인 이력은 Seer 가 모른다 |
| 3 | **라이다 토픽은 BEST_EFFORT** | `/scan_*`·`/scan_merged`·`/odom` 을 기본 RELIABLE 로 구독하면 **한 건도 못 받는다**(토픽은 멀쩡한데 화면·스크립트만 빈다) | `qos_profile_sensor_data` 로 구독. rviz 는 LaserScan Reliability = Best Effort |
| 4 | **조향 raw 와 물리각은 부호·오프셋이 다르다** | `/motor/low_cmd`·`fb_pos` 의 raw 값을 그대로 각도로 읽으면 45° 가 −71.7° 로 보인다 | `physical = direction × raw/57344 + offset`. Foil_A082 는 `direction_steer_* = −1`, `steer_offset_*_deg = −1.676` (`amr_motor_cmd_translator_qd.yaml`) |
| 5 | **드라이브가 이상을 보고하지 않는다** | 구동축이 지령을 받고도 안 도는데 `error_code 0` · `motor_enabled true` · `home_comp true` | 자기보고를 믿지 말고 **엔코더 이동량**으로 판정 |

## 1. 사전 점검 (움직이기 전, 30초)

```bash
export ROS_DOMAIN_ID=0
ros2 node list | grep -E "can_relay|translator|mux"
for t in /motor/low_state /wheel_motor_state /imu/data /robot_pose; do
  echo -n "$t "; timeout 8 ros2 topic hz $t 2>&1 | grep -m1 "average rate"
done
```

기대값 — `/motor/low_state` 50 Hz · `/wheel_motor_state` ~43 Hz · `/imu/data` ~95 Hz ·
`/robot_pose` 20~31 Hz.

⚠ **`/wheel_motor_state` 가 0 이면 조향이 통째로 죽는다.** 이 토픽은 translator 의
`publish_legacy_wheel_motor_state` 가 소유한다(기본 true). SIL 체인 런치는 이것을
**false 로 끄므로**(시뮬 플랜트가 같은 토픽을 내기 때문), 그 설정을 실차에 그대로
가져오면 액션의 조향 수렴 판정이 영원히 거짓이 되어 Phase 0 이 타임아웃한다.

```bash
ros2 param get /amr_motor_cmd_translator publish_legacy_wheel_motor_state   # 실차는 True 여야 한다
```

## 2. 조향축 단독 시험 (로봇 이동 없음)

구동을 일절 보내지 않으므로 **로봇은 움직이지 않는다.** 가장 먼저 할 시험.

```bash
ros2 topic pub --once /can_relay_node/steer_axis_deg std_msgs/msg/Float64MultiArray \
  "{data: [3.0, 30.0]}"     # node3(전륜) → 30°.  node4 는 rear.
ros2 topic echo /motor/low_state --once | grep -A2 "motor_id: 3"
```

판정 기준 (2026-08-08 실측):

| 항목 | 정상값 |
| --- | --- |
| 0 → ±30° 도달 시간 | 1.3 ~ 1.9 s |
| 정착 오차 | 0.05 ~ 0.1° |
| 전류 | ±100 안팎 |
| 지령 안 한 축 | **변하지 않아야** 한다(축별 분리 확인) |

⚠ 조향이 **한 카운트도 안 움직이면** can_relay 로그를 볼 것:
`지령 거부 — node3 호밍 미완료 — 조향 거부` 가 찍히면 호밍 판정 문제다
(→ §6 결함 ①, 커밋 `0b38966` 로 수정됨).

## 3. 구동축 단독 시험 (로봇 ~9 cm 이동)

**축을 하나씩** 보낸다. 둘을 같이 보내면 한쪽이 죽어도 로봇이 움직여 가려진다.

`/motor/low_cmd` 에 해당 축만 담아 `MODE_VELOCITY`, `target_vel = -735`(≈30 mm/s)로
2.5초 발행 → 0 으로 1.5초 → 엔코더 차분.

판정 기준:

| 항목 | 정상값 |
| --- | --- |
| 이동량 | 축당 0.06 ~ 0.10 m |
| 실속도(`fb_vel`) 최대 | 740 ~ 880 (0.1 rpm) |
| 두 축 차이 | **2 mm 이내** |

⚠ **`target_vel = -245`(10 mm/s) 로는 정지마찰을 못 이겨 양 축 다 0 이 나온다.**
「안 돈다」로 오판하지 말 것 — 최소 −735 로 시험한다.

⚠ 한 축만 지령의 2~8 % 만 반응하면(예: 최대 13~93 vs 785) **구동축 브링업 부재**다
(→ §6 결함 ②, 커밋 `a7420a6` 로 수정됨).

## 4. 조향 0° 가 물리적 직진인지 확인 (핵심 — 로봇 ~9 cm 이동)

**Seer 로는 확인할 수 없다**(§0 함정 2). 직접 주행해서 라이다로 잰다.

1. `~/steer_axis_deg` 로 node3·node4 를 **0°** 로 정렬
2. `/odom` 기준점 기록 (⚠ BEST_EFFORT 구독)
3. `~/drive_mmps` 30 mm/s × 3 s → 0
4. `/odom` 재기록. 변위 방향을 **차체 기준**으로 환산

```
rel = atan2(dy, dx) − yaw0
```

⚠ **주행은 ≥0.5 m, 3회 이상**(전진·후진 섞어서). 짧게 재면 잡음과 구분되지 않는다 —
같은 날 90 mm 1회로는 δ = 2.1°, 0.5 m 3회로는 δ = +0.53 / +0.66 / −0.14° 가 나왔다.

판정 — 2026-08-08 실측(0.5 m × 3회, 조향 0° 정렬 node3 −0.05° · node4 −0.06°):

| 회차 | 이동 | 진행 방향(차체 기준) | 잔차 δ | 헤딩 변화 |
| --- | --- | --- | --- | --- |
| 1 (+50 mm/s) | 501 mm | +179.47° | +0.53° | −0.04° |
| 2 (−50 mm/s) | 514 mm | +0.66° | +0.66° | +0.10° |
| 3 (+50 mm/s) | 521 mm | −179.86° | −0.14° | −0.08° |

`0°` 또는 `±180°` 면 **바퀴가 차체 축과 나란하다 = 0° 가 물리 직진**이다.
(`drive_mmps` 양수가 후진 쪽이라 180° 근처로 나온다 — 부호 규약일 뿐 결함이 아니다.)
`±90°` 근처면 조향이 90° 틀어진 것이고, 그때만 `steer_home_counts` 를 의심한다.

> ⚠ 2026-08-08 에 이 시험을 하기 전까지 「재시작마다 조향이 90° 튄다」·「후륜 홈이 90°
> 어긋났다」고 두 번 잘못 판정했다. 둘 다 이 시험 한 번으로 반증됐다.
> **홈 상수를 고치기 전에 반드시 이 시험을 먼저 할 것.**

## 5. 이설·신규 기체 — 홈 상수 `steer_home_counts` 입력 절차 ★필수

> **기체를 옮기거나 바꾸면 이 절차를 반드시 수행한다.** 홈 상수가 틀리면 조향 지령이
> 통째로 어긋나며, **정지 상태 판독만으로는 절대 알 수 없다.**

### 5-1. 무엇을 넣는 값인가

조향이 **물리적 직진(0°)** 일 때의 **절대 엔코더 counts**, 축별 1개씩.

```
위치   src/Comm/CAN/can_relay/config/machine/<기체>.yaml  →  steer_home_counts: [node3, node4]
단위   counts (57,344 counts/°)
정본   docs/homing/2026-08-03-can-relay-homing-assets.md §0-0
```

### 5-2. ❌ 넣으면 안 되는 값 3가지

| 넣으면 안 되는 것 | 왜 | 실제 사고 |
| --- | --- | --- |
| **호밍 후 정착값** (`7882020` / `7859062`) | 펌웨어 GOZERO 상수이고 **0° 가 아니다** — 0° 에서 **+0.178° / +0.331°** 벗어나 있다 | yaml 주석이 「혼동 금지」로 못박아 둔 항목 |
| **raw 판독값을 그대로** | 판독 시점 상태에 따라 어긋난다 | 폐기값 `7839894` 가 정답에서 **193 counts** 어긋나 있었다 |
| **다른 기체의 값** | 절대 엔코더는 기체마다 다르다 | — |

### 5-3. 측정 절차

**전제** — §1 사전 점검 통과, §2 조향축 단독 시험 통과, §3 구동축 단독 시험 통과.
(구동이 한쪽만 돌면 §4 의 직진 시험이 회전으로 나와 판정이 오염된다.)

1. **호밍** `ros2 service call /can_relay_node/home std_srvs/srv/Trigger`
   → 기준을 세운다. 정착값을 기록은 하되 **그것을 0° 로 쓰지 않는다**(§5-2).
2. **임시 후보 입력** — 같은 기종 값이나 호밍 정착값을 출발점으로 yaml 에 넣고 can_relay 기동.
3. **조향 0° 정렬** — `~/steer_axis_deg` 로 node3·node4 를 0° 로.
4. **직진 주행 시험(§4)** — 30 mm/s × 3 s, `/odom` 으로 진행 방향을 차체 기준으로 환산.
5. **잔차 δ 읽기** — 진행 방향이 `0°`/`±180°` 에서 벗어난 각이 δ 다.
6. **보정** — 홈을 `δ × 57,344` counts 만큼 옮긴다.
   ⚠ **부호는 1회 시험으로 정한다** — 보정 후 |δ| 가 줄어들면 맞고, 커지면 반대 부호다.
   추론으로 정하지 말 것(2026-08-08 에 부호 추론으로 두 번 틀렸다).
7. **2~6 반복**, `|δ| < 1°` 이면 채택.
8. **검증** — §7 crab 시험. 횡오차·헤딩오차가 판정표 안에 들어와야 한다.

### 5-4. 측정 중 금지 사항

- ❌ **Seer 각도로 검증하지 말 것.** can_relay 가 제어권을 쥔 동안 Seer 판독은 engage
  시점 스냅샷으로 얼어 있다(§0 함정 2). 조향을 20° 움직여도 Seer encoder 가 안 변한다.
- ❌ **정지 상태 판독만으로 0° 판정 금지.** 판독은 홈 상수에 의존하므로 **순환 논증**이 된다.
  반드시 **움직여서** 외부 기준(`/odom`)으로 재야 한다.
- ❌ **호밍만 하고 0° 로 간주 금지**(§5-2).

### 5-5. 기록 의무

채택값과 함께 아래를 남긴다 — 값만 남기면 다음 사람이 근거를 다시 만들어야 한다.

```
값 · 측정일 · 측정 방법(§5-3) · 최종 잔차 δ · 반복 횟수 · 검증한 crab 결과
→ machine yaml 주석 + docs/homing/ 에 이중 기록
```

### 5-6. Foil_A082 현재값의 근거 (2026-08-08 갱신)

```
steer_home_counts: [7871815, 7840086]
```

정본 문서(`docs/homing/2026-08-03-can-relay-homing-assets.md` §0-0 E8)는 이 값의 근거를
**「공학적 채택값(Seer 좌표계 정합)」** 으로 규정하고, 「Seer 의 0° 와 물리적 직진이
같은지는 **미확정**」이라고 남겨 두었다(`foil_a082.yaml:135-136`).

**2026-08-08, 본 절차 §5-3 의 직진 주행 시험으로 그 미확정 항목을 닫았다.**

조향 0° 정렬(node3 −0.05° · node4 −0.06°) 후 **약 0.5 m 를 전진·후진 섞어 3회**:

| 회차 | 지령 | 이동 | 진행 방향(차체 기준) | 잔차 δ | 헤딩 변화 |
| --- | --- | --- | --- | --- | --- |
| 1 | +50 mm/s | 501 mm | +179.47° | **+0.53°** | −0.04° |
| 2 | −50 mm/s | 514 mm | +0.66° | **+0.66°** | +0.10° |
| 3 | +50 mm/s | 521 mm | −179.86° | **−0.14°** | −0.08° |

```
평균 δ = +0.35°   ·   폭 0.80°   ·   전 회차 |δ| < 1°  → §5-3 채택 기준 만족
```

⇒ **현재 홈 상수의 0° 는 물리적 직진과 일치한다.** 평균 +0.35° 는 산포 0.80° 안에 있어
**0 과 구분되지 않는다** — 계통 오차의 증거가 아니다. 전진·후진에서 δ 의 부호가 뒤집히지
않은 것도 오도메트리 계통오차가 아님을 뒷받침한다.

⚠ **짧은 주행으로 판정하지 말 것.** 같은 날 90 mm · 1회로 쟀을 때는 δ = 2.1° 가 나왔다.
그 거리에서 2.1° 는 횡변위 3.3 mm 라 잡음과 구분되지 않는다. **≥0.5 m · 3회 이상**으로 잰다.

## 6. 이미 고친 결함 2건 — 재발 시 여기부터 본다

### ① 조향 게이트 (커밋 `0b38966`)

`set_motor_cmds`(ROS2 체인이 타는 저수준 경로)만 `self._homed` 를 직접 봐서, **Seer 가
호밍한 상태**(드라이브 `0x6041` bit15 = 1)에서 조향 지령을 전량 거부했다.
`set_steer_deg`·`set_steer_axis_deg` 는 `homed_effective()` 를 쓰고 있었다 — 그 경로만 누락.

증상: 조향 엔코더 0 counts, 액션 `Phase 0 steer timeout`, can_relay 로그에 거부 반복.

### ② 구동축 브링업 부재 (커밋 `a7420a6`)

**can_relay 프로세스를 재시작하면** `node1 walk_front` 가 `0x60FF` 를 받고도 안 돈다.
`allow_bringup: false` 라 can_relay 가 CiA402 기동 시퀀스를 한 번도 보내지 않았고,
그 상태는 원래 Seer 가 만들어 주던 것이다(`protocol.py:160-162`).

- 제어권 반환↔재획득 **사이클만으로는 재현되지 않는다** — 프로세스 재시작에서만 난다
- ROS 체인과 UI 직결 백엔드가 **둘 다** 실패한다(경로 문제가 아니다)
- Seer 가 한 번 주행하면 복구된다

⚠ **브링업을 조향축까지 보내지 말 것.** fault reset(`0x6040=0x86`)이 조향 위치 카운터를
지워 0° 기준이 무효가 된다. 2026-08-08 에 실제로 그렇게 만들어 전륜이 의도치 않게 움직였고,
`~/home` 재호밍으로 복구했다(정착값 node3 +0.18° · node4 +0.33°, 정본 기록과 일치).

## 7. 통합 확인 — crab 주행

위가 전부 통과하면 crab 으로 마무리한다. 2026-08-08 실측:

| 시험 | 거리 | 횡오차 | 헤딩오차 | 소요 |
| --- | --- | --- | --- | --- |
| crab +y 0.5 m | 0.5004 m | −0.0001 m | −0.197° | 13.9 s |
| crab 차체 45° 0.4 m | 0.4006 m | −0.0021 m | −0.014° | 10.5 s |

거리 0.5003 m 로 **정상처럼 보이는데** 횡오차 −0.234 m · 헤딩 −52.4° · 31.1 s.
**거리만 보고 통과 판정하지 말 것.**
