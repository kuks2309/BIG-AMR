# comment_check — 주석↔코드 재도출 검사기

주석이 인용한 **좌표·이름·수치**를 코드에서 다시 이끌어내 대조한다. `debt-070` 상환 도구.

```bash
python3 Tools/comment_check/check_comments.py src/Control/Motion_Control/2WS/
python3 Tools/comment_check/check_comments.py <경로> --json      # 기계 판독
python3 Tools/comment_check/test_check_comments.py               # 회귀 테스트
```

종료 코드: `0` 불일치 없음 · `1` 불일치 있음 · `2` 사용법 오류.

## 검사 5종

| 종류 | 무엇을 본다 | 예 |
| --- | --- | --- |
| `anchor` | 주석 속 `파일:줄` 의 파일 실재 + 줄 범위 | `chassis_kinematics.py:999` |
| `path` | 줄 번호 없이 인용된 저장소 경로의 실재 | `docs/plan/2026-06-09_….md` |
| `symbol` | `Ns::Name` 이 **그 스코프 안에** 있는가 · 파라미터 접두 `foo_*` 의 실재 | `trnav_2ws_core::loadGeometry` |
| `const` | 상수 선언 줄의 꼬리 주석 수치 ↔ 선언값 | `constexpr … = 25.0*M_PI/180; // 20°` |
| `history` | 주석이 **이력**을 적고 있는가 (기본 미포함 — 옵트인) | `// 종전에는 …이었다` |

`symbol` 은 **마지막 이름만 찾지 않는다.** `trnav_2ws_core::loadGeometry` 는 `loadGeometry` 라는
이름이 저장소에 있어도(실제 소유자는 `TwoWsActionServerBase`) 소속이 다르므로 잡힌다.

`const` 는 단위 환산(rad↔deg, m↔mm, s↔ms)을 하고, **주석이 쓴 유효숫자만큼만** 요구한다
(`~89.94 deg` 는 `89.9427°` 를 통과시킨다). 범위·증분 표현(`3° 와 15° 사이`, `lookahead+0.2 m`)은
값 주장으로 읽지 않는다.

## 억제 마커

주석에 `comment-check: ignore` 를 넣으면 **그 줄**은 검사하지 않는다. 정당한 예외가 실재한다:

1. 결함 **예시**를 인용하는 문서·도구 — 이 검사기 자신이 그렇다(`check_comments.py` 4줄)
2. 붙여넣은 외부 로그 (`[Err] [RenderEngine.cc:197] …`)
3. 상류 원본 좌표

마커는 명시적이라 `grep` 으로 전수 조사되고 남용이 드러난다. 파일 단위 예외는 두지 않았다 —
한 줄만 막는 편이 나머지 줄의 보호를 잃지 않는다.

## 무엇을 잡지 못하는가 (도구 출력에도 같은 문구가 나온다)

**서술·해석·부호 규약·동작 설명은 검증되지 않는다.** 문법적 단서가 없어 기계로 재도출할 수 없다.

- `// 양 휠 동일 steer` — 실제는 rear 만 offset
- `// 종료는 fine timeout 으로만` — 실제는 settle 게이트가 정상 종료 경로
- `# cross-track error, + left` — 실제는 경로 **우측**이 양수

## 실측 (2WS 스택 · 113 파일)

2026-08-11~13 감사에서 확정된 **180건**을 정답지로 삼아 측정했다.

| 지표 | 값 |
| --- | --- |
| 재현율 (기본 4종) | **25 / 180 ≈ 14%** — `path` 16 · `symbol` 9 |
| 오탐 | **0** (감사 완료 트리 113 파일) |
| `anchor`·`const` 재현 | **0** |

`anchor`·`const` 가 알려진 결함을 못 잡은 것은 그 결함들이 기계로 재도출되지 않는 형태였기 때문이다 —
`chassis_kinematics.py:64` 는 줄이 **존재하지만 엉뚱한 줄**이었고, crab 의 `±20°/±110°` 는 선언 꼬리가
아니라 **위쪽 블록 주석**에 있었다. 두 검사는 회귀 방지용으로 유지한다(테스트가 고정).

`symbol` 은 처음에 **0건**이었다. 마지막 이름만 대조해서 `trnav_2ws_core::loadGeometry` 가
「`loadGeometry` 가 저장소에 있으니 통과」로 빠졌기 때문이다. 스코프 대조로 고친 뒤 **9건**이 됐고,
그중 **2건은 3라운드 감사(36 에이전트)가 놓친 실제 결함**이었다
(`crab_linear_params.yaml:3` · `spin_params.yaml:3`).

`history` 는 기본 검사에서 뺐다. 현재 트리에 **42건**이 걸리는데 전부 `종전` 한 토큰의 기존 주석이고,
일부는 설계 근거를 대비로 설명한다. 게이트로 켜면 노이즈가 되므로 **신규/이식 코드에 옵트인**으로 쓴다:
`--checks anchor,path,symbol,const,history`.

## 그래서 어디에 쓰나

**이 도구는 에이전트 감사를 대체하지 않는다.** 알려진 결함의 86%가 의미 판정을 필요로 했다.

쓸모는 두 가지다:

1. **회귀 가드** — 오탐 0, 113 파일 수 초, 재실행이 싸다. 고쳐 놓은 것이 되돌아오는지 본다.
2. **이식 게이트의 1차 체** — `path` 유형은 **이식할 때 되돌아오는 바로 그 부채**다.
   실측 25건이 전부 상류 좌표·상류 소속 인용이었다(`docs/abstraction/…`,
   `src/Control/Kinematics/`, `src/Navigation/trnav_pose_publisher`, `trnav_2ws_core::loadGeometry`). LGIT 검증 후 QD 스택을 들여올 때
   머지 전에 이 검사를 통과시킨다(`debt-070` 상환계획 ②). 통과했다고 주석이 옳은 것은 아니다 —
   의미 판정은 별도로 받아야 한다.

## 검증된 적용 범위

**2WS 스택에서만 오탐 0 이 실측됐다.** `src/` 전체에 돌리면 581 파일에서 161건이 나오는데
(`path` 100 · `anchor` 33 · `symbol` 20 · `const` 8) **이것은 결함 161건이라는 뜻이 아니다** —
분류해 보지 않았다. 표본에는 진성(QD `package.xml` 의 `src/Control/Kinematics`)과 오탐
(로그 출력을 붙여 넣은 주석의 `RenderEngine.cc:197`)이 섞여 있다.

다른 패키지에 적용하려면 그 범위에서 먼저 오탐을 분류하고, 이 README 의 실측 표를 갱신하라.
분류 없이 「161건 결함」으로 인용하면 이 도구가 막으려는 부채(근거 없는 수치 인용)를 새로 만든다.

## 새 검사를 추가할 때

`test_check_comments.py` 에 **검출 사례와 오탐 사례를 함께** 넣는다. 오탐 고정 항목은 전부
2WS 실측에서 실제로 틀렸던 것들이다(단위 환산·유효숫자·범위 표현·멤버변수 접두·상류 출처 표기).
그것들을 지우면 도구가 이미 적대적으로 판정된 결론과 다시 싸운다.

## 외부 적대 검토에서 나온 것 (2026-08-13)

`codex` 가 실행으로 보인 거짓 통과 6종을 **직접 재현**한 뒤(전부 사실) 5종을 고쳤다.

| 지적 | 상태 |
| --- | --- |
| `const` 가 부호를 버린다 (`= 10.0; // -10 m`) | 고침 — 부호 반영 |
| 16진수·`L` 접미사 리터럴이 평가 실패 후 조용히 통과 | 고침 — `0x…`·접미사 파싱 |
| `기준` 한 단어로 값 검사 전체 생략 | 고침 — `기준` 제거, `최대/최소` 는 숫자 인접 시만 |
| 한 줄의 **두 번째** C++ 블록 주석 미추출 | 고침 — 한 줄 안의 주석을 전부 순회 |
| 여러 줄 XML `<description>` 본문 미추출 | 고침 — `in_desc` 상태 추적 |
| 주석에 숫자가 여럿이면 **하나만 맞아도** 통과 | **고치지 않음**(아래) |

`symbol` 검사가 네임스페이스를 버리던 것도 codex 가 반증했다 — 고친 결과가 위 실측표의 9건이다.

### 복수 숫자를 고치지 않은 이유

「전부 맞아야 통과」로 조였더니 **정상 주석 3건이 오탐**됐다(실측):

- `heading_divergence_count_{10}; // 서로 다른 pose 샘플 수 (실차 10 Hz 기준 약 1.0 s)`
- `control_rate_hz: 50  # 이산화 지연 50ms→20ms`

주석은 선언값 말고 **파생 수치**를 정당하게 언급한다. 오탐 0 을 지키는 쪽을 택했고,
그 대가로 「10 m 이고 또한 999 m」 같은 같은-주석-안 거짓 주장 하나는 놓친다.
`const` 를 조이려면 **선언의 단위를 알아야** 하는데 지금은 알 수 없다.

### 남은 것

- `_eval_expr` 실패는 여전히 fail-open(조용히 통과)이다.
- 매 실행 저장소 전체를 walk 한다(2WS 1.1초 · `src` 전체 2.6초 — 현재 규모에선 문제 없음).

고칠 때는 각각 회귀 테스트 픽스처를 함께 넣는다.
