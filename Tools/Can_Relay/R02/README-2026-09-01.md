## 어떻게 (통상 경로와 다른 점)

`docking_field_kit/flash_panda.py` 는 정상 판다 선존을 전제해 **공장 DFU 상태에선 `Panda()` 가
assert 로 죽는다**(2026-09-01 실측 재확인). 그래서 신규 도구 **`Tools/Can_Relay/flash_new_board.py`**
(이번에 정본화·함수표 등재)로 굽는다:

1. `PandaDFU(...).recover()` 로 bootstub(14,176 B) DFU 프로그램 → reset.
2. 보드가 **BOOT0/DFU-모드 강제 핀 때문에 DFU 로 재진입**(2026-08-23 과 동일 거동, 이번에 원인 확정 —
   아래) → 통상 재열거 경로가 막힘.
3. 그래서 **앱도 DFU 로 직접 프로그램**: 16K 섹터 1·2·3(0x8004000/0x8008000/0x800C000) 소거 후
   signed blob 을 `APP_ADDRESS_FX`(0x8004000)에 기록 — USB flasher(`flash_static`)와 동일 blob·주소·
   소거 범위라 등가. 라이브러리는 `panda-firmware/python` 정본 사용.

## 검증 상태

- ✅ **1차 flash 직후 앱 부팅 검증**: 정상 판다 `0xddcc` 부팅, `get_signature()`(0xd3/0xd4) **== 파일
  바이트 동일(True)**, version `DEV-cc5e0491-DEBUG` 일치, safety_mode 0(SILENT), hw_type `0x03`.
- ✅ **DFU read-back 검증**(재설치 후, 21:5x): 장치 앱 영역(`APP_ADDRESS_FX`, 30,488 B) DFU_UPLOAD 로
  읽어 파일과 대조 → **md5 `91fe4282…` 완전 일치**. 즉 부팅 여부와 무관하게 플래시 자체 성공 확정.
- ⏸ **앱 자립 부팅은 BOOT0/DFU-모드 핀 대기**: 이 보드는 **DFU 강제 핀이 SET** 되어 있어 리셋마다
  앱으로 점프하지 않고 DFU/bootstub 로 돌아온다. **사용자가 그 핀을 해제(앱 부팅 허용) 후 전원 재인가**
  하면 bootstub 이 앱 서명 검증 후 점프한다(1차에서 실증됨). 현재 보드는 DFU(`356534903232`) 상태로 대기.
- ⛔ **부팅 250 kbps 정합**: 실기 CAN 버스 장착 후 별도 확인 필요(수 초 수신·`can_rx_errs`=0,
  2026-08-23 절차). 벤치 플래시만으론 미검증.
- ⚠ **PC-intercept(engage)**: 이 보드가 R01(핀맵 결함)인지 R02(재배선)인지에 따라 갈린다. 이 stock
  이미지는 **passthrough(Seer 단독 주행 fail-safe) + 부팅 정합**만 보장. R01 이면 intercept 무동작
  (릴레이 K1=PC10 인데 stock 의 relay_SBU 구동 핀이 곧 PC10). R02 는 재배선이 stock(black-panda) 펌웨어와
  정합(RELAY 구동=PC10=pin_relay_SBU1)이라, 이 stock 이미지만으로 engage·릴레이 intercept 전환·passthrough
  RX 가 실기에서 동작한다(2026-09-01 22:2x 실측: ~/engage 성공·릴레이 스위칭·양버스 RX 0에러 —
  Tools/Can_Relay/R02/README.md:22-32). 다만 intercept 중 포워딩 비트 에러(문제 B)는 미해결이고 근본
  원인(보드 vs 펌웨어)은 미확정이다 — 커스텀 프로파일 미빌드가 원인이라는 서술은 오판. 상세 [../fw_backups/README-2026-08-23.md](../fw_backups/README-2026-08-23.md):42-87.

## 함정 기록 — 통상(normal) flash 경로가 이 보드를 bootstub 에 가둔다

`flash_new_board.py` 의 step3a(정상 판다 → `Panda().flash()`)는 flash 시작에 `reset(enter_bootstub=True)`
를 부르는데, **DFU 강제 핀이 SET 인 보드에선 이후 리셋이 앱으로 점프하지 않고 bootstub(`0xddee`)에
갇힌다**(2026-09-01 실측 — 영구도구 검증 재플래시 중 발생). 복구는 `reset(enter_bootloader=True)` 로
DFU 로 밀어넣은 뒤 step3b(DFU 직접) 경로로 재플래시하면 됨(그렇게 복구 완료).
**→ DFU 강제 핀이 SET 인 동안엔 항상 DFU 직접 경로로 굽는다.** 이미 앱 부팅 중인 보드에 재플래시하지 말 것.
