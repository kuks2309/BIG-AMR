주석 `:364-380` 의 실측 타임스탬프는 **전항 정확**하다. 재현 명령은 본 문서 말미.

|---|---|---|

## B. 반증 — 재현 불가 (폴 레이트)

주석 `:151-155` 의 "2026-07-27 Seer SDO 폴 **12초 실측**(bus0 …)" 수치는 **어느 데이터로도 재현되지 않는다.**

| 객체 | 주석 주장 (12 s 기준 환산) | 호밍캡처 180 s | 오늘 정상운전 8 s | 판정 |
|---|---|---|---|---|
| `0x6064` | 노드당 2,718~2,920회 → **226~243 Hz** | **101.5 Hz/node** | **111.5 Hz/node** | ✗ 반증 |
| `0x6041` | node3/4 300여 → ~25 Hz | 6.6 Hz/node | 2.9 Hz/node | ✗ 반증 |
| `0x6078` | 66회 → 5.5 Hz | 2.3 Hz/node | 2.9 Hz/node | ✗ 반증 |
| `0x606C` | 0회 | 0회 | 0회 | ✓ 참 |

**두 독립 측정(180 s / 8 s)이 서로는 일치**하고(101.5 vs 111.5 Hz) 주석만 2배 이상 벗어난다.
주석 자신의 정정 (7)이 "1차 캡처 로그는 저장소에 보존돼 있지 않다"고 인정했는데,
**보존되지 않은 수치가 그대로 코드 주석에 남아 후속 판단의 근거로 쓰였다** — 본 세션에서 실제로 그렇게 오용됐다.

⇒ **폐기.** 유효한 값은 위 실측 2건이다.

## 재현 명령

```bash
# 호밍 시퀀스 타임스탬프 (A)
python3 - <<'EOF'
import json
cap=[json.loads(l) for l in open("Log/homing_capture_220350.jsonl") if l.strip()]
for r in cap:
    a=r.get("id"); d=r.get("d","")
    if a is None or not (0x601<=a<=0x604): continue
    b=bytes.fromhex(d)
    if b[0] not in (0x2F,0x2B,0x27,0x23): continue
    idx=b[1]|(b[2]<<8)
    if idx in (0x6040,0x6099,0x60FB,0x6060,0x6081,0x607A):
        print(f"{r['t']:.4f} node{a-0x600} 0x{idx:04X}.{b[3]} = {b[4:8].hex()}")
EOF

# 폴 레이트 (B) — 정상 운전 신규 실측
```
