## 2026-07-28 — `0xec`(`seer_block_homing`) 존치 근거 무효

### 삭제된 주석 원문

```c
// *** Seer 호밍 트리거 차단 (0xec) ***
// 제어권 반환 직후 Seer 가 자기 초기화로 0x60FB.4=1(RstStart)을 보내 조향축을 137° 왕복시킨다.
```

### 무엇이 틀렸나 (3건)

**① 제어권 반환은 트리거가 아니다**

- 운영자 확인(2026-07-28): "절대 안 그럼".
- 실측: 제어권 조작 없는 정상 운전 8초 수동청취에서 **13,508 프레임 중 `0x60FB` 접근 0건**.
  - 로그 `Log/dry_baseline_183437.jsonl`
  - 도구 `Tools/docking_field_kit/orin_homing_capture.py --dry` (CAN 송신 0, 릴레이 미조작)
  - 관측된 ID 12종: `0x581~584` / `0x601~604` / `0x701~704` 뿐

**② 137° 는 이상거동이 아니라 설계 동작**

호밍은 원점(리밋)을 경유해 **조향 0° 로 복귀**하는 것까지가 한 동작이고, 그 복귀 이동이 약 137° 다.
목표 절대값 node3 = 7,882,020 / node4 = 7,859,062 counts (57,344 counts/°).

저장소 안에서 이 주석만 반대로 말하고 있었다 — 같은 파일의 "호밍의 정의" 절,
`Tools/docking_field_kit/orin_homing_capture.py` 헤더, 메모리 `biguamr-steer-homing-architecture`
는 모두 "설계된 복귀 이동"이라고 적고 있다.

**③ RstStart 가 실제 관측된 조건은 통신 단절 후 복구**

`Log/homing_capture_220350.jsonl` t=17.925 의 `0x60FB.4=1` 은 **intercept 로 CAN2 를 끊어
Node Guarding 타임아웃을 유발한 뒤** 관측된 재호밍이다. 제어권 반환과는 다른 사건이다.

### 귀결

- 막으려던 현상 자체가 존재하지 않았을 가능성이 크다.
- 호스트 호출처 **0건**(`grep -rn "0xec" --include=*.py Tools/` → 무결과) — 한 번도 켜진 적 없다.
- 기능 존치/제거 결정은 `docs/adr/2026-07-28-0xec-rationale-void.md`.

### 함께 확인된 결함 (미수정)

`seer_is_homing_write()` 가 `data[4]`(값)를 보지 않아 **호밍 중단(`0x60FB.4 = 0`)까지 차단**한다.
같은 파일 설계 결정 (c)가 "중단은 `0x60FB.4 = 0` 으로 한다"고 선언한 바로 그 프레임이다.
차단이 켜진 상태에서 Seer 가 정지를 보내면 drop + 가짜 ack 되어 Seer 는 정지가 수리된 줄 알고 축은 계속 간다.

수정안: `if ((index == 0x60FBU) && (sub == 0x04U)) { return (f->data[4] != 0U); }`

## 2026-07-28 — 호밍 속도(`0x6099`) 상한 검증 추가

`0xea` 의 `wIndex` 16비트 생값이 검증 없이 `0x6099` 로 전달되던 것을 범위 검증으로 막았다.

- Handbook 문서 범위 `0~10000`(0.1 r/min) 대비 주입 최대 65535 = **6.5배 초과** 가능했다.
  - 1차 source: `References/Tongyi-Motor-Controller/manuals/IxLII-IxLs-IxH_Servo_Driver_Handbook_V7.0.txt:5915,:10249`
- 상수 `SEER_HOME_SPEED_MIN 100U` / `SEER_HOME_SPEED_MAX 3000U` 신설, 범위 밖은 **거부**(클램프 아님).
- 결정 근거·Rollback: `docs/adr/2026-07-28-homing-speed-clamp.md`
