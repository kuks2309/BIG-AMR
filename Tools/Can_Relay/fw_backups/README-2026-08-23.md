## 어떻게 (통상 경로와 다른 점)

1. `PandaDFU.recover()` 로 bootstub(14,176 B) DFU 프로그램 → reset. **보드가 DFU 로 재진입**해
   통상 경로(bootstub 재열거 후 `flash_panda.py`)가 막혔다.
2. 그래서 **앱도 DFU 로 직접 프로그램**: 16K 섹터 1·2·3(0x8004000/0x8008000/0x800C000) 소거 후
   signed blob 을 `APP_ADDRESS_FX`(0x8004000)에 기록 — USB flasher(`flash_static`)가 쓰는 것과
   동일 blob·동일 주소·동일 소거 범위라 등가다. reset 후 이번에는 앱으로 정상 부팅했다.
   (1회차 DFU 재진입의 원인은 미규명 — BOOT0 스트랩 의심이었으나 2회차 reset 은 정상 점프했으므로
   확정하지 않는다.)
   스크립트는 세션 스크래치패드 1회용(`flash_new_board.py`·`flash_app_via_dfu.py`), 라이브러리는
   `panda-firmware/python` 정본을 사용.

  서비스 정지 상태로 8 s 수신 → **16,883 프레임**(2,110 fps) bus1 수신, `can_rx_errs` 0 유지,
  bus_off·error_passive·TEC·REC 전부 0. CANopen 주소 `0x601~0x604`(드라이브 노드 1~4 SDO
  요청)·`0x581~0x584`(응답)·`0x701·0x702`(하트비트) 관측 = Seer↔4축 드라이브 통신 정상,
  신규 보드는 SILENT 청취. verified_facts 2026-07-27 §A-1 재현.
  검증 스크립트(1회용, 읽기전용): 세션 스크래치패드 `bus_health_check.py`.
- ⛔ **릴레이 engage(intercept) 실패 — 보드 하드웨어 핀맵 문제 (2026-08-23 15:44)**:
  서비스 유지·`~/engage true` 호출은 성공했으나, **bus2(모터측 STM32 CAN3)가 error-passive
  TEC=128 LEC=3(Ack)**, 드라이브 피드백 전무(rx=0, node1~4 상태 None). 즉 PC가 bus2로 송신해도
  ACK 하는 노드가 없다 = **모터가 판다 bus2 경로에 도달하지 않는다**(CAN3 트랜시버 부재).
  ⚠ **정정(2026-08-23)**: 최초엔 bus0 깨끗(TEC=0)을 「릴레이 작동·Seer 기만 성공」으로 적었으나,
  stock 펌웨어 `set_intercept_relay`는 **SBU 핀**을 구동하는데 R01 릴레이 K1 은 **PC10** 이라
  이 시험에서 **K1 은 애초에 작동하지 않았을 것**이다(하네스 자동감지 부재 시 무동작). 따라서
  bus0 깨끗 = STM32 CAN1(CN4)에 아무것도 없어 **유휴**였을 뿐이고, passthrough 가 유지돼
  **Seer 단독 주행이 계속됨 = 로봇에 영향 없음**. (그래서 Seer 경보도 없었을 것 — 사용자 확인 권장.)
  - passthrough(릴레이 OFF)는 정상(앞서 16,883프레임 수신) — 릴레이 OFF는 pin4↔pin23을
    **기계 접점으로** 직결(U9 미경유)하기 때문. 즉 **모터는 붙어 있고 intercept 경로만 실패**.
  - **원인 = 보드(CAN RELAY R01) 회로도의 STM32 CAN 주변장치 배정 오류** (회로도 `CAN RELAY R01.pdf`
    2026-07-27, STM32F413RGT 실측 확인). 넷 이름(보드 라벨)과 STM32 주변장치가 어긋남:
    | 보드 넷(커넥터) | MCU 핀 | STM32 주변장치 | 펌웨어 버스 |
    |---|---|---|---|
    | CAN0 = Seer (CN2) | PB12/PB13 | **CAN2** | bus1 |
    | CAN2 = 모터 (CN3) | PB5/PB6 | **CAN2** | bus1 |
    | CAN3 = 독립+5V (CN4) | PB8/PB9 | **CAN1** | bus0 |
    | (미사용) | PA8/PA15 | **CAN3** | bus2 |
    · 릴레이 K1(G6K-2P, Q31 구동)이 CAN0↔CAN2 를 120Ω 종단과 함께 스위칭. Seer(CN2)와 모터(CN3)가
      **둘 다 STM32 CAN2(bus1) 한 주변장치**에 물려 릴레이 핀쌍으로만 갈린다. STM32 CAN3(bus2)는 트랜시버 부재.
    · 펌웨어(black-panda, hw_type 0x03)는 **동시 MITM** 을 요구한다 —
      `safety_seer_gate.h`: Seer 응답 항상 bus0, 포워딩 bus0(Seer)↔bus2(모터). `cans[]={CAN1,CAN2,CAN3}`
      → bus0=CAN1·bus1=CAN2·bus2=CAN3. 즉 **Seer=CAN1(bus0)·모터=CAN3(bus2)** 두 개의 동시 활성 버스 필요.
    · 실측 일치: engage 시 **bus2(CAN3)=트랜시버 없음 → ACK 0**(TEC=128), passthrough 수신은 **bus1(CAN2)에만**
      (Seer·모터가 같은 CAN2 라 하나로 브리지). 참조 정상 보드는 bus0+bus2 동시(PINMAP.md:88).
  - **모터는 무지령·미도달이라 움직이지 않았고**, estop 정상, disengage 로 passthrough 복귀.
  - **결론**: R01 은 Seer·모터가 한 STM32 주변장치(CAN2)를 공유해 **동시 MITM 불가** → 이 펌웨어와 근본 비호환.
    단순 재배선·설정 변경으로 해결 안 됨. passthrough(fail-safe)만 동작 = Seer 단독 주행만 가능.
  - **수정(R02 필요)**: 트랜시버 U2(Seer/CN2)→STM32 CAN1 핀(PB8/9 또는 PA11/12), U3(모터/CN3)→STM32
    CAN3 핀(PA8/15 또는 PB3/4), U4(예비/CN4)→STM32 CAN2 로 TXD/RXD 재배선하고 릴레이를 CAN1↔CAN3
    커넥터 브리지로 정정 = 참조 보드 위상과 일치. **당장 PC 릴레이 필요 시 검증된 기존 판다
    `400025001751323139343439` 로 원복**(정상).
  - **R02 배선 확정 (2026-08-23, 예비 CAN=IMU 용도로 결정)** — STM32 3개 컨트롤러를 각 역할에 1개씩:
    | 역할 | 커넥터 | STM32 | 펌웨어 버스 | MCU 핀(AF) |
    |---|---|---|---|---|
    | Seer | CN2 | CAN1 | bus0 | PB8(RX)/PB9(TX) AF9 |
    | 모터 | CN3 | CAN3 | bus2 | PA8(RX)/PA15(TX) AF11 |
    | IMU | CN4(+5V) | CAN2 | bus1 | PB5(RX)/PB6(TX) AF9 |
    IMU 가 bus1 을 차지하므로 "CAN3 미사용" 대안 폐기 → **기존 3개 트랜시버를 STM32 서로 다른 CAN 으로
    재배치**(U2:Seer→CAN1·U3:모터→CAN3·U4:IMU→CAN2, TXD/RXD 신호선만 이설·**부품 추가 불요**·릴레이/
    커넥터/종단 그대로 재사용). bus0=Seer·bus2=모터
    유지라 **안전 게이트 무수정**(재검증은 보드 브링업 I/O 만). IMU: ① 250 kbps(bus1) 정합 ② 판다가
    전 버스 RX 를 USB 로 호스트 전달하므로 Jetson 이 bus1 IMU 판독 가능 ③ IMU 가 폴링/설정에 TX 필요
    시 SILENT/게이트에서 bus1 호스트 TX 허용 여부 확인. 다음: 커스텀 보드 프로파일(릴레이=PC10,
    trans en=PC13/PC1, 하네스 자동감지 생략, bus0/1/2=Seer/IMU/모터) 작성 — IMU 모델 확정 후 착수.
