# motion_sil_regression — 액션 거동을 SIL 로 자동 판정

액션 서버의 `execute()` 는 370~563줄짜리 단일 함수라 gtest 로 잡을 수 없다. 그렇다고 그
코드를 리팩터하는 것은 **실기로 검증된 제어 코드를 건드리는 위험**을 지는 일이다.
그래서 코드를 바꾸지 않고 **밖에서** 거동을 고정한다.

로봇을 움직이지 않으므로 공간·안전 제약이 없다.

## 사용

```bash
# 실기 스택과 섞이지 않도록 도메인을 분리한다
ROS_DOMAIN_ID=7 python3 Tools/motion_sil_regression/sil_regression.py --case all
ROS_DOMAIN_ID=7 python3 Tools/motion_sil_regression/sil_regression.py --case turn --keep
```

종료코드 `0`=전 항목 통과, `1`=판정 실패, `2`=환경 문제.
`ROS_DOMAIN_ID` 가 0 이거나 미설정이면 **실행을 거부한다**(실기와 섞이면 로봇이 움직인다).

## 케이스

| 케이스 | 판정 |
| --- | --- |
| `turn` | 20° · R=1.0 · `status 0` · \|각오차\| ≤ 0.5°(실기 승인 규격과 같은 값) |
| `turn_reverse` | 같은 항목 |
| `yaw_control` | 헤딩 유지 후진 0.5 m · `status 0` · 거리 오차 ≤ 0.01 m · **가드 오탐 0** |
| `yaw_guard` | IMU 에만 잡음 3.0° 주입 → `status −7`(헤딩 발산) 발화 |

## ⚠ SIL 의 구조적 한계 — 알고 써야 한다

1. **플랜트는 IMU 와 맵 자세를 같은 지상진값에서 만든다** → 두 값의 괴리가 정확히 0 이다.
   `−7` 을 보려면 `imu_yaw_noise` 로 IMU 만 오염시켜야 한다. 그냥 돌리면 영원히 안 뜬다.
2. **`yaw_guard` 는 가드 임계를 0.5° 로 낮춘 뒤 판정한다.** 생산 기본값 5.0° 로는 발화하지
   않는다 — 백색 잡음 3.0° 1σ 가 5° 를 **10 cycle 연속** 넘길 확률이 사실상 0 이기 때문이다.
   여기서 보려는 것은 「임계가 적절한가」가 아니라 **판정·중단·코드 반환 경로가 살아 있는가**다.
   (그 `ros2 param set` 이 먹는 것 자체가 파라미터 콜백 화이트리스트의 회귀이기도 하다.)
3. **즉응 플랜트는 조향 지연이 없어 `gate_blocked` 가 생기지 않는다** → `status −8`(조향 미도달)은
   SIL 로 못 본다. 보려면 가드 임계 자체를 낮춰야 하며 그것은 회귀가 아니라 진단이다.
   `−8` 은 실기에서 확인했다.

## 무엇을 대신하지 못하는가

- **정확도 규격을 새로 정하는 근거가 아니다.** 플랜트는 실기가 아니며, 여기 수치(−0.263°)는
  실기값(−0.38~−0.44°)과 다르다. 이 도구는 **거동이 바뀌었는지**를 본다.
- `−8`, 조향축 비응답, IMU 저속 회전 특성은 실기·전용 도구 소관이다
  (`Tools/imu_rate_check/`, `debt-051`).
