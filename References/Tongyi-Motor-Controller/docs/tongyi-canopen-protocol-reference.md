## 2. COB-ID (프레임 종류)
| COB-ID | 종류 | 방향 | 비고 |
|---|---|---|---|
| 0x600+N | SDO_RX | Seer→모터 | 요청(쓰기/읽기) |
| 0x580+N | SDO_TX | 모터→Seer | 응답 |
| 0x700+N (RTR) | Node Guarding 요청 | Seer→모터 | DLC0, 20Hz(50ms) |
| 0x700+N (data) | Guarding 응답 | 모터→Seer | 1byte 상태(bit7 토글) |
| 0x000/0x080/PDO/EMCY | — | — | **미관측(미사용)** |

## 3. SDO 명령·응답 사전 (expedited only, ≤4byte) ✓
프레임: `[cmd][idx_lo][idx_hi][sub][d0][d1][d2][d3]`

**요청(0x600+N):**
| cmd | 의미 |
|---|---|
| 0x23/0x2B/0x2F | 쓰기 4/2/1 byte (expedited download) |
| 0x40 | 읽기 요청 (upload) |

**응답(0x580+N):**
| cmd | 의미 |
|---|---|
| 0x60 | 쓰기 성공 |
| 0x43/0x4B/0x4F | 읽기응답 4/2/1 byte |
| 0x80 | Abort(에러) |

예: `0x601  23 FF 60 00 8D 09 00 00` = node1 에 0x60FF(Target velocity)=0x098D(2445=244.5rpm) 쓰기 → 응답 `0x581 60 FF 60 00 ...`

> 같은 문서 `:140` 은 `0x60FB.04=1` 을 미확정 항목으로 별도 등재한다(「의미 미상(절대 엔코더 관련 추정)」).

> 「`OBJ_VENDOR_60FB = 0x60FB  # 기동 시 sub 0x04=1 기록 관측`」, `backend.py:267,270`.
>
> #### ⚠ 정정 (2026-07-27) — 위 「`0x60FB.04` = 벤더 오브젝트, 의미 ⚠ 미상(절대 엔코더 관련 추정)」은 오류다
> (원 문장은 이력 보존을 위해 위에 그대로 남긴다. 인용된 design-inputs.md 원문도 변경하지 않았다.)
> - **`0x60FB.04 = RstStart`** (UINT8, RW, PDO 매핑 가능) — **호밍 개시 트리거**. `0 = Reset off / 1 = Reset on`.
>   벤더 미상 오브젝트가 아니라 핸드북 정식 등재 항목이다.
>   근거: [Handbook V7.0 §6.9 Home, printed page 171](../manuals/IxLII-IxLs-IxH_Servo_Driver_Handbook_V7.0.txt#L8593-L8596)
>   「`60FB 4 RECORD RstStart UINT8 RW YES`」, 재등재 [Appendix I(Object Dictionary), printed page 196]
>   (같은 .txt:9659). 드라이브 내부 파라미터명은 `0x448F SelfSofRst.uwRstStart`(같은 .txt:5905, 5967
>   「Start homing: Write SelfSofRst.uwRstStart = 1」).
> - 「절대 엔코더 관련」추정이 빗나간 이유: **절대위치 계열은 같은 인덱스의 sub 2·sub 3**
>   (`Position_actual_Turn_value` / `slAbsAngle`)이고 **sub 4 는 별개**다(같은 .txt:9644-9660).
> - **실기 확인**: `Log/homing_capture_220350.jsonl` — `t=17.9252/17.9257` node3/4 `0x60FB.4=1` write
>   → **31 ms 뒤** `0x6041` 이 sw=0x1050(bit15=0, 호밍 진행 중)으로 **최초 관측**(`t=17.9562/17.9567`)
>     ⚠ 전이 시각이 아니다 — 직전 폴이 t=5.138 이라 1→0 은 구간 (5.138, 17.956] 에서만 확정
>   → `0x6064` 가 5 ms 내 정확히 0 으로(`t=17.9302/17.9308`). 즉 **이 쓰기가 모터를 물리적으로 움직인다.**
> - ⇒ Seer 의 `0x6099`(호밍 속도) → `0x60FB.4=1`(개시) 순서는 **문서화된 정규 호밍 시퀀스**이며,
>   「의미 미상 벤더 오브젝트」로 취급해 안전 함의를 과소평가하지 말 것.
> - **`0x6098`(Homing method)은 캡처 전 구간 미기록** — 253,510 프레임 전수 스캔에서 write·read **모두 0회**
>   (0x6000.1 / 0x603F / 0x6040 / 0x6041 / 0x6060 / 0x6064 / 0x607A / 0x6078 / 0x6081 / 0x6083 / 0x6084 /
>   0x6099 / 0x60FB.4 / 0x60FF / 0x100C / 0x100D 만 관측). ⇒ **드라이브 저장값을 그대로 사용**한다.
>   그 저장값은 2026-07-27 실기 판독으로 **전 노드 `0x6098 = 1`** = **Home 1(음의 리밋 트리거)** 로 확정됐다
>   (Handbook 기본 `0x448E SelfSofRst.uwRstMode = 1` 과 일치 — 같은 .txt:5901, [§4.6 Homing Operation, page 116]).
>   ⚠ **Home 35 를 쓰면 RstMode 가 0(호밍 꺼짐)으로 리셋**되므로(§4.6, 같은 .txt:6147-6148, printed page 122)
>   TR_Nav 류의 `0x6098` 기록 방식을 그대로 베끼면 **Seer 호밍이 죽는다.**

## 8. 폴트/E-stop/dropout 거동 ~~✓~~ ⚠ (관측 구간 한정 — 폴트 국면 미관측)

> **⚠ 2026-07-27 감사 — 조건 명시(기존 서술은 지우지 않고 적용 범위를 아래로 한정한다).**
> 아래 「EMCY 0건, Error_code 전구간 0」은 **2026-07-07~08 정상 운전 캡처 구간에 한해** 성립한다(본 문서 `:3`).
> **드라이버 폴트가 발생한 캡처는 없다** — 같은 문서 `## 9`「Fault 비트는 폴트 미발생으로 미관측」.
> 폴트 미발생 구간의 관측에서 「폴트 시에도 드라이버 CAN 폴트가 아니다」라는 일반 결론은 도출되지 않는다.
> ⇒ **폴트 발생 시 CAN 거동은 미관측·미확정.** 실제로 이후의 범위이탈 물리 갇힘 사건
> (`docs/claude-mistake/2026-07-27-002_node4-unverified-command-damage.md`)의 드라이버 CAN 거동은 이 절로 예측되지 않는다.

- **EMCY 0건, Error_code 전구간 0** — blocked·E-stop 모두 드라이버 CAN 폴트 아님(마스터 레벨 처리).
- E-stop: 속도지령 한 스텝에 0(step-cut). 정지 유지상태는 정상정지와 CAN 상 구별 불가, 전이순간은 dV/dt 로 구별.
- 링크 dropout: 마스터 무한 재시도(폴링 330fps로 감속)+guarding 유지. 재연결 시 **즉시 재개+무재초기화**(CAN링크 한정; 전원까지 끊으면 재부팅→init 필요).
